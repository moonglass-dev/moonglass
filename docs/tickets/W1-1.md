# Add the container-spec sanitizer and the `agent.toml` schema

## Outcome

`internal/policy` can load `/etc/moonglass/agent.toml`, check any container spec or resolved Compose project against ADR-0004's deny list and scoped allow blocks, and reject with an error that names the field and shows the `agent.toml` lines that would allow it. The escape suite in `testdata/escape/` and the tests below prove it, before any `Deploy` exists. The full behaviour is `docs/specs/container-policy.md`, which this ticket implements and may edit. It already exists and is faithful to ADR-0004 and threat-model §6; edit it only where the code shows it to be wrong, and never in a way that contradicts the ADR.

Concretely:

- `Parse` and `LoadFile` read the schema (`[update]`, `[commands] forbid`, `[sources]`, `[[containers.allow]]`) strictly. An unknown key or invalid block is an error. The file is read once; there is no reload.
- `Policy.Check` denies every field in ADR-0004 decision 1, both BuildKit entitlements, and any sysctl outside the allow-list, unless a matching block allows it. It rejects, never strips, and returns a `Checked` spec the executor must use.
- `Policy.CheckCompose` runs `compose-go`, enables every profile, takes interpolation variables only from the supplied map, and checks every resolved service.
- Mount checks resolve paths first: `..`, symlinks, aliases of `docker.sock` and `containerd.sock`, the Docker data root, and the agent-managed data directory `mounts/<project>/<name>`.

## Dependencies and ADR-0009

Two modules are authorised by this ticket's `dependencies` and by `allow` (`go.mod`, `go.sum`, `.golangci.yml`):

- `github.com/compose-spec/compose-go/v2`: the Compose parser named by ADR-0004 decision 7 and stack §2. The repository has not yet imported it, so this is its import path.
- `github.com/pelletier/go-toml/v2`: TOML parsing with strict unknown-key errors (`Decoder.DisallowUnknownFields`) and line and column in errors. Chosen over `BurntSushi/toml` because strictness is a decoder setting, not a second pass over metadata.

Pin the latest stable release of each when implementing, in `go.mod`, in ADR-0009 and in nothing else. Add both module paths to the depguard `allow` list in `.golangci.yml`. Only `internal/policy` may import them.

This ticket **also writes `docs/adr/0009-policy-dependencies.md`** and adds its row to `docs/adr/README.md`. ADR-0009 records: the two modules and pinned versions; why `compose-go` (official parser, resolves interpolation, `extends`, `include` and profiles, so an escape cannot hide in a variable) and why this TOML library; the binary-size effect measured from `make build-all` before and after, and the agent's idle memory with the policy loaded, against the combined 100 MB budget (G1, `docs/plan/build-plan.md`); and the alternatives rejected (a hand-rolled Compose parser, `BurntSushi/toml`, `yaml` plus custom resolution). Follow the format of ADR-0008. That ADR is expected for this ticket; it is **not** an unplanned contract change, and the plan stage must **not** set `contract_change_required` for it or for the new dependencies. The ADR text and the ticket's `dependencies` list are what authorise the modules; no other module is added. If `compose-go` pulls a transitive dependency that blocks a static `CGO_ENABLED=0` build, stop and report it rather than choosing a different library.

ADR-0004 and the `agent.toml` schema are not changed by this ticket. If implementation shows ADR-0004 to be wrong or incomplete, record it under "Open questions" in the spec and stop; do not amend the ADR.

## Out of scope

- The Deploy executor and anything that calls the Docker Engine (W2-3). No Docker client import in this ticket, and no real Docker in these tests: the code is pure checks over a `Spec` and the host filesystem paths named in `Paths`.
- Wiring into `moonglass agent`, reading `/etc/moonglass/agent.toml` at agent start-up, and mapping a `Rejection` to a protocol error code. No `.proto` change.
- Enforcing `[commands] forbid` and `[sources]` end to end (W5-3). This ticket only parses and validates them.
- Creating, owning or cleaning up the agent-managed data directories. Only mounts of them are checked.
- Compose reconcile and import (W6-4), previews, backups, one-click databases and pre-deploy steps as callers. They will build a `Spec` and call `Check`.
- Open questions listed in the spec. In particular, builds cannot be matched by an allow block, and `bind_mounts` is not blocked from agent state. Build the narrower behaviour written in the spec and do not widen it.
- Any reload, watcher or signal handling for `agent.toml`.

## Acceptance tests

Tests are table-driven, with failure messages that show the expected and actual values. Fixtures live in `testdata/escape/`. Tests that need paths use `t.TempDir()` and set `Paths` to them; none touches `/var`, `/run` or `/etc`.

Config:

- `TestParseFullExample`: the ADR-0004 example, with a digest, parses to the expected `Config` and allow block.
- `TestParseRejectsUnknownKeys`: an unknown key at the top level, in a table, and in an allow block is an error naming the key and its line.
- `TestParseRejectsInvalidUpdateCommandsSources`: a bad `channel`, an unknown or duplicate `forbid` class, a bad glob, an empty list and a duplicate entry each fail.
- `TestParseRejectsInvalidAllowBlocks`: missing or empty `project` or `image`; empty `environment` or `service`; a block with no allow key; a boolean key set to `false`; an empty or duplicate list entry; a malformed `bind_mounts`, `devices`, `cap_add` or entitlement entry; a project or `data_dirs` name that is not a path element. Each error names the block (`containers.allow[N]`) and key.
- `TestParseRejectsTagImage`: `name:tag`, `name:tag@sha256:…`, a short digest and a non-`sha256` digest all stop the agent, and the error shows `name@sha256:<digest>`.
- `TestParseRejectsHostSysctlBlock`: a block listing a sysctl that is not namespaced is invalid.
- `TestParseRejectsBlockOverProtectedOrMountsPath`: a `bind_mounts` source that is a socket, the Docker data root, inside or an ancestor of either, or inside or an ancestor of `MountsRoot`, is invalid.
- `TestLoadFileAbsentIsEmptyConfig`: no file means no exceptions, nothing forbidden, channel `stable`.
- `TestLoadFileRejectsUnsafeFile`: a symlink, a group- or world-writable file, a file with the wrong owner, and an unreadable file are errors that say how to fix them.
- `FuzzParse`: arbitrary bytes never panic; success implies a policy with no invalid block.

Deny rules:

- `TestCheckAllowsBenignSpec`: a named volume, a tmpfs, `no-new-privileges`, both allow-listed sysctls, a same-project network mode and the default runtime pass untouched.
- `TestCheckDeniesEveryField`: one row per row of `DeniedFields`; each is rejected with its `Field` and `Key`, and the spec is unchanged.
- `TestCheckSysctlAllowList`: `net.core.somaxconn` and `net.ipv4.ip_local_port_range` pass; a namespaced sysctl not on the list is rejected, and allowed by a block that lists it.
- `TestCheckHostSysctlNeverAllowed`: `kernel.core_pattern`, `vm.max_map_count` and `fs.suid_dumpable` are rejected with a message saying no block can allow them; a `net.*` sysctl under `network_mode: host` and an IPC sysctl under `ipc: host` are likewise never allowed.
- `TestCheckNetworkModeContainerSameProject`: `container:<id>` is allowed for the same project, rejected for another project and for an unknown container, and `host` is matched case-insensitively.
- `TestCheckSecurityOptDisablesConfinement`: `seccomp=unconfined`, `seccomp:unconfined`, `apparmor=unconfined`, `label=disable` and `label:disable` are rejected; `no-new-privileges` passes.
- `TestCheckBuildEntitlements`: `security.insecure` and `network.host` are rejected, and a build can never be matched by a block.
- `TestCheckMalformedSpec`: an empty project, a relative bind source and an unknown mount type are rejected, not defaulted.

Allow blocks:

- `TestAllowEveryKeyAllowsItsField`: for every allow key, a spec with only that denied field passes with a matching block.
- `TestAllowBlockMatchesEveryNamedKey`: a block applies only when every key it names matches. Wrong project, wrong digest, wrong environment and wrong service each reject; narrowing keys never widen.
- `TestAllowOnlyListedFields`: `pid_host = true` does not allow `ipc: host`; `cap_add = ["NET_ADMIN"]` does not allow `SYS_ADMIN`; a listed bind mount does not allow another host path, and a read-only entry does not allow a read-write mount.
- `TestAllowNeverMatchesTagOrMissingDigest`: a spec whose image is a tag, or has no image, matches no block. A tag plus digest matches on name and digest. `docker.io/library/x` and `x` are the same repository.
- `TestAllowUnitesMatchingBlocks`: two matching blocks allow the union of their listed fields.

Data directories and aliases:

- `TestDataDirAllowedForNamedImageAndProject`: `mounts/<project>/<name>` and a path inside it are allowed for the block's image and project.
- `TestDataDirRejectsEscapes`: without a block, for another image, for another project's subtree, for the project directory and `MountsRoot` themselves, for the agent's own state, through a symlink inside `mounts/`, through a symlinked `mounts/` and with `..`, each is rejected, and the message says why.
- `TestSocketAndDataRootAliasesRejected`: `docker.sock` and `containerd.sock` by their paths, `/run` and `/var/run` aliases, a symlink, a `..` path, a hard link or bind alias, and a parent directory (`/`, `/var`, `/run`); and the Docker data root and a path inside it. Only the exact socket, or the data root, can be allowed by its own key, and never an ancestor.

Errors:

- `TestRejectionNamesFieldAndAllowLines`: a golden test for the rendered error: it names the field, shows the `[[containers.allow]]` lines with `project`, `image` and the key, says to restart the agent, and merges several violations into one snippet; a host sysctl has no snippet; a tag shows the digest form.
- `TestRejectNeverStrips`: after a rejected `Check`, the input spec equals its copy before the call, and no `Checked` is returned.
- `TestRejectionHasNoEnvironmentValues`: an error for a spec built from `Env` values with a distinctive secret contains the rejected field and path, and no other variable's value.

Compose and escape fixtures:

- `TestComposeEscapes`: runs every directory in `testdata/escape/compose/`. Each `expect` file lists the violation keys exactly, or `ok`. It must include at least: the socket by short syntax, long syntax, `/run` alias, `..`, an interpolated source, a parent directory and a named volume bound with `driver_opts`; `privileged` behind `${VAR:-true}`, `extends` (one level and chained), `include`, a YAML anchor and merge key and a `profiles:` service; every other denied field; a tag in place of a digest in a block; a symlink out of `mounts/`; another project's subtree; and the agent's own state.
- `TestComposeBenignProjectPasses`: a benign project returns one `Checked` per service, equal to the resolved services.
- `TestComposeChecksEveryProfile`: a denied field in a service behind an inactive profile is rejected.
- `TestComposeUsesSuppliedEnvOnly`: a variable set in the process environment but not in `ComposeInput.Env` is not substituted.
- `TestComposeReturnsEveryViolation`: two failing services produce one `*Rejection` that lists both.
- `TestComposeLoaderErrorChecksNothing`: invalid YAML or an unset required variable returns an error and no `Checked`.
- `TestEscapeSuiteCoversEveryDeniedField`: fails when a row of `DeniedFields` has neither a row in `TestCheckDeniesEveryField` nor a fixture naming its key.

## Security notes

Threat model §6 in full, §7 (`internal/policy` is trusted core, one such ticket in review at a time), and §9 checklist item 2:

- **No bypass path.** `Check` is the only way to get a `Checked`. Nothing outside `internal/policy` can build one, and `Checked.Spec()` returns a copy, so the spec sent is the spec checked.
- **Reject, never strip or default.** No code path changes a spec to make it pass.
- **Compose after resolution.** Every profile is enabled, interpolation uses only the supplied map, and the agent's own environment is never read.
- **Paths are resolved before they are compared.** `..` and symlinks are rejected, not cleaned. A socket is recognised by identity as well as by name.
- **Scope never widens.** A block matches only when every key it names matches. It allows only the fields it lists. It matches a digest, never a tag. It reaches only its own `mounts/<project>/` subtree.
- **Nothing but a human editing the file changes policy.** No exported constructor takes anything but file bytes or a path. There is no reload and no mutation after construction. An unknown key or an invalid block stops the agent.
- **No secrets in errors.** Errors carry field names, paths, image references and sysctl names only.
- The parser takes untrusted-shaped input only from a root-owned file, but it has a fuzz target anyway (checklist item 1 spirit).

The reviewer must read every line of the diff. The code must be short enough to audit in one sitting.
