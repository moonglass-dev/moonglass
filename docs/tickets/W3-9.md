# Build host prerequisites

The agent unit's memory cap rises from `MemoryMax=48M` to `MemoryMax=512M`, because the host's `git` and `docker buildx` run as the agent's children inside that cap (owner decision D19, `docs/specs/build.md`, `docs/specs/install.md` "Units"). `scripts/install` also checks for `git` 2.30 or later and the Docker CLI's buildx plugin; each one that is missing prints one line to stderr naming it and saying that git builds need it, and the install continues and exits 0, because image deploys work without them (`docs/specs/build.md` "Host requirements"). The idle budget of W1-7 is unchanged.

## Scope

- `deploy/systemd/moonglass-agent.service`: `MemoryMax=48M` becomes `MemoryMax=512M`. Nothing else in the unit changes. The proxy unit is untouched (`MemoryMax=64M`).
- `scripts/install`: a prerequisite check, run in every layout (system and custom `--prefix`/`--unit-dir`), after all artifacts are verified and installed and before the final `installed` line:
  - git: runs `git --version` as a plain command. Missing (`command -v git` fails), a non-zero exit, or output with no parsable `major.minor` version counts as not present. A version below 2.30 (compared numerically on major, then minor) counts as not present. Version strings such as `git version 2.39.3 (Apple Git-146)` and `git version 2.30.0` parse.
  - buildx: runs `docker buildx version` as a plain command. Missing `docker`, or a non-zero exit, counts as not present.
  - For each one not present, exactly one line on stderr in the script's existing form `moonglass-install: …`. The git line contains `git 2.30` and `git builds`; the buildx line contains `buildx` and `git builds`. When both are present the check prints nothing.
  - The check never calls `die`, never changes the exit status, and never `eval`s or executes text from the commands' output.
- `docs/specs/install.md`: the agent unit bullet states `MemoryMax=512M` as the current value (drop the "48M, raised by W3-9" history) and the prerequisite paragraph states the check runs in every layout after the install and never fails it.
- `internal/installtest/`: the five tests below, using `PATH` shims in `installEnv.shimDir` for `git` and `docker` (the existing `runInstall` prepends `shimDir`). Shims are written per test into `t.TempDir()`; no real git, Docker or network is needed.

## Acceptance criteria

- `TestAgentUnitMemoryMaxFitsBuilds`: the agent unit has exactly one `Service.MemoryMax` with value `512M`, and the proxy unit's is still exactly `64M`.
- `TestInstallWarnsWhenGitMissing`: with a `git` shim that exits 127 and a working `docker buildx` shim, the install exits 0, the binary and both units are installed, and stderr has exactly one line containing both `git 2.30` and `git builds`, and no line containing `buildx`.
- `TestInstallWarnsWhenGitTooOld`: table-driven over `git --version` outputs. `git version 2.29.9`, `git version 1.9.5` and `git version garbage` each produce exactly one git line; `git version 2.30.0`, `git version 2.39.3 (Apple Git-146)` and `git version 3.0.1` produce none. Every case exits 0 with the files installed.
- `TestInstallWarnsWhenBuildxMissing`: table-driven: a `docker` shim whose `buildx version` exits 1, and a `docker` shim that exits 127 for everything, each with a git shim reporting 2.40.0. Each exits 0 with the files installed and stderr has exactly one line containing both `buildx` and `git builds`, and no line containing `git 2.30`.
- `TestInstallQuietWhenBuildPrereqsPresent`: with git 2.40.0 and a `docker buildx version` that exits 0, the install exits 0 and stderr has no line containing `git builds`; with both missing it has exactly two such lines, one per prerequisite.
- The existing tests in `internal/installtest` (`TestUnitsAreHardened`, `TestInstallCreatesProxyAdminGroup`, the signature tests and the rest) pass unchanged; none is edited to weaken it.
- A failed verification still exits non-zero with nothing installed, as before; the prerequisite check adds no root step and no new command run as root beyond `git --version` and `docker buildx version`.
- `grep -n 'MemoryMax=48M' deploy docs/specs` finds nothing.
- `make ci` is green.

## Out of scope

- The idle memory budget and its test: W1-7 (unchanged).
- Installing git, Docker or buildx; the deploy key: W3-7, W3-8, W3-10.
- The proxy admin socket group: W2-12 (done).

## Security notes

- `docs/threat-model.md` §9 item 6 (root steps in install scripts): the check adds no root-only step and runs in the custom layout without root. It runs only after every artifact's `.sig` and the SHA-256 have verified, so it cannot affect what is installed, and its output is only compared, never executed or evaluated. A missing prerequisite never makes the script skip or relax verification.
- `docs/threat-model.md` §9 item 7 (systemd unit privileges): the only unit change is the agent's `MemoryMax`, which remains set; no capability, group, writable path or hardening directive changes. The reason for the larger cap is the build children (D19); the proxy keeps its own 64M cap.
- §8: no host shell from the control plane is involved; the script runs on the operator's host by the operator.
