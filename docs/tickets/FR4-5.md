# Correct connection.md route registration

The "Route registration" section of `docs/specs/connection.md` still says that the operation registry does not exist and that `/v1/agent` joins the fixed route list when W2-1 lands. W2-1 has merged. `GET /v1/agent` is on `registry.NonOperationRoutes` (`internal/registry/routes.go`), and `docs/specs/registry.md` ("Routes and commands that are not operations") lists it there. After this ticket the section describes the code as it is. The route is on `registry.NonOperationRoutes`, it is mounted only on the agent listener, and its authorisation is mutual TLS with an enrolled agent key, as "Transport" describes (R-4 finding 5).

## Scope

- `docs/specs/connection.md`, the "Route registration" section only. Replace its paragraph with text that says:
  - `GET /v1/agent` is not a registry operation. It is on `registry.NonOperationRoutes`, the fixed list of routes outside the registry (`docs/specs/registry.md`).
  - The route is mounted only on the agent listener (`--agent-listen`), not on the `--listen` API listener.
  - Its authorisation is the mutual TLS 1.3 handshake in "Transport": the server accepts only a client leaf key that is an enrolled server's public key in the store, and proof of possession is TLS 1.3 CertificateVerify. No other authorisation runs on the route.
  - A test fails when the agent listener mounts a route that is not on `registry.NonOperationRoutes` (`TestAgentRoutesMatchTheDeclaredList` in `internal/server`).
- No other line of the spec changes. No code or test changes.

## Acceptance criteria

- The "Route registration" section of `docs/specs/connection.md` names `registry.NonOperationRoutes`, the agent listener and mutual TLS with an enrolled agent key.
- The phrases "does not exist yet" and "when W2-1 lands" no longer appear in `docs/specs/connection.md`.
- The new text agrees with `internal/registry/routes.go` (the `GET /v1/agent` entry), `internal/server/agent.go` (`AgentTLSConfig`, `authorizeAgent`, `AgentRoutes`), `internal/server/agent_routes_test.go` and the "Transport" section of the same spec. It claims no authorisation beyond what "Transport" and `docs/threat-model.md` §3 B3 state. In particular it adds no revocation, which "Out of scope" leaves for later.
- Every other section of `docs/specs/connection.md` is unchanged.
- `git diff --stat main` touches only `docs/specs/connection.md` and this ticket's own docs.
- `make ci` is green.

## Security notes

`docs/threat-model.md` §3 B3 (control plane ↔ agent). This ticket changes docs only. The spec must not claim more than B3 and the "Transport" section support. Authorisation is presence of the client key in the store, checked during the TLS 1.3 handshake on the agent listener. Revocation is not yet built and must not be implied.
