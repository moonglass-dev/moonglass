# depguard boundaries for ADR-0009 and ADR-0010

Rewrite `policy-deps` as `$all`-with-exclusion rules so compose-go and go-toml are denied outside internal/policy, pgx outside internal/store/pg and modernc outside internal/store/sqlite and internal/agent/state (R-1 finding 10).

ADR-0009 says compose-go and go-toml are imported only from `internal/policy`. ADR-0010 says only `internal/store/pg` imports pgx, and only `internal/store/sqlite` and `internal/agent/state` import modernc sqlite. Today `policy-deps` denies these modules only in `cmd/` and `internal/protocol`, and `sqlite-deps` lists packages by hand, so a new package (or `internal/server`, `internal/api`, `internal/registry` for pgx) can cross the boundary with lint still green. After this ticket every Go file in the module, current and future, is covered, using the `$all` plus `!` exclusion form that `huma-deps` already uses and that works.

## Scope

- `.golangci.yml`, `linters.settings.depguard.rules`:
  - `policy-deps`: `list-mode: lax`, `files: ["$all", "!**/internal/policy/**"]`, deny `github.com/compose-spec/compose-go/v2` (desc `only internal/policy may import compose-go (ADR-0009)`) and `github.com/pelletier/go-toml/v2` (desc `only internal/policy may import go-toml (ADR-0009)`). The pgx entry moves out of this rule.
  - New `pgx-deps`: `list-mode: lax`, `files: ["$all", "!**/internal/store/pg/**"]`, deny `github.com/jackc/pgx/v5` (desc `only internal/store/pg may import pgx (ADR-0010)`).
  - `sqlite-deps`: replace the hand-written package list with `files: ["$all", "!**/internal/store/sqlite/**", "!**/internal/agent/state/**"]`, deny `modernc.org/sqlite` (desc unchanged: `only internal/store/sqlite and internal/agent/state may import modernc sqlite (ADR-0010)`).
  - Each rule's comment names its ADR and says every file outside the excluded paths is covered, so new packages are too, as the `huma-deps` comment does. The false claim that depguard file exclusions "were not applied" is removed from `policy-deps` and `sqlite-deps`.
- No other rule, linter or setting changes.

## Acceptance criteria

- `make lint` passes on the branch, and `make ci` is green.
- `policy-deps`, `pgx-deps` and `sqlite-deps` each use `files` starting with `"$all"` followed only by the `!` exclusions listed in Scope; none lists packages by hand.
- The deny lists are exactly: compose-go and go-toml in `policy-deps`; pgx in `pgx-deps`; modernc sqlite in `sqlite-deps`. No module is denied by two rules.
- The existing importers still lint clean: `internal/policy/compose.go`, `internal/policy/parse.go`, `internal/store/pg/pg.go`, `internal/store/sqlite/sqlite.go`, `internal/agent/state/state.go`.
- The rules bite, checked once by the worker and recorded in `docs/tickets/FR1-10/` (not committed as code): a temporary blank import of each denied module added to `internal/server` (pgx, modernc, compose-go, go-toml), to `internal/store` top level (pgx, modernc), and to `internal/store/sqlite` (pgx) makes `make lint` fail with the matching depguard description; the temporary imports are removed before commit.
- No change outside `.golangci.yml` apart from the ticket's own docs.

## Out of scope

- `age-deps`, `proxy-deps` and `websocket-deps` keep their hand-written file lists and comments; converting them is for a later drift-review fix ticket.
- `go.mod` tidiness and its CI gate: FR1-9.
- Any change to which packages may import these modules: that is an ADR-0009 or ADR-0010 amendment.

## Security notes

- `docs/threat-model.md` §3 B2 ("Only the storage package writes SQL"): after this ticket the lint enforces that no package outside `internal/store/pg`, `internal/store/sqlite` and `internal/agent/state` (ADR-0010 amendment) can import a SQL driver. The rules must not widen any boundary: the exclusions are exactly the ADR-named directories.
- ADR-0009: the agent.toml and Compose parsers stay confined to `internal/policy`, so policy parsing has one implementation (§6 deny list is checked in one place).
