# Container spec pass-through fields

ADR-0004 decisions 10 to 12 and `docs/specs/container-policy.md`, "Pass-through fields and agent labels (W2-9)". After this ticket `policy.Spec` carries `Cmd`, `Env`, `Labels`, `AgentLabels`, `Networks`, `RestartPolicy` and `LogConfig`, and `Check` copies them into `Checked` unchanged, so the Deploy executor (W2-3) can build its whole Engine request from a `Checked` and nothing else. A user label in the `dev.moonglass.` namespace is a violation that no block can allow, an `AgentLabels` key outside it makes the spec malformed, and no environment value ever appears in a rejection.

## Scope

- `internal/policy/types.go`: add the fields to `Spec` with the types in the spec's table (`Cmd []string`, `Env`, `Labels`, `AgentLabels map[string]string`, `Networks []string`, `RestartPolicy string`, `LogConfig` with `Driver string` and `Options map[string]string`). `Spec.clone` deep-copies every new slice and map, including `LogConfig.Options`. Add the row `{Key: "agent_labels"}` to `DeniedFields`, after the build-entitlement rows.
- `internal/policy/check.go`: the well-formedness rules (an `AgentLabels` key without the `dev.moonglass.` prefix; a `RestartPolicy` other than empty, `no`, `on-failure`, `unless-stopped`; a `LogConfig` with an empty `Driver` and non-empty `Options`) are malformed-spec violations with field `spec`. A `Labels` key starting with `dev.moonglass.` is a violation with key `agent_labels`, checked whatever blocks match. The other pass-through fields are not judged.
- `internal/policy/reject.go`: an `agent_labels` violation renders no `[[containers.allow]]` snippet, like a sysctl that is not namespaced. Nothing in `Rejection.Error()` or any `Violation` is derived from `Spec.Env` values.
- `internal/policy/parse.go`: an allow block naming `agent_labels` is invalid, with an error that names the block position and the key and says it can never be allowed.
- `internal/policy/compose.go`: `serviceToSpec` fills `Labels` from the service's `labels` and never fills `AgentLabels`.
- `testdata/escape/compose/user-agent-label/`: a Compose service with a `dev.moonglass.project` label; `expect` is `agent_labels`. Add it to `requiredFixtures`.
- `docs/specs/container-policy.md`: only if the implementation shows a wording gap; the behaviour is already specified.

## Acceptance criteria

- `TestCheckCopiesPassThroughFields`: a table with one row per pass-through field (`Cmd`, `Env`, `Labels`, `AgentLabels` with `dev.moonglass.` keys, `Networks`, each valid `RestartPolicy` including empty, `LogConfig` with and without options) shows `Check(s)` succeeds and `Checked.Spec()` is `reflect.DeepEqual` to `s`. Mutating the input's slices and maps after `Check`, or the result of one `Spec()` call, does not change a later `Spec()` call.
- `TestCheckRejectsUserLabelInAgentNamespace`: a spec whose `Labels` holds `dev.moonglass.project` (and one holding `dev.moonglass.managed`) is rejected with a violation of key `agent_labels`, also when a block matching its project and image exists; the error names the label key, says only the agent sets labels in the `dev.moonglass.` namespace, and contains no `[[containers.allow]]`. A label `moonglass.dev/x` or `app.tier` passes.
- `TestCheckRejectsAgentLabelOutsideNamespace`: an `AgentLabels` key without the `dev.moonglass.` prefix (for example `app.tier`, or `dev.moonglassx`) makes the spec malformed: a single violation with field `spec` and an empty key.
- `TestCheckRejectsMalformedRestartPolicyAndLogConfig`: table rows `RestartPolicy` `always`, `on-failure:3`, `No` and a `LogConfig` with empty `Driver` and non-empty `Options` are each malformed (field `spec`); `LogConfig` with a `Driver` and no options, and with both, passes.
- `TestParseRejectsAgentLabelsAllowKey`: `Parse` of an otherwise valid block with `agent_labels = true` (and with a list value) returns an error that contains `containers.allow[0]` and `agent_labels`, and says it can never be allowed.
- `TestRejectionOmitsEnvironmentValues`: a spec with `Labels{"app.tier": "web", "dev.moonglass.project": "x"}` and `Env{"TIER_KEY": "app.tier", "DB_PASSWORD": "s3cr3t-pw-9"}` is rejected; neither `app.tier` nor `s3cr3t-pw-9` appears in `Error()` or in any `Violation`'s `Field`, `Key` or `Value`. The same holds for a spec made malformed by `RestartPolicy` `always` with the same `Env`.
- `TestCheckComposeFillsLabelsOnly`: a Compose service with `labels` (map and list form) yields a `Checked` whose `Labels` equals them and whose `AgentLabels` is empty.
- `TestComposeEscapes` runs the new `user-agent-label` fixture and it is rejected with exactly `agent_labels`; `TestEscapeSuiteCoversEveryDeniedField` passes with the new `DeniedFields` row.
- Every existing test in `internal/policy` passes unchanged; `make ci` is green.

## Out of scope

- Building the Engine request from `Checked`, the project network, default restart and log settings, and the agent's own labels: W2-3.
- The pre-deploy spec (`Cmd`, `dev.moonglass.role=pre_deploy`): W2-6.
- Filling `Cmd`, `Env`, `Networks`, `RestartPolicy` and `LogConfig` from Compose, and checking cross-project `Networks` (spec "Open questions" 8): W6-4.
- Secret delivery into `Env`: W4-8.

## Security notes

- `docs/threat-model.md` §6 (labels in `dev.moonglass.` set only by the agent and never allowable; environment values never in an error) and §9 checklist item 2 (the checked spec is the exact spec sent, including command, environment, labels and networks) and item 3 (no secret plaintext in an error string).
- `Check` still rejects, never strips: a reserved label is never dropped or renamed, and no field is defaulted (empty `RestartPolicy` stays empty in `Checked`).
- No new allow key: `agent_labels` is a deny-list key that a block can never name. `agent.toml` gains nothing the control plane can widen.
- `Cmd` is an argv list only; nothing in this package joins it or treats it as a shell string (AGENTS.md security rules).
- `internal/policy` is trusted core: tests are locked before code and the owner reads every line.
