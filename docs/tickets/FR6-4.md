# depguard boundaries for ADR-0011 and ADR-0012

ADR-0011 lets only `internal/proxy` import Caddy, and ADR-0012 lets only `internal/agent` and `internal/server` import `coder/websocket`. Today `proxy-deps` and `websocket-deps` in `.golangci.yml` deny those modules from a hand-written list of directories, so any new package (for example `internal/deploy`, `internal/api`, `internal/cli`) could import them unnoticed (R-6 finding 4). After this ticket both rules cover every Go file in the module except the directories the ADRs allow, the same `$all`-with-exclusion shape that `huma-deps`, `age-deps`, `policy-deps`, `sqlite-deps`, `pgx-deps` and `docker-deps` already use.

## Scope

- `.golangci.yml`, `linters.settings.depguard.rules.proxy-deps`: `files` becomes `"$all"` and `"!**/internal/proxy/**"`; the deny entry for `github.com/caddyserver/caddy/v2` stays, with `desc: only internal/proxy may import Caddy (ADR-0011)`. The comment says Caddy is imported only by `internal/proxy` (ADR-0011), `cmd/` calls `proxy.Run`, and every file outside `internal/proxy` is covered, so new packages are too.
- `.golangci.yml`, `websocket-deps`: `files` becomes `"$all"`, `"!**/internal/agent/**"` and `"!**/internal/server/**"`; the deny entry for `github.com/coder/websocket` stays, with `desc: only internal/agent and internal/server may import coder/websocket (ADR-0012)`. The comment follows the same pattern.
- `.golangci.yml`, `deploy-deps`: delete its `github.com/caddyserver/caddy/v2` deny entry, which `proxy-deps` now covers (one rule per boundary); its `moonglass.dev/moonglass/internal/proxy` deny entry and its comment about not importing internal/proxy stay, with the comment no longer claiming this rule denies Caddy itself.
- No Go code changes. Current importers (`internal/proxy/proxy.go`, `internal/proxy/counter.go`, `internal/agent/connect.go`, `internal/agent/connect_test.go`, `internal/server/agent.go`, `internal/server/agent_test.go`) are all inside the excluded directories.

## Acceptance criteria

- `proxy-deps.files` is exactly `["$all", "!**/internal/proxy/**"]` and denies `github.com/caddyserver/caddy/v2`.
- `websocket-deps.files` is exactly `["$all", "!**/internal/agent/**", "!**/internal/server/**"]` and denies `github.com/coder/websocket`.
- No other depguard rule denies `github.com/caddyserver/caddy/v2` or `github.com/coder/websocket`; `deploy-deps` still denies `moonglass.dev/moonglass/internal/proxy`.
- `make lint` and `make ci` are green on the branch.
- A reviewer check, not committed: adding `import _ "github.com/coder/websocket"` to a file in `internal/deploy` or `internal/cli`, or `import _ "github.com/caddyserver/caddy/v2"` to a file in `internal/server` or `internal/api`, makes `make lint` fail with the rule's desc. Before this ticket those imports pass lint.
- No change outside `.golangci.yml` and the ticket's own docs.

## Out of scope

- FR6-1, FR6-2, FR6-3, FR6-5, FR6-6, FR6-7, FR6-8: the other R-6 findings.
- Rewording the enumerated directory lists in ADR-0011, ADR-0012 and `docs/specs/proxy.md`: those statements stay true (the new rules deny from every listed directory and more); a change to an ADR needs the owner.
- Any change to the `main` allow list or to `go.mod`.

## Security notes

`docs/threat-model.md` §3: B3 (control plane ↔ agent, the only WebSocket connection) and B4/B8 (Caddy runs only in the proxy process, ADR-0001 and ADR-0011): no other role links Caddy, and only the two ends of B3 link the WebSocket module. The rewritten rules widen enforcement to every file, tests included, and must not exclude any directory beyond those ADR-0011 and ADR-0012 name.
