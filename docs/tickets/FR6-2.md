# Image-in-use by error type only

`removeImage` in internal/deploy recognises an image in use by the client's typed conflict error through `errdefs.IsConflict(err)` from `github.com/containerd/errdefs` (ADR-0017), which becomes a direct module in go.mod, and `isConflict`'s text match is deleted (R-6 finding 2). After this ticket, retention leaves an image the Engine still uses for the disk guard only when the Docker client returned its typed HTTP 409 conflict. Every other `ImageRemove` failure goes back to `Run`'s `onError`, even when its text contains "conflict", as docs/specs/release.md "Keep five" and ADR-0017 decision 4 require.

## Scope

- `internal/deploy/stop.go`: `isConflict(err)` returns `errdefs.IsConflict(err)` and nothing else. The `strings.Contains(err.Error(), "conflict")` match is deleted, and so is the `strings` import if nothing else in the file uses it. `removeImage` keeps its current shape: not found or conflict is nil, and anything else is `remove image <id>: %w`.
- `go.mod`: `github.com/containerd/errdefs v1.0.0` moves from the indirect block to the direct `require` block at the same version (ADR-0017 decision 1). `github.com/containerd/errdefs/pkg` stays indirect. `go.sum` changes only if `go mod tidy` asks for it.
- New tests in `internal/deploy` (a new `conflict_test.go` or `stop_test.go`), and `testdata/tests.txt` rewritten with `make test-list`.

`.golangci.yml` already allows the module and has the `errdefs-deps` rule (ADR-0017 decisions 2 and 3). This ticket does not change it.

## Acceptance criteria

- `TestIsConflictMatchesTypedErrorOnly`: a table-driven unit test of `isConflict`. It is true for `errdefs.ErrConflict` and for it wrapped with `fmt.Errorf("…: %w", …)`. It is false for `errors.New` text that contains "conflict" (for example `"image conflict: unable to delete"`), for `errdefs.ErrNotFound`, and for `errdefs.ErrUnavailable` wrapped in a message that contains "conflict". Each failure message shows the input error, the expected value and the actual value.
- `TestRemoveImageInUseIsNotAnError`: against a real Docker Engine, an imported image used by a created container (made through `createFixture`, labelled and cleaned up per run). `e.cli.ImageRemove` by ID without force returns an error for which `errdefs.IsConflict` is true, so the test proves the client's typed error is what the code matches. `Engine.removeImage` on the same ID then returns nil, and the image is still present afterwards.
- `TestRemoveImageReportsOtherFailures`: against a real Docker Engine, `Engine.removeImage` with an already-cancelled context on an imported image's ID returns a non-nil error. The error contains `remove image <id>`, and the image is still present.
- `internal/deploy/stop.go` matches no error text for conflicts: `isConflict` has no `strings` call and no `.Error()` call.
- `github.com/containerd/errdefs v1.0.0` is a direct requirement in `go.mod`, with no `// indirect` comment. No other module is added, removed or re-versioned.
- `TestRetainRemovesImagesOutsideFive` still passes unchanged.
- Integration tests skip without a Docker Engine except under `CI`, where they fail (AGENTS.md, "Testing rules").
- `make ci` is green, and `scripts/verify check FR6-2` passes.
- No spec change: docs/specs/release.md "Keep five" already says what the code does after this ticket.

## Out of scope

- `isNotFound`'s text match in `internal/deploy/engine.go`: FR2-3 and FR3-1 cover not-found and not-running. This ticket does not touch them.
- The `statusRetired` copy in `internal/deploy/stop.go`: FR6-6.
- The health-gate test limits in `internal/deploy/switch_test.go`: FR6-8.
- depguard rules for Caddy and coder/websocket: FR6-4.

## Security notes

- `docs/threat-model.md` §3 B5 (agent → Docker Engine): image removal stays by ID and without force, so no reference from a message reaches the Engine. No container is created, so nothing new bypasses `internal/policy`.
- §8 and AGENTS.md "Fail loudly": a removal failure that is not the typed conflict or not found must reach `onError` and must not be swallowed. That is the bug this ticket fixes.
- The new direct module is the one ADR-0017 accepts, at the version it pins. depguard confines it to `internal/deploy`.
- Error messages carry only the image ID, never environment values or tokens.
