# One update-channel mapping

Three specs describe the channel an agent reports, and they disagree. `docs/specs/container-policy.md` "agent.toml" and `internal/policy/parse.go` accept `update.channel` as lower-case `stable` or `canary`, and treat an absent key, or an absent file, as `stable`. `docs/specs/protocol.md` "Heartbeat" and `docs/specs/update.md` §1 "Polling" say `Heartbeat.update_channel` is `"STABLE"` or `"CANARY"` copied from that key "byte for byte", and that it is empty, and the agent is never offered an update, when the key is unconfigured. `internal/protocol/heartbeat.go` rejects `stable` and `canary`. Both specs also say the field is "set by W7-6d", but W7-6d only defined and validated it, and the agent's `Heartbeat` (`internal/agent/connect.go`) still sets only `agent_version` (R-5 finding 2). After this ticket the three specs state one mapping, word for word the same, and name W7-6e as the ticket that sets the field.

The mapping is a contract: it fixes what the `agent.toml` schema means and what the agent puts in a protocol field. The owner decides it before this ticket is built (AGENTS.md "Contracts"). The decision is one choice, what an absent `update.channel` reports:

- **Absent means stable**: `stable` → `STABLE`, `canary` → `CANARY`, absent key or absent file → `STABLE`. This keeps `docs/specs/container-policy.md`, ADR-0004's schema and `internal/policy` as they are, and only `update.md` and `protocol.md` change.
- **Absent means not offered**: `stable` → `STABLE`, `canary` → `CANARY`, absent key or absent file → empty, and the agent is never offered an update. This changes the "Absent means `stable`" row and the absent-file rule of `docs/specs/container-policy.md`, and `policy.Config` then has to tell an absent key from `stable`, which a later ticket the owner names must implement.

**Owner decision, 2026-11-20: absent means stable.** `stable` → `STABLE`, `canary` → `CANARY`, absent key or absent file → `STABLE`. The owner recorded it as item 31 of `docs/specs/update.md` §10. This ticket writes that mapping into the three specs; `docs/specs/container-policy.md` and `internal/policy` already say `stable` for an absent key and file.

## Scope

  - §1 "Polling", the `update_channel` bullet: state the mapping as a table or list of the three cases (`stable`, `canary`, absent) and the value each reports; say the agent sets the field from W7-6e; say the field is also empty from an agent built before W7-6e, and an agent that reports empty is never sent an `UpdateOffer`; keep "Any other non-empty value is rejected", "no `UNSPECIFIED` value" and "The control plane cannot change that file (ADR-0004 d5)". Delete "set by W7-6d".
  - The opening paragraph, where it lists what W7-6e builds: add that W7-6e sets `Heartbeat.update_channel` from `agent.toml`.
  - §10: unchanged. Item 31 already records the decision; add no other item.
- `docs/specs/protocol.md` "Heartbeat": the `update_channel` paragraph states the same mapping as `update.md` §1, says W7-6d added and validates the field and W7-6e sets it, and keeps the wire rule: only empty, `STABLE` and `CANARY` open, so `stable`, `UNSPECIFIED` and whitespace are rejected. Delete "byte for byte" as a description of copying from `agent.toml`; the agent maps the file's lower-case value to the upper-case wire value.
- `docs/specs/container-policy.md` "agent.toml": the `update.channel` row states the same mapping and points to `docs/specs/update.md` §1 for the wire value. Under "Absent means not offered", the row and the "An absent file is an empty configuration" bullet change to match; under "Absent means stable", they keep saying `stable`.
- No code, test, `.proto` or ADR changes.

## Security notes

`docs/threat-model.md` §2 "Host root" and §3 B3: `agent.toml` is local policy the control plane cannot change, and the agent chooses its channel only from that file. The text must keep saying that the control plane learns the channel from the heartbeat and cannot change it (ADR-0004 d5), and that an offer names no channel (`docs/specs/update.md` §1 and §6). The mapping is not a trust boundary: whatever the heartbeat says, the agent accepts only the version its own channel's signed pointer names (`docs/specs/update.md` §1, check 2, `NOT_ON_CHANNEL`; TM §3, the ninth boundary). The docs must not claim the reported channel is authenticated beyond the B3 connection that carries it.
