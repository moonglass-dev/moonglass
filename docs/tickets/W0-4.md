# Fleet scripts

## Outcome

`scripts/fleet/` can wipe and rebuild the three test-fleet VPSs described in `docs/plan/milestones.md` §1: one 2 GB x86, one 2 GB arm64, and one 4 GB x86. `scripts/measure-memory` reports process RSS so later tickets (W1-7) can enforce the agent+proxy memory budget in CI. The cloud provider token is read from the environment at run time; it is never stored in the repository, written to a file, or printed to stdout/stderr.

The week-0 test fleet is Hetzner Cloud, which can provide both x86 and arm64 in these sizes. The token is `HCLOUD_TOKEN` (or `MOONGLASS_FLEET_TOKEN` as a synonym). Server identity lives in environment variables or a gitignored inventory file; ship a non-secret `inventory.example` that shows the shape. A missing token must fail clearly and do nothing to remote servers.

## Out of scope

Actually creating or destroying the project's servers in this ticket (fleet accounts are not necessarily set up yet; the checklist item is still open). Installing the agent or proxy on a VPS. Benchmarking Coolify/Dokploy (week 8). Changing CI to fail on a memory budget (W1-7). Reading or embedding any token. Marketplace images.

## Acceptance tests

None as named Go tests. Behaviour the scripts must have, and that `make ci` must still pass:

- `scripts/fleet` (or a documented entrypoint under that directory) supports a dry-run that prints the intended wipe/rebuild actions without calling the API when the token is absent or `--dry-run` is set.
- Without a token, a real wipe/rebuild exits non-zero and does not call the network.
- `scripts/measure-memory` can report RSS for a given PID or command; it works on Linux (CI and the fleet) and does not require a cloud token. On this Mac it should still run or fail with a clear "unsupported platform" message, not a stack trace.
- `grep` over `scripts/fleet` and `scripts/measure-memory` finds no hardcoded token or password.

## Security notes

Agents running in the harness have a scrubbed environment and must never be given the provider token. Scripts may read `HCLOUD_TOKEN` / `MOONGLASS_FLEET_TOKEN` only when a human runs them. Do not log the token, put it in argv of a child process that would appear in `ps` if you can avoid it, or write it to disk. Inventory files that might later contain secrets stay gitignored.

## Done when

- `scripts/fleet/` and `scripts/measure-memory` exist, are executable, and are documented in a short `scripts/fleet/README.md`.
- The dry-run and missing-token behaviours above hold. `make ci` is green.
- No `TODO`, `FIXME`, `XXX` or `HACK` in the scripts.
