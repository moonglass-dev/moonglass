# Health-gated switch

After this ticket the agent can execute `SwitchRelease`: it checks the transition, runs the health gate on the candidate container in one of the three modes of `docs/specs/release.md` ("Health"), pushes the complete proxy config with the candidate routed through the agent's one `*deploy.Proxy`, and commits the switch in one state transaction that sets the rows' statuses and `stop_after`. A failed gate aborts the candidate with the new `release.State.Abort`, so the old release keeps serving. This implements `docs/specs/release.md`, "Executor: Switch, drain and rollback (W2-4)", steps 1 to 4 of "SwitchRelease", and the `Abort` event.

## Scope

- `internal/release`: `State.Abort(id)` as the spec's Transitions say: legal for the candidate `id` in either phase; the candidate is cleared, the phase is `none`, `Current` and `Previous` are untouched. No candidate or a different id returns an error wrapping `ErrIllegalTransition` and the input state.
- `internal/agent/state`: two one-transaction writes on the existing schema (no migration):
  - `RecordSwitch(ctx, appID, releaseID, next, now)`: refuses, writing nothing, when `next` does not equal the stored state's `Switch(releaseID)` (the `sameState` check `RecordPreDeploy` uses). Otherwise sets the new current row `current` with `switched_at` = now, the old current (if any) `previous` with `stop_after` = now + 10 minutes, the old previous (if any) `retired` with `stop_after` = now + 30 seconds, and the `apps` row to `next`.
  - `RecordAbort(ctx, appID, releaseID, next, detail)`: refuses, writing nothing, when `next` does not equal the stored state's `Abort(releaseID)`. Otherwise sets the candidate row `aborted` with `error` = detail and `container_id` empty, and the `apps` row to `next`.
- `internal/deploy`:
  - The health gate, in the three modes of "Health": HTTP `GET http://<container IP on mg-<project>>:<port><health_path>` every second with a 2-second timeout per probe, 2xx or 3xx a pass, redirects never followed; TCP connect to that address every second with a 2-second timeout when there is a port and no `health_path`; without a port, healthy once the container has run 10 consecutive seconds with an unchanged restart count. Probe modes need three passes in a row. The gate fails after 60 seconds without that, or as soon as an inspect shows the container not running or its restart count changed from the value at the gate's start. The 60-second limit is an `Executor` field set by `New`, as `preDeployLimit` is, so in-package tests can shorten it; the interval, probe timeout, three passes and 10 seconds are constants.
  - `Executor.SwitchRelease(ctx, *agentv1.SwitchRelease) *agentv1.CommandResult` in the spec's order: an unknown app is `REJECTED`; `State.Switch` illegal is `REJECTED` with nothing touched; the candidate's record is read; the gate runs; on gate failure `Abort` is applied, the candidate container is removed (force, a missing container is not an error), `RecordAbort` writes the row and the answer is `FAILED` with the aborted state; on gate success the config is pushed with the candidate routed; a failed push is `FAILED`, the stored state unchanged and the candidate still `ready`; then `RecordSwitch` commits and the answer is `SUCCEEDED` with the new state. A failed `RecordSwitch` is `FAILED` with the error and the stored state.
  - Pushing with the candidate routed: `Proxy` gains one way to push the complete document in which one app's route is built from a given release record instead of its stored current release. `Proxy.Push` and `Proxy.Run` keep their behaviour, and the routed document is recorded as the last pushed like any other.
  - `deploy.New` takes the agent's `*Proxy`, so switch pushes go through the same pusher as `Run` (W2-4a), and every existing caller in `internal/deploy` is updated.
  - `testdata/server` gains the argv modes the gate tests need (answer a chosen HTTP status, and exit or crash after a chosen delay), keeping its present modes.
- `docs/specs/release.md`: `Abort` is added by W2-4b (not W2-4); "SwitchRelease" states that step 3's document routes the candidate in place of the app's stored current release, and that a failed commit in step 4 is `FAILED` with the stored state unchanged. `docs/specs/agent-state.md`: the statuses and `stop_after`/`switched_at` values a switch writes, and the `aborted` row a failed gate writes.

## Acceptance criteria

- `TestAbortClearsCandidate`: table-driven over a `pending` and a `ready` candidate, with and without `Current` and `Previous`: `Abort(id)` clears the candidate and sets phase `none`, leaving `Current` and `Previous` equal; with no candidate, or a different id, it returns an error matching `ErrIllegalTransition` and the input state; a `Deploy` after `Abort` is legal.
- `TestRecordSwitchWritesStatusesAndStopAfter`: a first switch (no old current), a second (old current becomes `previous`) and a third (old previous becomes `retired`) each write the statuses, `switched_at` = now and `stop_after` = now + 10 minutes and now + 30 seconds in RFC 3339 UTC; a `next` that does not follow from the stored state, or a candidate not `ready`, writes nothing and returns an error.
- `TestRecordAbortMarksCandidateAborted`: the candidate row becomes `aborted` with the given `error` and an empty `container_id`, the `apps` row's candidate is null and phase `none`, `Current` and `Previous` unchanged; a `next` that does not follow from the stored state writes nothing.
- `TestHealthGateHTTPPath`: against real Docker, a candidate answering 200 and one answering a 3xx pass; one answering 500 fails at the shortened limit; the gate probes `<container IP on mg-<project>>:<port><health_path>`.
- `TestHealthGateTCPConnect`: a container listening on the port passes with no `health_path`; a port nothing listens on fails at the shortened limit.
- `TestHealthGateWithoutPort`: a container with no port that keeps running passes only after 10 seconds of running.
- `TestHealthGateFailsWhenContainerExitsOrRestarts`: a candidate that exits, and one that restarts under `unless-stopped`, fail the gate before the limit, in each mode that applies.
- `TestSwitchReleaseRoutesCandidateAndCommits`: with the fake admin socket of `proxy_test.go`, a healthy candidate is pushed routed at its container IP and port before the commit; the stored state, row statuses, `switched_at` and `stop_after` match `RecordSwitch`'s rules over three consecutive switches; the answer is `SUCCEEDED` with the new app state.
- `TestSwitchReleaseHealthFailureAborts`: an unhealthy candidate answers `FAILED`; its container is gone; its row is `aborted` with the detail as `error`; `Current` and `Previous` are unchanged; nothing is posted to `/load`; a new `Deploy` for the app is then accepted.
- `TestSwitchReleaseRefusalsAndPushFailure`: an unknown app, no candidate, a different release id and a `pending` candidate are each `REJECTED` with stored state and rows unchanged and no container touched; a `/load` answering non-2xx after a passing gate is `FAILED`, the candidate stays `ready` with its row `candidate` and its container running, and a re-sent `SwitchRelease` then succeeds.
- No result `detail` or stored `error` contains a health-probe response body.
- The executor never starts a goroutine that outlives `SwitchRelease`, and nothing stops or removes the old current or old previous container (that is W2-4).
- `make ci` is green.

## Out of scope

- The stops and removals at `stop_after`, the start-up reconcile stops, keep five, retention and the 10-minute draining behaviour: W2-4.
- The `Rollback` executor: W2-4d.
- The `agent connect` flags and running `Proxy.Run`: W2-4c.
- Dispatching `SwitchRelease` from the connection and command records: W2-10.
- The healthcheck gate mode and `Deploy.healthcheck`: W6-1c.
- Newest-wins supersession: the control plane (W2-5).

## Security notes

- `docs/threat-model.md` §3 B4: every switch push is a complete JSON config over the admin Unix socket through the one `Proxy`; nothing dials a TCP admin port.
- §3 B5 and §9.2: the switch creates no container; the only Engine calls are inspect and force-remove of the candidate container named in agent state.
- §3 B3 and §8 "Local policy beats remote command": `SwitchRelease` carries only `app_id` and `release_id`; the probe target is the container's own address on its project network and the stored `port` and `health_path`, never a host or address from the message, so the control plane cannot aim the probe elsewhere.
- §9.3: a probe's response body is never read into a result, a stored `error` or a log line, since an app can print its own environment.
- §9.8: one push path (the `Proxy`), one abort path (`release.State.Abort` plus `RecordAbort`), no code for W2-4's stops.
