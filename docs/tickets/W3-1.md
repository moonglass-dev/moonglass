# Keys

Environment keys, the agent X25519 key as an age recipient, the key record, `moonglass keys init` writing the recovery key file, wrap and unwrap; test vectors readable by stock `age` (ADR-0015, `docs/specs/secrets.md`).

After this ticket `internal/keys` is the only package that imports `filippo.io/age` v1.3.2, and it offers: generating an environment key (an age X25519 identity), encoding the agent's existing raw X25519 key (`agent-agree.key`) as an age recipient and identity without changing the file on disk, parsing X25519 recipients and identities and nothing else, the strict key record of `docs/specs/secrets.md`, and wrapping a record to one recipient and unwrapping it with one identity. `moonglass keys init --out FILE` writes a fresh recovery identity to a new 0600 file and prints its recipient and the ADR-0003 loss warning. Nothing is uploaded, stored or delivered yet (W3-2, W4-8).

## Scope

- `go.mod`, `go.sum`: require `filippo.io/age v1.3.2` (ADR-0015 decision 1). No other new module.
- `internal/keys`:
  - Generate an environment key: a fresh age X25519 identity from `crypto/rand`, with its `age1…` recipient.
  - Agent key as age: from the raw 32-byte X25519 public key, the `age1…` recipient; from the raw 32-byte private key, the age identity. A wrong length is an error. The encoding is age's own Bech32 form (lowercase `age` HRP for recipients, `AGE-SECRET-KEY-` uppercase for identities); its correctness is proved by age's own parser accepting the result and deriving the same recipient. `agent-agree.key` and the agent package are unchanged (ADR-0015 consequences).
  - Parse a recipient and parse an identity: X25519 only (ADR-0015 decision 3). Scrypt, SSH, plugin (`age1<name>1…`, `AGE-PLUGIN-…`) and post-quantum hybrid strings are refused.
  - The key record (`docs/specs/secrets.md`, "The key record"): marshal to exactly `{"v":1,"environment_id":"…","protected":…,"identity":"AGE-SECRET-KEY-1…"}` and parse strictly. `environment_id` is 32 lowercase hex characters; `identity` must parse as an X25519 identity.
  - Wrap: encrypt a marshalled record with age to exactly one X25519 recipient. Unwrap: decrypt with one identity, parse the record, and refuse it when its `environment_id` differs from the environment the caller names. Plaintext is held only in memory.
  - Stock-age vectors under `internal/keys/testdata/`: a test-only identity file and ciphertexts produced by `internal/keys` (a wrapped record to that identity, and one wrapped to an agent-agree key's recipient), checked in and also regenerated in the test.
- `internal/registry/routes.go`: add `keys init` to `LocalCommands` with synopsis `keys init --out FILE`, a summary, and `Touches` naming the recovery key file it writes.
- `cmd/moonglass`: the `keys init` local handler, calling `internal/keys` only (no age import).
- `.golangci.yml`: add `filippo.io/age` to the strict allow list; add a lax deny rule for `filippo.io/age` covering `cmd/` and every `internal/` package except `internal/keys` (ADR-0015 decision 2), in the existing per-package file-list style.
- `.github/workflows/ci.yml`: install the `age` package from the Ubuntu archive before `make ci` (ADR-0015 decision 4).
- `docs/specs/secrets.md`: the recovery-key section states exactly what `keys init` prints and where, the file's format (one age identity line readable by `age -d -i FILE`), and that the agent recipient is the age encoding of `agent-agree.key`.
- `docs/specs/registry.md`: add `keys init` to the `registry.LocalCommands` list.

## Acceptance criteria

- `TestGenerateEnvironmentKey`: two generated environment keys differ; each identity parses with the package's identity parser and its recipient starts with `age1` and equals the recipient derived from the identity.
- `TestAgentAgreeKeyAsAgeRecipient`: for a key from `GenerateAgentIdentity`, the recipient from `AgreePublic` equals the recipient of the identity from `AgreePrivate`; a record wrapped to that recipient unwraps with that identity; a table of wrong-length public and private keys (0, 31, 33 bytes) each returns an error naming the expected length.
- `TestOnlyX25519RecipientsAndIdentitiesParse`: a table of an X25519 recipient and identity (accepted) and an SSH ed25519 and RSA public key, a plugin recipient, a plugin identity, a post-quantum hybrid recipient, an empty string, and a corrupted Bech32 checksum (each refused with an error).
- `TestKeyRecordRoundTrip`: a record with each value of `protected` marshals to exactly the field order and form of `docs/specs/secrets.md` and parses back to an equal record.
- `TestKeyRecordRejectsMalformed`: a table refuses `v` of 0 and 2, a missing field (each of the four), an unknown field, a duplicated field, trailing data after the object, `environment_id` that is not 32 lowercase hex, an `identity` that is not an X25519 identity, and a non-boolean `protected`. No error string contains the identity text from the input.
- `TestWrapUnwrapKeyRecord`: a wrapped record unwraps with its identity to an equal record; unwrapping with a different identity fails; a ciphertext with one flipped byte fails; a record for environment A unwrapped as environment B is refused with an error naming both ids. No error string contains the identity text.
- `TestKeyVectorsDecryptWithStockAge`: the checked-in vectors and freshly wrapped records decrypt with `age -d -i <identity file>` to the expected record bytes. With no `age` on `PATH` the test fails when `CI` is set and skips otherwise.
- `TestKeysInitWritesRecoveryKeyFile`: `keys init --out FILE` exits 0, creates `FILE` with mode 0600 holding one identity that the package's identity parser accepts and stock `age` can use (when installed); stdout's first line is that identity's `age1…` recipient; the output contains the ADR-0003 warning that if every server in an environment is gone and no recovery key exists, nobody can decrypt its secrets or backups; the identity text never appears on stdout or stderr.
- `TestKeysInitFailures`: a table: an existing `FILE` (exit 1, file contents and mode unchanged), a missing `--out` or an extra argument (exit 2, usage), and an `--out` in a directory that does not exist (exit 1, error names the path and nothing is created).
- A fuzz target for the key-record parser exists in `internal/keys` and its seed corpus passes under `make test` (threat-model §9.1: a fuzz target for each new parser).
- `TestEverySubcommandIsGeneratedOrLocal` still passes with `keys init` listed in `registry.LocalCommands` and handled in `cmd/moonglass`.
- `filippo.io/age` is imported only by files under `internal/keys`; `make lint` fails if `cmd/` or another `internal/` package imports it.
- Only X25519 is used: no call to age's scrypt, SSH, plugin or hybrid APIs anywhere in the diff.
- `go.mod` adds `filippo.io/age v1.3.2` and no other direct requirement.
- `make ci` is green and `testdata/tests.txt` lists the new tests.

## Security notes

- Threat model §2 (user secrets, owner recovery key, agent keys): the recovery identity is written only to the file the owner names, created exclusively with mode 0600 and never overwritten; it is never printed, logged or put in an error. The agent private key does not leave `agent-agree.key`; the age identity built from it exists only in memory.
- §3 and §9.1: the key record is the only thing that will tell an agent whether an environment is protected, so parsing is strict (exact version, no unknown, missing or duplicated fields, no trailing data) and the environment id must match the caller's. age authenticates the payload; a tampered ciphertext must fail, never yield a partial record.
- §7: `internal/keys` and `internal/registry` are trusted core; the owner reads every line.
- §8 and `AGENTS.md`: cryptography is reused (age only, X25519 only, ADR-0015); no hand-written cipher or KDF. Bech32 here is an encoding, checked by age's own parser.
- `docs/specs/agent-state.md`: no key material enters agent state; this ticket does not touch the agent.
