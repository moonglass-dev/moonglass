# GitHub sign-in

A person signs in with GitHub: the provider round trip with `state` and PKCE over the standard library, a 14-day `__Host-mg_session` for an identity linked to a user, refusal for one that is not, sign-out, and a plain failure page with its CSP (`docs/specs/auth.md`, "Operator configuration", "The provider round trip", "Sessions"). It is the second piece of the W4-1b split (owner decision, 2026-11-19); W4-1b adds Google to the same flow. The session it mints is the one W4-1e authenticates.

## Scope

- `internal/auth` (new package, standard library only):
  - **Operator variables**, read once at `moonglass server` start: `MOONGLASS_PUBLIC_URL`, `MOONGLASS_GITHUB_CLIENT_ID`, `MOONGLASS_GITHUB_CLIENT_SECRET`. GitHub is on when both of its variables are set; one without the other refuses to start, naming the missing variable. With GitHub on, a missing or invalid public URL refuses to start and says why (`https`, except host `localhost` or `127.0.0.1`; no path). The secret is never logged or put in an error.
  - **Start** `GET /auth/github/start?purpose=sign-in&return=…`: `state` and `code_verifier` (32 random bytes each, base64url), the `__Host-mg_oauth` cookie (`HttpOnly`, `Secure`, `SameSite=Lax`, `Path=/`, `Max-Age=600`) holding them and the purpose and `return`, then a redirect to `https://github.com/login/oauth/authorize` with `client_id`, `redirect_uri` (`<public>/auth/github/callback`), `state`, the S256 `code_challenge`, `code_challenge_method=S256` and no `scope`. A `purpose` other than `sign-in` is answered 400 `unknown purpose`; W4-1c and W4-1 add theirs. `return` is kept only when it starts with `/` and not `//` or `/\`; otherwise `/`.
  - **Callback** `GET /auth/github/callback`: requires the cookie, compares `state` in constant time, clears the cookie whatever the result, exchanges `code` with `code_verifier` and the client secret (`POST https://github.com/login/oauth/access_token`, `Accept: application/json`), then `GET https://api.github.com/user`; the identity is `github:<id>`, the numeric id. The access token is dropped. Endpoints are fixed in code; tests pass an `httptest` server through the provider's constructor.
  - **Sign-in**: `Store.UserByIdentity`. A linked identity gets a session (`store.AddSession` with the SHA-256 of a new `mg_` bearer, 14 days absolute), the `__Host-mg_session` cookie (`HttpOnly`, `Secure`, `SameSite=Lax`, `Path=/`, `Max-Age` up to the expiry) and a redirect to `return`. An unknown identity gets the page "This GitHub account is not linked to a Moonglass user. Ask an owner of your organisation to link it."
  - **Failure page**: any failure shows one plain sentence and a link to `/sign-in`, never the provider's error text. Pages are `html/template` with no script and the header `Content-Security-Policy: default-src 'none'; style-src 'self'; form-action 'self'; frame-ancestors 'none'`.
  - **Sign-out** `POST /auth/sign-out`: revokes the current session (`store.RevokeSession`), clears the cookie and redirects to `/sign-in`. It is same-origin only, through W4-1e's cross-origin protection.
- `internal/store`: `UserByIdentity(ctx, identity) (userID string, err error)` on the interface and both backends: a read of `user_identities`, `ErrNotFound` for an unknown identity, never a write. No table or column changes.
- `internal/registry/routes.go`: `NonOperationRoutes` gains `GET /auth/{provider}/start`, `GET /auth/{provider}/callback` and `POST /auth/sign-out`, each with the authorisation in `docs/specs/auth.md`, "Routes that are not operations".
- `internal/server` and `cmd/moonglass`: read the variables at start (refusing to start as above, with exit code 1) and mount the three routes. With no provider on, the `/auth` routes answer 404 `sign-in is not configured on this server`.
- `docs/specs/auth.md`: already says this; change it only if the built behaviour needs a wording fix.

## Acceptance criteria

- `TestOperatorVariables`: a table over the variable sets: none (off), both GitHub variables with a valid URL (on), each GitHub variable alone (error naming the other), GitHub on with no URL, an `http` URL for a public host, an `http://localhost` URL (accepted), a URL with a path; the error never contains the secret.
- `TestStartSetsOAuthCookieAndRedirects`: the cookie's attributes are exactly those above; the redirect's query has `client_id`, `redirect_uri`, `state` equal to the cookie's, `code_challenge` equal to base64url(SHA-256(verifier)) with `S256`, and no `scope`; an unsafe `return` (`//evil`, `/\evil`, `https://x`) is stored as `/`; an unknown `purpose` is 400.
- `TestCallbackRefusesMissingOrMismatchedState`: no cookie, and a `state` that differs, each give the failure page, make no request to the provider and clear the cookie.
- `TestGitHubSignInIssuesSession`: with `httptest` token and user endpoints, a linked identity gets the session cookie with the attributes above, a redirect to `return`, a `session_hashes` row holding the SHA-256 of the cookie value and not the value, and W4-1e's `AuthenticateSession` accepts the cookie; the token request carried `code_verifier`; no store table holds the access token.
- `TestUnlinkedIdentityIsRefused`: an identity with no user gets the exact refusal sentence, no session and no cookie, and `user_identities` and `user_orgs` are unchanged (no user is minted).
- `TestFailurePageHidesProviderError`: a provider that answers `{"error": "bad_verification_code", "error_description": "secret detail"}` yields a page without either string, with the CSP header above and no `<script`.
- `TestSignOutRevokesSession`: after `POST /auth/sign-out` the cookie is cleared, the redirect is `/sign-in` and the session is refused by `AuthenticateSession`.
- `TestSignInRoutes404WhenNotConfigured`: with no provider on, each `/auth` route answers 404 with that message.
- `TestUserByIdentityConformanceSQLite` and `TestUserByIdentityConformancePostgres`: a linked identity returns its user; an unknown one is `ErrNotFound` and leaves `user_identities` and `user_orgs` unchanged.
- `TestEveryMountedRouteIsOperationOrAllowlisted` and every other existing test pass unchanged.
- `make ci` is green and `scripts/verify check W4-1f` passes.

## Out of scope

- W4-1e: authenticating the session on registry routes, cross-origin protection.
- W4-1b: Google, its `nonce` and ID-token checks.
- W4-1c: `purpose=step-up` and the step-up pages. W4-1: `purpose=link`, the link landing and `--print-owner-link`.
- W2-S: the `/sign-in` screen.

## Security notes

- `docs/threat-model.md` §2 (tokens) and §9.4: the session bearer is 256 bits from `crypto/rand`, `mg_`, stored only as SHA-256, shown only in the cookie; `state` and the verifier are single use and live 10 minutes in the cookie only.
- §8: a sign-in never attaches to an existing user by email and never mints a user: `UserByIdentity` only reads.
- §9.3: the client secret, the provider's access token, the session value and the provider's error text never reach a log line, an error, a page or the database.
- §9.5: `NonOperationRoutes` lists every new route with its authorisation, so the route test still covers the listener.
- ADR-0005: no new module; `net/http`, `crypto/rand`, `crypto/subtle`, `crypto/sha256` and `html/template` only.
