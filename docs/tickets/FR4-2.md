# One TLS issuer check

`internal/deploy` exports the issuer check that `issuerApps` uses, `parseAgentConnect` calls it, and the switch in cmd/moonglass is deleted; the W2-4c flag tests stay green (R-4 finding 2).

Today the three accepted `--tls-issuer` values (`acme`, `acme-staging`, `internal`) are listed twice: in the `switch` in `parseAgentConnect` (`cmd/moonglass/main.go`) and in `issuerApps` (`internal/deploy/proxy.go`). After this ticket the list lives once, in `internal/deploy`: an exported `deploy.CheckIssuer(issuer string) error` is the only place that decides whether an issuer is accepted, `issuerApps` relies on it, and `parseAgentConnect` calls it. Behaviour does not change: `docs/specs/release.md` ("Certificates") and `docs/specs/connection.md` (`--tls-issuer`) already describe it.

## Scope

- `internal/deploy`: add `func CheckIssuer(issuer string) error`. It returns nil for `acme`, `acme-staging` and `internal`, and for anything else the error `issuerApps` returns today: `TLS issuer %q is not one of acme, acme-staging or internal; pass one of those`. `issuerApps` calls `CheckIssuer` first and returns its error; the accepted values are not listed a second time as an accept/refuse decision (the per-issuer branches that build the `apps.tls` and `apps.pki` values stay, and are unreachable for a refused value).
- `cmd/moonglass`: `parseAgentConnect` replaces its `switch *issuer` with `deploy.CheckIssuer(*issuer)`; a non-nil error makes it return `agentConnectArgs{}, false`, so the command still prints the usage and exits 2 before anything is opened or dialled. The flag's help text stays.
- Tests in `internal/deploy/proxy_test.go` (or a new `internal/deploy/issuer_test.go`) and `cmd/moonglass/connect_test.go`; `testdata/tests.txt` regenerated with `make test-list`.

## Acceptance criteria

- `TestCheckIssuerAcceptsTheThreeIssuers`: table over `acme`, `acme-staging`, `internal`; `deploy.CheckIssuer` returns nil for each.
- `TestCheckIssuerRefusesOtherValues`: table over at least `""`, `letsencrypt`, `ACME`, ` acme`, `acme-staging ` and `Internal`; each returns a non-nil error whose text contains the refused value quoted with `%q` and each of `acme`, `acme-staging` and `internal`.
- `TestCheckIssuerAgreesWithPush`: table over the three accepted values and at least two refused ones; against the package's fake admin socket, `NewProxy(nil, newProxyDB(t), ProxyConfig{Socket: fake.path, Issuer: v}).Push(ctx)` returns an error exactly when `CheckIssuer(v)` does, and for a refused value the two errors have equal text and the fake socket received no request.
- `TestAgentConnectIssuerFollowsDeployCheck`: table over the three accepted values and at least three refused ones; `parseAgentConnect([]string{"--url", "https://x", "--tls-issuer", v})` returns `ok == true` exactly when `deploy.CheckIssuer(v)` returns nil, and when ok, `proxy.Issuer == v`.
- The W2-4c and W2-4a tests still pass unchanged: `TestAgentConnectProxyFlagDefaults`, `TestAgentConnectRejectsBadProxyFlags` (stderr is exactly the usage, exit 2, no `agent.db` created) and `TestProxyPushIssuers`. None of them is edited.
- No non-test Go file under `cmd/` contains the string literal `"acme-staging"`; under `internal/deploy/` only the issuer function(s) in `proxy.go` (or the file `CheckIssuer` lives in) name the three issuers.
- `make ci` is green and `scripts/verify check FR4-2` passes.

## Out of scope

## Security notes

- `docs/threat-model.md` §8: the issuer is local agent configuration from the command line; nothing the control plane sends reaches `CheckIssuer` or changes it. The check still runs before the command opens the Docker Engine, the agent state or the proxy socket, and before `Push` sends any request on the admin socket.
- `docs/threat-model.md` §9 (reviewer checklist): the change must not widen the accepted set; a value accepted before must be accepted after and a value refused before must be refused after, with `internal` still the only issuer that sets `apps.pki` with `install_trust: false`.
- `internal/deploy` still never imports `internal/proxy` (ADR-0011).
