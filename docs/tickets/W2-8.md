# Protocol: deploy identity, service settings and command results

`Deploy` gains `project`, `environment`, `service`, `port`, `health_path`, `domains` and `has_pre_deploy`, and the agent gains a typed answer to every command it accepts: the `CommandResult` message under the new type `COMMAND_RESULT`, carrying an outcome, a detail, the app's release state, and the image the release runs. `internal/protocol` validates every new field when a payload is opened, rejects unknown fields at every nesting level, and has protocol-abuse tests and a fuzz target for each new parser. This implements the section "Deploy identity, service settings and results (W2-8)" of `docs/specs/protocol.md`.

## Scope

- `proto/moonglass/agent/v1/agent.proto`:
  - `MessageType` gains `COMMAND_RESULT = 10`. `RUN_PRE_DEPLOY` stays 9.
  - `Deploy` keeps `app_id = 1`, `release_id = 2` and `image = 3`, and gains `project = 4`, `environment = 5`, `service = 6` (`string`, names 1-63 of `[a-z0-9-]`, first and last a letter or digit), `port = 7` (`uint32`, 0 or 1-65535), `health_path = 8` (`string`, only with port, 1-256 bytes, starts with `/`, charset `[A-Za-z0-9._~/-]`), `domains = 9` (`repeated string`, 0-16, only with port, lowercase DNS, no wildcard, trailing dot, or duplicate), `has_pre_deploy = 10` (`bool`).
  - New `CommandResult`: `outcome = 1` (`CommandOutcome`), `detail = 2` (`string`, at most 4096 bytes, empty on `SUCCEEDED`), `app = 3` (`AppState`, required), `image_id = 4` (`string`, empty or `sha256:` plus 64 lowercase hex), `repo_digest = 5` (`string`, empty, or `repo@sha256:` plus 64 lowercase hex, also passing the image rule: 1-512 bytes, no whitespace, no control characters, no leading `-`, non-empty repository before `@`). Emptiness of `image_id` and `repo_digest` by command type stays a producer rule for W2-3 and W3-7.
  - New `CommandOutcome` enum: `COMMAND_OUTCOME_UNSPECIFIED = 0`, `SUCCEEDED = 1`, `FAILED = 2`, `REJECTED = 3`. Zero rejected.
  - New `AppState`: `current_release_id = 1`, `previous_release_id = 2`, `candidate_release_id = 3` (`string`, empty or a W2-2 identifier) and `phase = 4` (`ReleasePhase`).
  - New `ReleasePhase` enum: `RELEASE_PHASE_UNSPECIFIED = 0`, `NONE = 1`, `PENDING = 2`, `READY = 3`. Zero rejected.
- `internal/protocol/agentv1/agent.pb.go`: regenerated with `make proto`, never edited by hand.
- `internal/protocol`:
  - `validateType` and `typeOf` know `COMMAND_RESULT` and `*agentv1.CommandResult`; `validatePayload` validates `CommandResult`.
  - `validateDeploy` checks the new fields; new validators for names, port, health path, domains, `CommandResult`, `AppState`, image id and repo digest. Every failure wraps `ErrMalformed` with the field, the expected form and the actual value or length.
  - `Open` rejects unknown fields on the nested `AppState` as well as on the top-level payload.
  - Existing tests are updated for the new required `Deploy` fields, and `TestDeployMessagesRejectUnknownType` stops using `10` as its unknown type (it becomes `COMMAND_RESULT`); it keeps asserting the same rejections with numbers that remain unknown. No assertion is removed or weakened.
- `docs/specs/protocol.md`: add `COMMAND_RESULT` to the `MessageType` list; delete "Until W2-8 merges, they are not on the wire."; record the `ReleasePhase` zero value, that `app` is required, and that `image_id` and `repo_digest` hex is lowercase.

Validation rules, as in `docs/specs/protocol.md`:

- **Name** (`project`, `environment`, `service`): required, 1 to 63 bytes of `[a-z0-9-]`, first and last byte a letter or digit.
- **`port`**: 0 (none) or 1 to 65535.
- **`health_path`**: empty, or (only with a non-zero `port`) 1 to 256 bytes, starting with `/`, only `[A-Za-z0-9._~/-]`.
- **`domains`**: 0 to 16 entries, any entry only with a non-zero `port`; each at most 253 bytes, at least two labels separated by `.`, each label 1 to 63 bytes of `[a-z0-9-]` not starting or ending with `-`; no `*`, no trailing dot, no empty label; no duplicate entries.
- **`CommandResult.outcome`**: `SUCCEEDED`, `FAILED` or `REJECTED`.
- **`CommandResult.detail`**: at most 4096 bytes; empty when `outcome` is `SUCCEEDED`.
- **`CommandResult.app`**: present; each release id empty or an identifier (the W2-2 identifier rule); `phase` `NONE`, `PENDING` or `READY`.
- **`image_id`**: empty, or `sha256:` followed by exactly 64 lowercase hex characters.
- **`repo_digest`**: empty, or a value that passes the `image` rule (1 to 512 bytes, no whitespace, no control characters, no leading `-`) and ends in `@sha256:` plus exactly 64 lowercase hex characters, with a non-empty repository before that `@`.

## Acceptance criteria

- `TestDeployIdentityRoundTrip`: a `Deploy` with every new field set, at the boundaries (63-byte names, single-character names, `port` 1 and 65535, a 256-byte `health_path`, 16 domains, a 253-byte domain, a 63-byte label, `has_pre_deploy` true and false), and a `Deploy` with `port` 0, no `health_path` and no domains, each round-trip through `Wrap`, `Marshal`, `Unmarshal` and `Open` and are `proto.Equal` to the input.
- `TestDeployRejectsBadIdentity`: for each of `project`, `environment` and `service`: empty, 64 bytes, an uppercase letter, `_`, `.`, a space, a non-ASCII byte, a leading `-` and a trailing `-` are each rejected by `Open` with `ErrMalformed`, and the error names the field.
- `TestDeployRejectsBadServiceSettings`: `Open` rejects with `ErrMalformed`: `port` 65536 and 2^32-1; `health_path` without a port; `health_path` not starting with `/`, of 257 bytes, or containing `?`, `%`, a space, `#` or NUL; domains without a port; 17 domains; a duplicate domain; a single-label domain; `*.example.com`; `example.com.`; an uppercase domain; an empty entry; an empty label (`a..com`); a 64-byte label; a label with a leading or trailing `-`; a 254-byte domain.
- `TestCommandResultRoundTrip`: a `CommandResult` for each outcome round-trips through the envelope under `COMMAND_RESULT` and is `proto.Equal` to the input, including a 4096-byte `detail` on `FAILED`, an `AppState` in each phase with ids empty and set, a valid `image_id`, and a valid `repo_digest` and an empty one.
- `TestCommandResultRejectsInvalid`: `Open` rejects with `ErrMalformed`: outcome `UNSPECIFIED` and an unknown number; a 4097-byte `detail`; a non-empty `detail` with `SUCCEEDED`; a missing `app`; phase `UNSPECIFIED` and an unknown number; an `AppState` release id that breaks the identifier rule; an `image_id` without the `sha256:` prefix, with 63 or 65 hex characters, or with uppercase hex; a `repo_digest` with no `@sha256:`, an empty repository, uppercase hex, whitespace, a leading `-`, or more than 512 bytes.
- `TestCommandResultProtocolAbuse`: unknown fields appended to a `CommandResult` payload, and unknown fields inside its nested `AppState`, are rejected with `ErrMalformed`; unknown fields inside a `Deploy` payload are rejected; a `COMMAND_RESULT` envelope opened as `Deploy`, and a `DEPLOY` envelope opened as `CommandResult`, fail with `ErrTypeMismatch`; `Wrap(COMMAND_RESULT, …, &Deploy{})` fails with `ErrTypeMismatch`; a `COMMAND_RESULT` envelope carrying `error` is rejected by `Marshal` and `Unmarshal`; a `CommandResult` whose encoding pushes the envelope over `MaxEnvelopeSize` fails `Marshal` with `ErrTooLarge`.
- `FuzzOpenDeploy`: arbitrary payload bytes in a `DEPLOY` envelope, seeded with a valid full `Deploy` and edge cases; `Open` never panics; any payload it accepts passes the validators above, re-wraps, opens again and is `proto.Equal` to the first result.
- `FuzzOpenCommandResult`: the same for `COMMAND_RESULT` and `CommandResult`, seeded with a valid result per outcome and a payload with unknown nested fields.
- Every existing test in `internal/protocol` still passes with its assertions intact; `TestEnvelopeRoundTripEveryType` covers `COMMAND_RESULT` through the descriptor.
- `make proto-check` is clean: `agent.pb.go` matches `make proto` output.
- No new field is a host shell command, a host command line or a host path; `health_path` is an HTTP path inside the container.
- No new dependency; `go.mod` and `go.sum` are unchanged.

## Out of scope

- Binding an `app_id` to its project, environment and service, and answering a mismatch `REJECTED`: W2-3 (agent state) and the executor.
- Producing `CommandResult`s, the health gate and the without-port rule: W2-3, W2-4.
- Direction enforcement, accepted types per side, request-id rules and re-sending: W2-10 (`docs/specs/connection.md`).
- `Build`, `DiskReport` and `deploy_key` in `Heartbeat`: W3-7.
- Routes and domains in the proxy: the proxy tickets.

## Security notes

- `docs/threat-model.md` §3 B3: the agent treats the control plane as hostile. Every new field is size- and format-checked when the payload is opened, before any later code acts, and unknown fields are rejected at every nesting level, including `AppState`.
- §9.1: The owner approved this .proto contract on 2026-11-17: COMMAND_RESULT = 10; Deploy fields project=4, environment=5, service=6, port=7, health_path=8, domains=9, has_pre_deploy=10; CommandResult outcome=1, detail=2, app=3, image_id=4, repo_digest=5; CommandOutcome UNSPECIFIED=0, SUCCEEDED=1, FAILED=2, REJECTED=3; AppState current_release_id=1, previous_release_id=2, candidate_release_id=3, phase=4; ReleasePhase UNSPECIFIED=0, NONE=1, PENDING=2, READY=3. Zero values are rejected, app is required, and image_id and repo_digest hex is lowercase. The plan step must proceed. No field carries a shell string, host command line or host path: names are `[a-z0-9-]` (safe as an `agent.toml` path element), `health_path` is a restricted-alphabet HTTP path, domains are lowercase DNS names with no wildcard. There is a protocol-abuse test and a fuzz target for each new parser.
- §9.3: `CommandResult.detail` travels to the control plane and its database. The protocol caps it at 4096 bytes and empty on success; producers (W2-3 onward) must never put an environment value, secret or credential in it, and that is stated in the spec, not enforced here.
- §8 "local policy beats remote command": `project`, `environment` and `service` only select `agent.toml` blocks; they grant nothing. The binding that stops a control plane moving an app between projects is W2-3's and must hold there.
