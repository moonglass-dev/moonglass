# Let write sessions commit and format, and read real ADR status lines

## Outcome

Three harness fixes found while running W1-1:

1. A write session can run the commit forms it actually uses. W1-1's tests stage stalled on `git add internal/policy testdata/escape && git commit -q -m "W1-1: tests"` and on formatting. `.claude/settings.json` now allows `git commit` with `-q`, `--quiet`, `-a`, `-s` or `--allow-empty` before `-m` (plus `-qm`, `-am`, `-sm`). Formatting goes through the existing `make fmt` and `make fmt-check` allows; direct `gofmt` is not allowed. Chains of allowed commands (`git add … && git commit … && git status && git log`) run; the harness matches each part of a compound against the allow and deny rules, so a denied part denies the whole chain.
2. `adr_names` in `scripts/ticket` accepts both status lines the repo uses: `- Status: accepted` (ADR-0008) and `- **Status:** Accepted` (ADR-0001 to ADR-0007). Proposed, Rejected, Deprecated and Superseded (or Superceded) are not accepted.
3. `adr_names` keeps skipping an "Alternatives rejected" section through its deeper subheadings (`###` under `##`) until a heading of the same or a shallower level, so a module under such a subheading stays blocked.

`docs/harness.md` describes all three.

## Out of scope

Allowing `git commit` without `-m`, or with a message from a file. Changing the verify gates or `is_protected`. Product code. New ADRs. Relaxing any existing deny.

This ticket edits the guard (`.claude/settings.json`, `scripts/ticket`), which the harness cannot do for itself, so it runs out of band with a direct `claude -p`.

## Acceptance tests

`make test-harness` covers:

- `.claude/settings.json` allows `git commit -q -m *`, `-qm`, `--quiet -m`, `-am`, and every `git commit` allow starts with `-m` or one of the listed flags followed by `-m`.
- It still denies `git commit` with `-F`, `--file`, `--template`, `--no-verify`/`--no-v*`, `-n` (and the `-qn`/`-qF` bundles), `--amend`/`--am`/`--ame`, `--pathspec-from-file` for `git add` and `git commit`, and `git push`, `reset`, `rebase`, `config`, `hook` and `--force`. `git add -n` is not denied.
- A module in an ADR with `- **Status:** Accepted` passes the plan stage. One in an ADR with `- **Status:** Proposed`, `Rejected`, `Deprecated`, `Superseded` or `Superceded`, or `- Status: rejected`, blocks.
- Under `## Alternatives rejected`, a `###` subheading (`example.com/rejected-sub`, and one that does not say "rejected"), and the body below it, still block their modules. A heading after the section ends the skip.

A one-off `claude -p` probe against the committed file showed the chains and bypass forms behaving as described (`git add a && git commit -q -m x && git status` runs; `-F`, `--no-verify`, `--no-verif`, `-n`, `-sn`, `-qF`, `--am`, `--template`, `--pathspec-from-file` and `&& git push` are denied). `make ci` stays green.

## Security notes

Touches the agent permission boundary. The new `git commit` allows are limited to prefixes that put `-m` first or after a safe flag, so a message from a file, `-n`, `--amend` or a pathspec file cannot lead the command, and the denies catch them after `-m`. Short-flag bundles are denied only for the combinations listed (`-qn`, `-an`, `-sn`, `-vn`, `-qF`, `-aF`, `-sF`, `-vF` and `-n*`/`-F*`); an unusual bundle such as `-qan` after the message is not caught. Nothing in this repo runs commit hooks, and the `paths` gate and review still apply. Direct `gofmt` is deliberately not allowed: it can write files, and path denies match raw command text, so quoted or variable-expanded absolute paths would escape the worktree. Write sessions format only through `make fmt` and `make fmt-check`. The ADR change only widens what counts as accepted to the form the repo already writes, and narrows what counts as an unrejected section.
