# Agent key files in internal/keys

R-1 finding 3: the agent's private keys and the control-plane pin are read and written by `internal/agent`, outside trusted core, which disagrees with ADR-0010, `docs/specs/agent-state.md` and the heading "Agent identity (`internal/keys`, agent only)" of `docs/specs/enrolment.md`. After this ticket `internal/keys` is the only package that knows the names, formats and modes of `agent-signing.key`, `agent-agree.key`, `control-plane.pub` and `fingerprint`, and the only one that reads or atomically writes them. `internal/agent` calls it. File names, contents, modes and every behaviour in `docs/specs/enrolment.md` and `docs/specs/connection.md` stay exactly as they are.

## Scope

- `internal/keys`: a new file (for example `agentfiles.go`) that owns the four file names as unexported constants and one unexported atomic writer (temp file in the same directory, mode 0600 set before any byte is written, rename over the target, temp file removed on every failure path), moved from `internal/agent/enroll.go` `writeFile`. Exported functions, standard library only:
  - `LoadAgentIdentity(dataDir string) (AgentIdentity, bool, error)`: the body of today's `loadIdentity`. `false, nil` when `agent-signing.key` does not exist; an error when `agent-agree.key` is missing, the signing key is not 64 bytes, or the agree key is not a valid X25519 private key.
  - `LoadAgentSigningKey(dataDir string) (ed25519.PrivateKey, error)`: reads and length-checks `agent-signing.key` only, as `connect` does today. `LoadAgentIdentity` uses it, so the signing key is read one way.
  - `WriteAgentIdentity(dataDir string, id AgentIdentity) error`: writes `agent-signing.key` (raw 64 bytes) and `agent-agree.key` (raw 32 bytes).
  - `LoadControlPlanePin(dataDir string) (ed25519.PublicKey, error)` and `WriteControlPlanePin(dataDir string, pin ed25519.PublicKey) error`: raw 32 bytes in `control-plane.pub`; both reject any other length, and the write rejects it before touching the file.
  - `WriteFingerprint(dataDir, fingerprint string) error`: the lowercase hex plus `\n` in `fingerprint`.
  - Every error names the file and wraps its cause with `%w`, so `errors.Is(err, fs.ErrNotExist)` holds for a missing file.
- `internal/agent/enroll.go`: delete the file-name constants, `loadIdentity` and `writeFile`; call the `internal/keys` functions in the same order as today (identity only when it was not already saved, then pin, then fingerprint), all after the `ACCEPTED` response. The writability probe and `MkdirAll(dataDir, 0o700)` stay in `Enroll`, before the POST. Errors keep the `enrol:` prefix and the "remove DIR to start over" advice.
- `internal/agent/connect.go`: delete `loadConnectKeys`; call `keys.LoadAgentSigningKey` and `keys.LoadControlPlanePin`. Errors keep the `connect:` prefix and the "run `moonglass agent enroll` first" / "remove DIR and enrol again" advice. Connect still reads only the signing key and the pin, and never writes the data dir.
- `docs/specs/enrolment.md`: under "Agent identity (`internal/keys`, agent only)", say that `internal/keys` reads and writes these four files and `internal/agent` calls it. No other spec text changes.

## Acceptance criteria

- `TestAgentIdentityFilesRoundTrip`: `WriteAgentIdentity` then `LoadAgentIdentity` on a temp dir returns `saved == true` and an identity equal to the generated one in all four fields; `agent-signing.key` holds exactly the 64-byte private key and `agent-agree.key` exactly the 32-byte private key, both mode 0600; writing a second identity replaces both files and no `*.tmp-*` file is left in the directory.
- `TestLoadAgentIdentityAbsentDir`: on an empty temp dir `LoadAgentIdentity` returns `saved == false` and a nil error, and the directory is still empty afterwards.
- `TestLoadAgentIdentityRejectsMalformed`: table-driven; a signing key with no agree key, a signing key of the wrong length, and an agree key that is not 32 bytes each return an error whose text names the offending file; `LoadAgentSigningKey` rejects a wrong-length signing key and returns an error satisfying `errors.Is(err, fs.ErrNotExist)` when the file is missing.
- `TestControlPlanePinFile`: `WriteControlPlanePin` then `LoadControlPlanePin` round-trips the raw 32-byte key in `control-plane.pub` with mode 0600; a second write replaces the pin; a write of a 31- or 33-byte key fails and leaves the existing file byte-for-byte unchanged; a wrong-length file on disk is rejected on load; a missing file gives `errors.Is(err, fs.ErrNotExist)`.
- `TestFingerprintFile`: `WriteFingerprint` writes exactly the fingerprint followed by `\n` to `fingerprint` with mode 0600, and a write into a directory that does not exist fails with an error naming `fingerprint`.
- `TestAgentPackageHoldsNoKeyFileIO`: no non-test `.go` file directly in `internal/agent` (not its subpackages) contains any of the strings `agent-signing.key`, `agent-agree.key`, `control-plane.pub` or `"fingerprint"`; the failure message lists each file and string found.
- Every existing test in `internal/agent` (`enroll_test.go`, `connect_test.go`), `internal/keys` and `cmd/moonglass` passes unchanged; none is edited, skipped or weakened.
- File names, byte formats, modes (files 0600, directory 0700), write order and the "nothing written before `ACCEPTED`" rule are unchanged.
- `internal/keys` gains no import outside the standard library and the modules it already has; `.golangci.yml` is unchanged.
- No other package reads or writes these four files after the change.
- `make ci` is green and `scripts/verify check FR1-3` passes.

## Out of scope

- How enrolment gets TLS and how the agent authenticates the control-plane key before pinning it (FR1-1).
- Storing the agent age recipient on the control plane (FR1-2).
- The server's own identity file in `internal/server`.
- The SSH deploy key (W3-8) and wrapped key records on the agent (W4-8), which build on these functions later.
- Adding `fsync`, changing the temp-file pattern, or any other change to how the files are written beyond moving the code.

## Security notes

- `docs/threat-model.md` §7 (trusted core): the point of the ticket is that agent private keys and the pin are handled only in `internal/keys`, so changes to them get trusted-core review. The review checks that no copy of the read or write logic is left in `internal/agent`.
- §2 (agent keys are never held by the control plane) and B3 (control-plane key pinned at enrolment): private keys are never sent, logged or put in error text; the pin is written only after an `ACCEPTED` response with a 32-byte key, and a wrong-length pin is refused before any file changes.
- ADR-0010: no key material goes to `internal/agent/state`; this ticket keeps the files under `internal/keys`' control in the agent data dir.
- Errors name files and paths but never include key bytes.
