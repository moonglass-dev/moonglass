# Proxy config push

The agent gets its one proxy pusher: `deploy.NewProxy(engine, db, deploy.ProxyConfig{Socket, Issuer, OnError})` builds the complete Caddy JSON from every app's current release that has domains and pushes it to the proxy's agent-facing admin socket with `POST /load`, repeating the `admin` and `storage` values it reads from the running proxy. `Proxy.Run` pushes at start and again whenever the running config is not the last one pushed, so a restarted proxy gets its routes back without the control plane. `Deploy` refuses a domain that another app's current release already routes. This implements `docs/specs/release.md`, "Proxy config" and step 3 of "Order"; the `agent connect` wiring is W2-4c.

## Scope

- `internal/agent/state`: one read, `CurrentReleases(ctx) ([]CurrentRelease, error)`. A `CurrentRelease` is an app's `Binding` and the `Record` of the release in its `current_release_id` (domains, port, container id included). It returns every app that has a current release, ordered by `app_id`; an app with only a candidate, or with no releases, is absent. It is the one query both the domain check and the config builder use. No migration: the schema already holds everything.
- `internal/deploy`, `Deploy`: step 3 of "Order". After the transition and before the image, read `CurrentReleases`; the first domain of the `Deploy`, in the order sent, that appears in the domains of a current release of a different `app_id` is `REJECTED` with `domain <name> is already routed to app <app_id>`, through the existing `rejected` / `fail` path, so a `failed` row is written with that detail as `error`, the state is unchanged and nothing is created. The app's own current release never conflicts with it, and another app's candidate does not hold its domains.
- `internal/deploy`, new file `proxy.go`:
  - `type ProxyConfig struct { Socket string; Issuer string; OnError func(error) }` and `func NewProxy(engine *Engine, db *state.DB, cfg ProxyConfig) *Proxy`.
  - The admin-socket client: an `http.Client` whose transport dials `unix` at `Socket` and nothing else; every call has the 60-second call limit of `engine.go`. It uses only `GET /config/admin`, `GET /config/storage`, `GET /config/` and `POST /load`. A non-2xx answer is an error carrying the method, path, status and the body (bounded, as `truncate` bounds a detail).
  - `Proxy.Push(ctx) error`: holds a mutex for its whole run, so pushes run one at a time. It reads `admin` and `storage` from the socket, reads `CurrentReleases`, and for each current release with at least one domain inspects its `container_id` through the Engine for its IP on `mg-<project>`. A container that is gone or has no address on that network is an error naming the app, the release and the container, and nothing is posted. It then posts the config below and, only when `/load` answers 2xx, records the posted document as the last pushed.
  - The config, as one JSON object:
    - `admin` and `storage`: exactly the JSON values the two `GET`s returned.
    - `logging`: `{"logs": {"default": {"level": "WARN"}}}`, the level the proxy starts with (`docs/specs/proxy.md`), so a push does not change it.
    - `apps.http`: `grace_period` `"30s"`. When at least one route exists, one server `moonglass` with `listen` `[":443"]` (the proxy unit binds :80 and :443, `docs/specs/install.md`; Caddy's automatic HTTPS adds the :80 redirect) and `routes`, one per routed app in `app_id` order: `{"match": [{"host": <the release's domains, in stored order>}], "handle": [{"handler": "moonglass_counter", "release": <release id>}, {"handler": "reverse_proxy", "upstreams": [{"dial": "<container IP>:<port>"}]}], "terminal": true}`. With no routes, `apps.http` holds only `grace_period` and no server, so nothing listens.
    - `apps.tls`: `{"automation": {"policies": [{"issuers": [<issuer>]}]}}`, where the issuer is `{"module": "acme"}` for `acme`, `{"module": "acme", "ca": "https://acme-staging-v02.api.letsencrypt.org/directory"}` for `acme-staging`, and `{"module": "internal"}` for `internal`. Only for `internal`, `apps.pki` is `{"certificate_authorities": {"local": {"install_trust": false}}}` (`docs/specs/proxy.md`).
    - Any other `Issuer` makes `Push` return an error that names the value and the three accepted ones, before anything is read or posted.
  - `Proxy.Run(ctx)`: pushes once at start, then every second `GET`s `/config/`. When the probe answers 2xx and its body, decoded as JSON, is not deep-equal to the last pushed document decoded the same way (or nothing has been pushed yet), it pushes again. A probe that fails is not reported. A push that fails is passed to `OnError` (when it is non-nil) and retried at the next probe; it never stops `Run`. `Run` returns `nil` only when `ctx` ends.
  - `internal/deploy` never imports `internal/proxy` or Caddy (depguard `deploy-deps`).
- `internal/proxy`: one test file only (`TestAgentPushLoadsIntoProxy`); no product code changes.
- `docs/specs/release.md`, "Proxy config": name `OnError` in `ProxyConfig`, the server name and `listen`, the `logging` value, the empty-routes rule, route order, the issuer JSON, and the gone-container error. `docs/specs/proxy.md`: one line in "Admin API" pointing to `docs/specs/release.md` for the config the agent pushes.

## Acceptance criteria

- `TestCurrentReleasesListsEveryAppsCurrentRelease`: in a temp agent state, with app `a` whose current release has domains, app `b` whose current release has none, app `c` with only a candidate, and a `failed` row for app `d`, `CurrentReleases` returns exactly `a` then `b`, each with its binding and its current release's record (domains, port, container id as stored); `c` and `d` are absent. Current releases are seeded through `RecordCandidate` and a direct SQL update of `apps.current_release_id` in the test, since the switch is W2-4b.
- `TestDeployRejectsDomainRoutedByAnotherApp` (real Docker, imported images, per-run project): table of cases. (1) Another app's current release routes `x.example.com`; a `Deploy` with domains `[y.example.com, x.example.com]` is `REJECTED` with detail exactly `domain x.example.com is already routed to app <other app_id>`, a `failed` row with that `error` exists, the app's stored state is unchanged, and no container `mg-<app_id>-<release_id>` exists. (2) Another app has only a candidate with that domain: `SUCCEEDED`. (3) The app's own current release has that domain and the new release keeps it: `SUCCEEDED`. (4) An illegal transition with a conflicting domain is `REJECTED` with the transition error, not the domain error, and writes no row.
- `TestProxyPushBuildsCompleteConfig` (real Docker): with a fake admin socket (an `httptest` server on a Unix socket in a short temp path) that answers `GET /config/admin` and `/config/storage` with fixed values and records each `POST /load` body, and agent state holding two routed apps (current releases with running containers on `mg-<project>`, one with two domains), one current release without domains and one candidate with domains, `Push` returns nil and posts exactly one body that, decoded, deep-equals the expected document of "Scope": `admin` and `storage` echoed verbatim, `logging` WARN, `grace_period` `"30s"`, server `moonglass` on `[":443"]` with two routes in `app_id` order, each host match, `moonglass_counter` with the release id, and `reverse_proxy` dialling the container's IP on `mg-<project>` and the release's port. With no routed app the body has `apps.http` equal to `{"grace_period": "30s"}`.
- `TestProxyPushIssuers`: table over `acme`, `acme-staging` and `internal`: `apps.tls` and the presence of `apps.pki` are exactly as "Scope" says. An issuer of `letsencrypt` returns an error containing `letsencrypt`, `acme`, `acme-staging` and `internal`, and the fake socket received no request at all.
- `TestProxyPushFailuresPushNothing`: table: no socket at the path; `GET /config/admin` answering 500; `POST /load` answering 400 with a body (the error contains `400` and that body); a routed current release whose container was removed (the error names the app, the release and the container). In every case `Push` returns a non-nil error, and in all but the `/load` case no `POST /load` was received. A failed push does not become the last pushed: a following `Run` probe, with `/config/` answering the failed body, pushes again.
- `TestProxyPushesOneAtATime`: ten concurrent `Push` calls against a fake socket whose `/load` handler sleeps 50 ms all return nil, the handler saw ten requests, and never more than one in flight.
- `TestProxyRunPushesAgainWhenRunningConfigDiffers`: against a fake socket whose `GET /config/` answers the last `/load` body it received: `Run` posts once within 2 seconds of starting and no second time in the next 3 seconds. When the fake starts answering `/config/` with the proxy's start-up config (as after a restart), `Run` posts again within 3 seconds. While the socket is closed and then reopened at the same path, `Run` keeps running, `OnError` is not called for the failed probes, and it posts again after the reopen. When `/load` answers 400, `OnError` receives an error containing `400` and `Run` keeps probing. Cancelling the context makes `Run` return nil within 2 seconds.
- `TestAgentPushLoadsIntoProxy` (`internal/proxy`, needs a Docker Engine for `deploy.Connect`; skips without one, except under `CI`, where it fails): `proxy.Run` on a temp data dir and admin socket; `deploy.NewProxy` with an empty temp agent state and issuer `internal`; `Push` returns nil, and `GET /config/apps/http/grace_period` over the admin socket answers `"30s"`. Then the proxy is stopped and started again on the same paths while `Proxy.Run` runs: within 5 seconds of the restart, `GET /config/` decoded equals the pushed document again.
- Every existing test in `internal/deploy`, `internal/agent/state` and `internal/proxy` passes unchanged; `testdata/tests.txt` lists the new tests.
- `internal/deploy` imports neither `internal/proxy` nor Caddy (`make lint`).
- `make ci` is green and `scripts/verify check W2-4a` passes.

## Out of scope

- W2-4c: `moonglass agent connect --proxy-socket` / `--tls-issuer`, opening the Engine and state there, and running `Proxy.Run` for the command's life.
- W2-4b: `release.Abort`, the health gate and `SwitchRelease`, which pushes through this `Proxy` and is what first makes a release current in production.
- W2-4d: the rollback executor and its push. W2-4: the rest of the switch and drain work.
- W2-12: the admin socket path, mode and group (merged). W4-3: reading the counters.

## Security notes

- `docs/threat-model.md` §3 B4: the agent reaches the proxy only through the Unix socket at `Socket`; it never dials TCP to an admin API and never creates, chmods or removes the socket. Every push is a complete JSON document that repeats `admin` and `storage` exactly as the proxy reports them, so the proxy's guard (`internal/proxy/guard.go`) accepts it and the admin API and certificate keys stay where they are.
- §3 B5 and ADR-0014: the Engine is used only to inspect the release's container for its IP; nothing new is created or run, and `internal/proxy` gains no Docker import in product code.
- §3 B8, ADR-0001 decision 5: the proxy reaches containers only by their bridge IP on `mg-<project>`; no port is published on the host.
- One app can never take over another's traffic: a domain routed by another app's current release is refused at `Deploy`, before anything is created.
- No secret or token is in the config, an error, or `OnError` output; the config holds only domains, release ids, IPs and ports. Nothing is run through a shell.
