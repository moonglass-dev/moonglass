# Agent command dispatch and `--policy`

After this ticket the agent's connection carries the deploy commands. `moonglass agent connect --policy FILE` loads `agent.toml` with `policy.LoadFile` and an Env read through `deploy.PolicyEnv`. It builds the one `deploy.Executor`, runs `Executor.Run` for its whole life next to `Proxy.Run`, and hands every accepted `DEPLOY`, `SWITCH_RELEASE`, `ROLLBACK` and `RUN_PRE_DEPLOY` envelope to the matching executor method with the envelope's request id. Commands for one app run one at a time in arrival order and different apps run concurrently. A request id that is queued or running is never started again, and each result goes out on whichever connection is live when it finishes. This implements `docs/specs/connection.md`, "Command channel" → "Agent" and "Each request id runs once" rules 1–3, on top of W2-10a's `commands` table and the executor's stored-result answer.

## Scope

- `internal/deploy` (`policyenv.go`): `PolicyEnv(ctx context.Context, e *Engine) (policy.Env, error)`.
  - It reads the Engine's info once. `Paths.DockerRoot` is `DockerRootDir` and `DefaultRuntime` is the default runtime.
  - The fixed paths are those of `docs/specs/container-policy.md`, "API": `Paths.MountsRoot` is `/var/lib/moonglass/mounts`, `Paths.DockerSockets` is `/var/run/docker.sock` and `/run/docker.sock`, and `Paths.ContainerdSockets` is `/run/containerd/containerd.sock`.
  - `ContainerProject(ref)` inspects the container `ref` within the 60-second call limit. It returns the container's `dev.moonglass.project` label and true when the container exists and carries the label. A container that does not exist, has no such label or cannot be inspected returns `"", false`: an unknown container is cross-project.
  - A failed info call returns an error that names the Engine.
- `internal/agent` (`connect.go`, new `dispatch.go`):
  - An `Executor` interface with the four methods of `deploy.Executor`: `Deploy`, `SwitchRelease`, `Rollback` and `RunPreDeploy`, each `(ctx, requestID string, msg) *agentv1.CommandResult`. `ConnectOptions.Executor` holds it. When it is nil, `Connect` returns an error that names the option, before dialling. `internal/agent` does not import the Docker client.
  - The session reads frames for its whole life. A `HEARTBEAT_ACK` answers the waiting Heartbeat as before. A `DEPLOY`, `SWITCH_RELEASE`, `ROLLBACK` or `RUN_PRE_DEPLOY` envelope is opened into its message (`protocol.Open`) and handed to the dispatcher. These close the connection and reconnect through backoff, as before: every other type (including `BUILD`, `STOP_APP`, `REMOVE_APP`, `UPDATE_OFFER`, `COMMAND_RESULT` and `HEARTBEAT`), a payload that does not open, and every bad frame of "Bad frames".
  - The dispatcher lives for the whole `Connect` call, not for one session. It keys commands by the message's `app_id`. One app's commands run one at a time in arrival order, and different apps run concurrently. A request id that is already queued or running is ignored: it is not queued, not started and gets no second result. Commands run under `Connect`'s context, so a dropped connection never cancels a running command.
  - When a command returns, its `CommandResult` is wrapped as `COMMAND_RESULT` with the command's request id and written to the connection that is live at that moment. With no live connection it is not sent; the stored record answers the re-send (rule 2, through W2-10a's stored-result path in the executor). A failed write ends that session, which reconnects.
  - `Connect` returns only after every command it started has returned.
- `cmd/moonglass` (`main.go`):
  - `agent connect` gains `--policy FILE`, default `/etc/moonglass/agent.toml`. An empty value prints the usage and exits 2, before anything is opened.
  - After the Engine opens, and before the state database, the proxy or the connection, it calls `deploy.PolicyEnv` and `policy.LoadFile(file, env, 0)`. If either fails, it prints `moonglass: <error>`, closes the Engine and exits 1 without dialling.
  - It builds `deploy.New(engine, policy, db, proxy)` over the one `deploy.Proxy`, runs `Executor.Run(runCtx, report)` beside `Proxy.Run` and passes the executor in `agent.ConnectOptions.Executor`. It closes the database and the Engine only after `Connect`, `Proxy.Run` and `Executor.Run` have all returned.
- `internal/registry` (`routes.go`): the `agent connect` synopsis in `registry.LocalCommands` becomes `agent connect [--data-dir DIR] [--policy FILE] [--proxy-socket PATH] [--tls-issuer ISSUER] --url URL`. Nothing else in the file changes.
- Test edits the owner allowed (2026-11-20, `docs/pipeline/children/build.md`):
  - `internal/registry/routes_test.go`: the expected synopsis in `TestAgentConnectSynopsisNamesProxyFlags` becomes the one above.
  - `internal/agent/connect_test.go`: each `ConnectOptions` gets an idle fake `Executor`. No assertion changes.
  - `cmd/moonglass/connect_test.go`: `TestAgentConnectRunsProxyPush` is isolated from other managed containers on the Engine. Its `DOCKER_HOST` points at a proxy that answers `GET /v*/containers/json` with `[]` and forwards everything else. No assertion changes.
  - `internal/agent/dispatch_test.go` and `resend_test.go` hold the new `internal/agent` tests. `.golangci.yml` already exempts them from `exhaustive`.
- `docs/specs/connection.md`: in "Agent", say these four things. A request id that is queued, not only one that is running, is not queued again. Commands run under the agent's lifetime, not the connection's. A nil executor is refused. An empty `--policy` exits 2. Mark the W2-10b items as built.

## Acceptance criteria

- `TestResentCommandReturnsStoredResult` (real Engine, a fake control plane in the test):
  - The control plane sends a `DEPLOY` of an imported `moonglass.local/<test project>/web:<release>` image and receives its `COMMAND_RESULT`. It then drops the connection, accepts the agent's reconnect and re-sends the identical envelope.
  - The second `COMMAND_RESULT` has the same request id and is proto-equal to the first, and the Engine saw exactly one `POST /containers/create`.
  - The test does not import the Docker client (ADR-0014 decision 2). It imports the image, counts creates and removes its labelled containers, networks and images through the Engine HTTP API over its Unix socket, with the standard library only. One way to do this is a counting Unix-socket proxy in front of the Engine named by `DOCKER_HOST`.
  - It builds the executor with `deploy.New` and never calls `Executor.Run`.
  - It skips with no Engine, except under `CI`, where it fails.
- `TestCommandsForOneAppRunInArrivalOrder`: three commands for one app, sent back to back, reach a fake executor one at a time, never overlapping, in the order sent. Each gets its own `COMMAND_RESULT`.
- `TestCommandsForDifferentAppsRunConcurrently`: a command for app B runs and is answered while a command for app A is still blocked in the fake executor.
- `TestRunningRequestIDIsNotStartedTwice`:
  - A command blocked in the fake executor is re-sent with the same request id on a new connection after the first connection is dropped. The executor is called once for that id, and exactly one `COMMAND_RESULT` for it arrives, on the connection that is live when it finishes.
  - A re-send of a command that is still queued behind another command for the same app is also not run twice.
- `TestAgentClosesOnMessageItDoesNotAccept`: a table over `BUILD`, `STOP_APP`, `REMOVE_APP`, `UPDATE_OFFER`, `COMMAND_RESULT`, `HEARTBEAT`, and a `DEPLOY` whose payload does not open. For each, the agent closes the connection and reconnects, and the fake executor is never called.
- `TestHeartbeatsContinueWhileCommandRuns`: while a command is blocked in the fake executor, Heartbeats keep arriving on the interval and their acks keep the connection open.
- `TestPolicyEnvReadsEngine` (real Engine):
  - `DockerRoot` and `DefaultRuntime` equal what the Engine reports, and the three fixed path fields hold the values in Scope.
  - `ContainerProject` returns the label and true for a test container labelled `dev.moonglass.project=<test project>`. It returns `"", false` for an unlabelled container and for an id the Engine does not have.
- `TestAgentConnectPolicyFlagDefault`: `parseAgentConnect` without `--policy` yields `/etc/moonglass/agent.toml`, `--policy F` yields `F`, and `--policy ""` is refused.
- `TestAgentConnectRefusesPolicyThatDoesNotLoad` (real Engine): a `--policy` file with mode 0666, and one with invalid TOML, each exit 1 with the `policy.LoadFile` error on stderr. No `agent.db` appears in the data directory, and the fake control plane sees no connection.
- `TestAgentConnectSynopsisNamesPolicyFlag`: the `agent connect` synopsis in `registry.LocalCommands` is exactly the string in Scope.
- The existing tests in `internal/agent`, `cmd/moonglass` and `internal/registry` stay green, changed only as the owner-allowed edits in Scope say.
- `internal/agent` and `cmd/moonglass` import neither `github.com/moby/moby/client` nor `github.com/moby/moby/api`, in code or in tests.
- An absent `--policy` file is the empty policy and the command runs: `TestAgentConnectRunsProxyPush` keeps passing with no file at the default path.
- `make ci` is green, `testdata/tests.txt` is updated with `make test-list`, and `scripts/verify check W2-10b` passes.

## Security notes

- §3 B3: the agent accepts only `HEARTBEAT_ACK` and the four command types. Every other type, a payload that fails `protocol.Open`, and every bad frame closes the connection. No message carries a shell string, and each opened message reaches only its own typed executor method.
- §9 checklist, "Can a re-sent command run twice?": a queued or running request id is never started again, and a finished one is answered from the stored record (rules 1–3). `TestResentCommandReturnsStoredResult` proves this against a real Engine.
- §6 and the `agent.toml` rule in `AGENTS.md`: the policy is loaded only from the local file, which must be owned by uid 0 and not group- or world-writable (`policy.LoadFile`), before anything is dialled. The control plane cannot change it. A file that does not load stops the agent. `policy.Env` comes from the local Engine, and an unknown container is cross-project.
- ADR-0014 decision 2: only `internal/deploy` touches the Docker client. `internal/agent` and `cmd/moonglass` reach it only through `deploy.PolicyEnv` and `deploy.New`.
- §8: results and errors are logged without secrets from request payloads. The `CommandResult` detail is the executor's, already truncated to 4096 bytes.
