# Plan for W7-6d

## What changed since the needs-human round

The owner approved every number and name on 2026-11-19. They are recorded in `docs/specs/protocol.md` "Update messages (W7-6d)" (commit eb85a71), and the `MessageType` list sentence already names both types. Nothing else needs a human: no new module (only `fmt`, `strings`, `slices` from the standard library), no ADR, no rule the specs leave open. The approved numbers are:

- `MessageType`: `UPDATE_OFFER = 17`, `UPDATE_REPORT = 18`.
- `UpdateOffer { string version = 1; }`
- `UpdateReport { string version = 1; string sha256 = 2; UpdateOutcome outcome = 3; UpdateReason reason = 4; bool proxy_restarted = 5; }`
- `Heartbeat.update_channel = 4` (`string`).
- `UpdateOutcome`: `UPDATE_OUTCOME_UNSPECIFIED = 0`, then `_REJECTED` 1, `_VERIFY_FAILED` 2, `_SWITCHING` 3, `_PASSED` 4, `_REVERTED` 5, `_CHECK_FAILED` 6.
- `UpdateReason`: `UPDATE_REASON_UNSPECIFIED = 0`, then `_NOT_NEWER` 1 … `_DEADLINE` 17, in the ticket's order.

- `internal/protocol/update.go` (new):
  - `const sha256HexLen = 64` and `const maxQuotedLen = 64`.
  - `func quoteOrLen(s string) string` returns `%q` of `s` up to `maxQuotedLen` bytes, and otherwise `"<n> bytes"`. Every error stays bounded.
  - `func validateReleaseVersion(field, s string) error`:
    - `strings.CutPrefix(s, "v")` must succeed.
    - `strings.Split(rest, ".")` must give exactly 3 parts.
    - Each part is non-empty and contains only bytes `'0'`–`'9'`, checked byte by byte. It has no leading `'0'` unless it is exactly `"0"`.
    - It never parses the parts to integers.
    - The error is `fmt.Errorf("%s %s, expected vMAJOR.MINOR.PATCH: %w", field, quoteOrLen(s), ErrMalformed)`.
  - `func validateUpdateOffer(m *agentv1.UpdateOffer) error` calls `validateReleaseVersion("version", m.GetVersion())`.
  - `func updateReasons(o agentv1.UpdateOutcome) []agentv1.UpdateReason` is one switch over the six outcomes, returning the ticket's binding (`SWITCHING` and `PASSED` return `{UPDATE_REASON_UNSPECIFIED}`). Any other outcome returns nil.
  - `func validateUpdateReport(m *agentv1.UpdateReport) error` runs these checks in order. The first one that fails returns:
    1. `version`: `validateReleaseVersion`.
    2. `outcome`: `updateReasons(o) == nil` gives `"outcome %d, expected one of REJECTED, VERIFY_FAILED, SWITCHING, PASSED, REVERTED, CHECK_FAILED"`. This covers both `UNSPECIFIED` and unknown numbers.
    3. `reason`: when `agentv1.UpdateReason_name[int32(r)]` is missing, the error is `"reason %d unknown"`.
    4. `reason`: `!slices.Contains(updateReasons(o), r)` gives `"reason %v with outcome %v, expected one of %v"`.
    5. `sha256` with `REJECTED`: it must be empty, otherwise `"sha256 must be empty with outcome REJECTED, got %d bytes"`.
    6. `sha256` with any other outcome: `len == sha256HexLen && strings.Trim(s, hexChars) == ""` (reusing `hexChars` from `deploy.go`), otherwise `"sha256 %s, expected 64 lowercase hex characters"` with `quoteOrLen`.
    7. `proxy_restarted`: true with `REJECTED` or `VERIFY_FAILED` gives `"proxy_restarted true with outcome %v, expected false"`.
    - Every error wraps `ErrMalformed` and starts with the field name.
- `internal/protocol/heartbeat.go`:

  - `func validateUpdateChannel(s string) error` is a switch: `""`, `"STABLE"` and `"CANARY"` return nil. Anything else gives `fmt.Errorf("update_channel %s, expected empty, STABLE or CANARY: %w", quoteOrLen(s), ErrMalformed)`.

## Tests to write

All tests go in `internal/protocol/update_test.go`. They are table-driven and use `t.Parallel()`. Each reject case checks `errors.Is(err, ErrMalformed)` and that `err.Error()` contains the field name, and its failure message shows the input, the expected result and the actual result.

The tests use a local helper `openUpdate(t, typ, payloadMsg, out)`. It builds the envelope by hand as `&agentv1.Envelope{Version, Type, RequestId: "u…", Payload: proto.Marshal(msg)}`, then runs `Marshal`, `Unmarshal` and `Open`. Hand-building is needed for reject cases, because `Wrap` does not validate payloads.

## Edge cases

- **A numeric identifier wider than uint64.** Nothing parses it to an integer (`TestUpdateOfferRoundTrip`).
- **Non-ASCII digit, NUL, whitespace, newline, `/`, `:`, `-`, `+`.** The byte check rejects all of them (`TestUpdateOfferRejectsInvalid`, fuzz).
- **Empty parts** (`v1..3`, `v.1.2`, `v1.2.`) and wrong part counts (`v1.2`, `v1.2.3.4`) are rejected (`TestUpdateOfferRejectsInvalid`).
- **Enum numbers outside the descriptor**, up to `MaxInt32`: they are rejected by the outcome switch or the `UpdateReason_name` lookup, and nothing indexes by them (`TestUpdateReportRejectsInvalid`, fuzz).
- **Negative enum numbers**, which fuzz input can produce: the outcome switch rejects them, and so does the `_name` lookup (fuzz).
- **Hostile long strings in errors.** `quoteOrLen` caps what is echoed (the 1 KiB `update_channel` case, the oversize version).
- **Unknown fields, wrong type, and `error` on a non-`ERROR` type.** The existing `rejectUnknown`, `typeOf` and `validate` handle these once the two types are known (`TestUpdateMessagesProtocolAbuse`).
- **Oversize.** The existing `frameBody` and `Unmarshal` size checks reject it before parsing (`TestUpdateMessagesProtocolAbuse`).
- **Lowercase channel names** (`stable`, `Stable`): rejected byte for byte (`TestHeartbeatUpdateChannel`).

## Risks

- **Enum name collisions break `protoc`.** Every value has its prefix, so none can collide. `make proto-check` confirms the generated file is current.
- **`max_diff_lines: 260`.** Hand-written, non-test lines are about 40 in the `.proto`, 10 in `envelope.go`, about 100 in `update.go`, about 12 in `heartbeat.go` and about 15 in the spec. That leaves headroom if the generated `.pb.go` is excluded, as in earlier protocol tickets. The validators stay plain switches.
- **The reason binding is written twice, in the code and in the test.** This is deliberate: the test's own table catches a wrong binding in the code.
- **Existing tests use unknown type numbers `15` and `99`.** `15` is the varint tag in a hand-built error body, not a type, and `99` stays unknown. No existing test line changes.
- **Banned words.** No "fallback", "legacy", "TODO" and so on in comments in `update.go` or `heartbeat.go`.
- **Lint.** A `gosec` G115 warning on `int32(r)` is avoided because `UpdateReason` is already `int32`. The `errorlint` and `%w` patterns match the existing validators.
- **Scope creep.** Message direction, the `u` request-id shape, the command-class table and setting `update_channel` from `agent.toml` all stay out (W7-6e and W7-6f).
