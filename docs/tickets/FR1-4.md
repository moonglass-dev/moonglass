# agent.toml load fails closed

`policy.LoadFile` refuses a file whose owner uid cannot be read, checks mode and owner once each, drops the unused `Uid()` assertion and wraps every error with the path (R-1 finding 4). Today `internal/policy/parse.go` skips the owner check when the uid cannot be read, so an `agent.toml` written by the service user could load on such a platform, against `docs/threat-model.md` §6 ("The file is owned by root and is not writable by the service user"). After this ticket the checks of `docs/specs/container-policy.md` "The file" run exactly once each, any check that cannot be made refuses the file, and every error names the file.

## Scope

- `internal/policy/parse.go`:
  - The checks on the stat result move into one unexported function, `checkAgentTOML(file string, fi fs.FileInfo, owner int) error`, which `LoadFile` calls with the result of `os.Lstat`. It checks, once each and in this order: symlink, regular file, mode, owner.
  - Mode: one check. A file whose permission bits have group or other write (`0o022`) set, or lack owner read (`0o400`), is refused with an error containing `chmod` and the mode in octal. This keeps today's accepted and refused modes.
  - Owner: one check, through `statUID`. When the uid cannot be read the file is refused with an error containing `owner`; there is no path that loads without the owner comparison. A uid other than `owner` is refused with an error containing `chown`, the uid and the wanted uid.
  - Delete the `interface{ Uid() uint32 }` assertion, the `_ = ok` line, the unreachable second mode and readability checks, and the `fileUID` wrapper (callers use `statUID` directly).
  - Every error `LoadFile` returns contains the path: the `os.Lstat` error (other than not-exist, which stays the empty configuration), the open and read errors, and the `Parse` error. Errors from the standard library are wrapped with `%w`.
- `internal/policy/stat_unix.go`: `statUID` stays the one way to read the uid; only changes needed by the removal of `fileUID`.
- `docs/specs/container-policy.md`, "The file": state that a file whose owner cannot be read is refused, that the file must be readable by its owner, and that every load error names the path.

## Acceptance criteria

- `TestCheckAgentTOMLRefusesUnknownOwner`: `checkAgentTOML` given a regular `fs.FileInfo` with mode `0o600` whose `Sys()` is `nil`, and one whose `Sys()` is a type other than `*syscall.Stat_t`, returns an error containing the path and `owner`, for any `owner` value including the uid that would otherwise match.
- `TestCheckAgentTOMLMode`: table over fake regular `fs.FileInfo` values owned by `owner`: modes `0o600`, `0o400`, `0o640`, `0o644` return nil; modes `0o620`, `0o602`, `0o622`, `0o666`, `0o200`, `0o000`, `0o004`, `0o044` return an error containing the path and `chmod`. No case is skipped when the test runs as root.
- `TestCheckAgentTOMLOwner`: a fake regular `0o600` file with uid `owner` returns nil; with uid `owner+1` returns an error containing the path, `chown`, both uids.
- `TestCheckAgentTOMLFileType`: a fake symlink returns an error containing the path and `symlink`; a fake directory and a fake named pipe return an error containing the path and `not a regular file`.
- `TestLoadFileErrorsNamePath`: table over real files under `t.TempDir()`: a path whose parent is a regular file (`errors.Is(err, syscall.ENOTDIR)` holds), a symlink, a directory, a `0o620` file, a file with the wrong owner, a file with invalid TOML, and a file with an unknown key; every error is non-nil and contains the path. An absent file still loads as the empty configuration.
- `TestLoadFileLoadsSafeFile`: real `0o600`, `0o400` and `0o644` files owned by the current uid, holding `[update] channel = "stable"` and one `[sources] registries` pattern, load with `Config()` equal to the parsed values.
- `internal/policy/parse.go` contains no `Uid()` method assertion, no `_ = ok`, no `fileUID`, and exactly one mode comparison and one owner comparison in `checkAgentTOML`.
- The existing `TestLoadFileAbsentIsEmptyConfig` and `TestLoadFileRejectsUnsafeFile` pass unchanged.
- `docs/specs/container-policy.md` "The file" states the unknown-owner refusal, owner readability and the path in every error.
- `make ci` is green.

## Security notes

- `docs/threat-model.md` §6: the file is owned by root and not writable by the service user. Every check that cannot be made refuses the file; the owner comparison can never be skipped. Group or other write is always refused.
- §7 trusted core: `internal/policy` is `risk: high`; the change removes code paths and adds no new way to load a configuration. `Parse` and `LoadFile` stay the only constructors.
- §9 checklist: no unused branch or result remains in `LoadFile`; errors name the file and say whether to fix `chmod` or `chown`, and never print file contents.
