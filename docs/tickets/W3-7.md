# Protocol: builds and server reports

The control plane gains a typed command to build a GitHub commit on a server, the `Build` message under the new type `BUILD` = 11, and the agent's `Heartbeat` gains two server reports: an optional `DiskReport` (absent means not measured) and the server's SSH deploy public key `deploy_key`. `internal/protocol` validates every new field when a payload is opened, fully validates a disk report whenever one is present, rejects unknown fields at every nesting level including inside `DiskReport`, and has protocol-abuse tests and a fuzz target for each new parser. This implements the section "Builds and server reports (W3-7)" of `docs/specs/protocol.md` (owner decisions D16, D17, D25).

## Scope

- `proto/moonglass/agent/v1/agent.proto`:
  - `MessageType` gains `BUILD = 11`. `COMMAND_RESULT` stays 10.
  - New `Build`: `app_id = 1`, `release_id = 2`, `project = 3`, `environment = 4`, `service = 5`, `repository = 6`, `commit = 7` (all `string`), with a comment saying `repository` and `commit` are validated fields from which the agent builds the clone URL itself, never a URL, git option or shell string.
  - `Heartbeat` keeps `agent_version = 1` and gains `disk = 2` (`DiskReport`, optional message) and `deploy_key = 3` (`string`).
  - New `DiskReport`: `data_root_free_bytes = 1`, `data_root_total_bytes = 2`, `agent_dir_free_bytes = 3`, `agent_dir_total_bytes = 4` (`uint64`), `level = 5` (`DiskLevel`).
  - New `DiskLevel` enum: `DISK_LEVEL_UNSPECIFIED = 0`, `OK = 1`, `LOW = 2`, `CRITICAL = 3`. Zero rejected.
- `internal/protocol/agentv1/agent.pb.go`: regenerated with `make proto`, never edited by hand.
- `internal/protocol`:
  - `validateType` and `typeOf` know `BUILD` and `*agentv1.Build`; `validatePayload` validates `Build` and `Heartbeat`.
  - New validators: `validateBuild` (reusing `validateID` and `validateName` from `deploy.go`), repository, commit, `validateHeartbeat`, disk report, deploy key. Every failure wraps `ErrMalformed` with the field, the expected form and the actual value or length.
  - `Open` already rejects unknown fields on nested messages through `rejectUnknown`; that now covers `DiskReport` inside `Heartbeat`.
  - `TestDeployMessagesRejectUnknownType` in `deploy_test.go` uses `11` as an unknown type, which becomes `BUILD`. Its list `{UNSPECIFIED, 11, 99}` changes `11` to a number that stays unknown (`15`), keeping every assertion. This edits an existing test line, so it needs an owner allowance like the one recorded for W2-8 (commit f6d1b35); no other existing test line changes.
- `docs/specs/protocol.md`: add `BUILD` to the `MessageType` list; record the `DiskLevel` zero value, that `free ≤ total` holds for each filesystem pair and nothing else relates the numbers to `level`, and the exact `deploy_key` shape below.

Validation rules, as in `docs/specs/protocol.md`:

- **`Build.app_id`, `Build.release_id`**: the W2-2 identifier rule (1 to 64 bytes of `[A-Za-z0-9._-]`).
- **`Build.project`, `environment`, `service`**: the W2-8 name rule (1 to 63 bytes of `[a-z0-9-]`, first and last byte a letter or digit).
- **`Build.repository`**: exactly one `/`, splitting `<owner>/<repo>`. `owner` is 1 to 39 bytes of `[A-Za-z0-9-]`, not starting with `-`. `repo` is 1 to 100 bytes of `[A-Za-z0-9._-]`, not `.` or `..`, not starting with `-` or `.`. So no scheme, host, `:`, `@`, extra path segment or whitespace can reach the clone URL.
- **`Build.commit`**: exactly 40 characters of `[0-9a-f]`.
- **`Heartbeat.disk`**: absent is valid. When present: `data_root_free_bytes ≤ data_root_total_bytes`, `agent_dir_free_bytes ≤ agent_dir_total_bytes`, and `level` is `OK`, `LOW` or `CRITICAL`; `UNSPECIFIED` and unknown numbers are rejected. Zero totals are allowed when the matching free value is also zero.
- **`Heartbeat.deploy_key`**: empty, or at most 256 bytes of the form `ssh-ed25519 <b64> moonglass-deploy` with exactly those two single spaces, where `<b64>` is non-empty, padded standard base64 (RFC 4648 §4) that decodes with `base64.StdEncoding.Strict()`. No newline, no other key type, no other comment.
- **`Heartbeat.agent_version`**: unchanged (no rule).

## Acceptance criteria

- `TestBuildRoundTrip`: a `Build` with every field set round-trips through `Wrap`, `Marshal`, `Unmarshal` and `Open` under `BUILD` and is `proto.Equal` to the input, including boundaries: a 64-byte `app_id` and `release_id`, 63-byte and 1-byte names, a 39-byte owner, a 100-byte repo, single-character owner and repo, a repo containing `.`, `_` and `-` after its first byte (`a.b_c-d`), an owner containing `-` after its first byte, and an all-digit commit.
- `TestBuildRejectsInvalid`: `Open` rejects with `ErrMalformed`, and the error names the field: a bad `app_id` and `release_id` (empty, 65 bytes, a `/`); each of `project`, `environment`, `service` empty, 64 bytes, uppercase, with `_` or a leading `-`; `repository` empty, with no `/`, with two `/`, with an empty owner or repo, owner of 40 bytes, owner starting with `-`, owner with `_` or `.`, repo of 101 bytes, repo `.` or `..`, repo starting with `.` or `-`, containing `:`, `@`, a space, NUL or a non-ASCII byte, `https://github.com/a/b`, `github.com/a/b`, `git@github.com:a/b`; `commit` empty, 39 or 41 characters, uppercase hex, a non-hex letter, a branch name (`main`) and a 40-byte string with a leading `-`.
- `TestBuildProtocolAbuse`: unknown fields appended to a `Build` payload are rejected with `ErrMalformed`; a `BUILD` envelope opened as `Deploy`, and a `DEPLOY` envelope opened as `Build`, fail with `ErrTypeMismatch`; `Wrap(BUILD, …, &Deploy{})` and `Wrap(DEPLOY, …, &Build{})` fail with `ErrTypeMismatch`; a `BUILD` envelope carrying `error` is rejected by `Marshal` and `Unmarshal`; `Build` has no string field whose name looks like a host command (`assertNoShellStringFields`).
- `TestHeartbeatReportsRoundTrip`: a `Heartbeat` with neither `disk` nor `deploy_key`; with a `DiskReport` at each level; with free equal to total, both zero, and `math.MaxUint64` free and total; with a valid `deploy_key` produced from a 32-byte Ed25519 public key in OpenSSH wire format; and with a `deploy_key` of 253 bytes, the longest valid line (224 base64 characters; a valid line of exactly 256 bytes cannot exist, because the fixed 29 bytes leave 227 and padded base64 is a multiple of 4), each round-trip under `HEARTBEAT` and are `proto.Equal` to the input. An absent `disk` stays absent after the round trip (`GetDisk() == nil`).
- `TestHeartbeatRejectsBadDiskReport`: `Open` rejects with `ErrMalformed`, naming the field: `data_root_free_bytes` one above `data_root_total_bytes`; `agent_dir_free_bytes` one above `agent_dir_total_bytes`; free non-zero with total zero for each pair; `level` `UNSPECIFIED`; `level` an unknown number (4 and 2^31-1); a present but empty `DiskReport{}` (level unspecified).
- `TestHeartbeatRejectsBadDeployKey`: `Open` rejects with `ErrMalformed`: 257 bytes of otherwise valid shape; `ssh-rsa` prefix; no comment; comment other than `moonglass-deploy`; two spaces between parts; a trailing newline; a leading space; empty base64; base64 with a character outside the standard alphabet (`-` or `_`); unpadded base64 whose length is not a multiple of 4; base64 with non-zero padding bits; a NUL byte.
- `TestHeartbeatReportsProtocolAbuse`: unknown fields appended to a `Heartbeat` payload, and unknown fields inside its nested `DiskReport`, are rejected with `ErrMalformed`; a `HEARTBEAT` envelope opened as `Build` and a `BUILD` envelope opened as `Heartbeat` fail with `ErrTypeMismatch`; `Heartbeat` and `DiskReport` have no string field that looks like a host command.
- `FuzzOpenBuild`: arbitrary payload bytes in a `BUILD` envelope, seeded with a valid `Build` and boundary cases; `Open` never panics; any payload it accepts passes the rules above, re-wraps, opens again and is `proto.Equal` to the first result.
- `FuzzOpenHeartbeat`: the same for `HEARTBEAT` and `Heartbeat`, seeded with a heartbeat without reports, one with a valid disk report and deploy key, and one with unknown fields inside `DiskReport`; any accepted payload has either no `disk` or a `disk` with free ≤ total for both pairs and a known level.
- Every existing test in `internal/protocol` still passes with its assertions intact; `TestHeartbeatRoundTrip` passes unchanged (a heartbeat without the new fields stays valid); `TestEnvelopeRoundTripEveryType` covers `BUILD` through the descriptor. The only edited existing line is the unknown-type list in `TestDeployMessagesRejectUnknownType`, as above.
- `make proto-check` is clean: `agent.pb.go` matches `make proto` output.
- No new field is a host shell command, a host command line, a host path or a URL. No new dependency; `go.mod` and `go.sum` are unchanged (`encoding/base64` is standard library).

## Out of scope

- Generating the deploy key, sending it in every `Heartbeat`, storing it on the server row, `moonglass servers deploy-key`: W3-8. Checking that the base64 decodes to a well-formed Ed25519 SSH wire key belongs with the key code in `internal/keys` (W3-8); this ticket checks the line's shape only.
- Cloning, building, the identity binding for `Build`, the per-server build queue, the concurrent-`BUILD` rejection, the image tag and `CommandResult` for `BUILD`: W3-4.
- Sending `BUILD` and accepting it per side (direction rules): W3-4 with `docs/specs/connection.md`.
- Measuring disk, computing the level with its hysteresis, sending the report in every heartbeat, and refusals: W3-6. The protocol does not check `level` against the byte counts, because hysteresis makes the level not derivable from one sample.
- `LOG_REQUEST`, `LOG_CHUNK`, `USAGE`: W4-4.

## Security notes

- `docs/threat-model.md` §3 B3: the agent treats the control plane as hostile. `Build.repository` and `commit` are the only text from a message that reaches `git`; they are restricted to alphabets with no `:`, `@`, whitespace, leading `-` or extra `/`, so the URL the agent builds (`git@github.com:<owner>/<repo>.git`) cannot change host or transport and nothing becomes a git option. `commit` is hex only, so no branch, tag or option name passes. All checks run when the payload is opened, before later code acts.
- §9.1: this ticket changes the `.proto` contract and needs owner approval before the plan step proceeds: `BUILD = 11`; `Build` app_id=1, release_id=2, project=3, environment=4, service=5, repository=6, commit=7; `Heartbeat` disk=2, deploy_key=3; `DiskReport` data_root_free_bytes=1, data_root_total_bytes=2, agent_dir_free_bytes=3, agent_dir_total_bytes=4, level=5; `DiskLevel` UNSPECIFIED=0, OK=1, LOW=2, CRITICAL=3, zero rejected. It also needs the owner to allow the one edit to an existing test line in `internal/protocol/deploy_test.go` (`11` → `15` in `TestDeployMessagesRejectUnknownType`), recorded in the pipeline prompts as for W2-8. There is a protocol-abuse test and a fuzz target for each new parser.
- §2 and §9.3: `deploy_key` is a public key, not a secret; the private key never leaves the server (`docs/specs/build.md`). The protocol accepts only the public OpenSSH line shape, so a private key block (multi-line, `-----BEGIN`) cannot travel in this field.
- §8 "local policy beats remote command": `project`, `environment` and `service` in `Build` only select `agent.toml` blocks; they grant nothing, and the binding rule that stops a control plane moving an app between projects is W3-4's to enforce.
