# Compose plan

`internal/compose` decides what an import will do before anything is applied: the hash of each service's settings, the create, update, unchanged and remove list against the environment's services, the apply order by `depends_on`, the environment secrets to set, and the refusals that stop an import (`docs/specs/compose.md`, "Mapping", "Environment values", "Change detection", "The list", "Apply"). It is a pure library: it makes no network call and reads no file. Owner decision of 2026-11-19.

## Scope

- `internal/compose` (new package):
  - `Hash(svc policy.ComposeService, domains []string) string`: SHA-256 hex of the canonical JSON of "Change detection", byte for byte.
  - `Plan(services []policy.ComposeService, existing []Existing, secrets []string, opts Options) (Plan, error)`: `Existing` is a service of the environment as `services.list` gives it (name, `compose_hash`); `secrets` the names `secrets.list` gives; `Options` holds the domains per service and the `--update` names. It returns the actions in apply order (creates and updates in `depends_on` order, ties by name; then removals by name) with each one's settings and hash, and the secrets to set with whether each replaces one.
  - The refusals of "Mapping", "Environment values" and "The list", each one error that names the services, all found together. A value is never in an error.
  - `(Plan).Text() string`: the list exactly as "The list" shows it, including `(not published)` for a port and `nothing to apply` for an empty plan.
- `docs/specs/compose.md`: already says this; change it only if the built behaviour needs a wording fix.

## Acceptance criteria

- `TestServiceHashIsCanonical`: the hash of a fixed service equals a golden value written in the test; reordering labels, domains or volumes in the input gives the same hash; changing any one setting changes it.
- `TestServiceHashIgnoresEnvironmentAndDependsOn`: changing environment names, environment values or `depends_on` leaves the hash unchanged.
- `TestPlanMarksCreateUpdateUnchangedRemove`: against existing services with hashes, each file service is `create`, `update` or `unchanged` as specified, a compose-managed service missing from the file is `remove`, a service named in `--update` is `update`, and a non-compose service absent from the file is not touched.
- `TestPlanRefusesServiceNotFromCompose`: a file service whose name exists with an empty `compose_hash` is refused with the exact message.
- `TestPlanRefusesChangedVolumeService`: a changed service that mounts a named volume, and an unchanged one named in `--update`, are refused with the exact message; a new service with a volume is a `create`.
- `TestPlanRefusesConflictingEnvironmentValues`: two services giving `PORT` different values are refused with the exact message, which holds neither value; equal values are one secret.
- `TestApplyOrderFollowsDependsOn`: a service comes after everything it depends on; independent services are in name order; removals come last, by name.
- `TestPlanListText`: `Text()` for a plan with every kind of line equals the expected text exactly.
- `make ci` is green and `scripts/verify check W6-4c` passes.

## Out of scope

- W6-4a: resolving the files. W6-4: calling the operations, the confirmation and the flags. W6-4b: storing the hash.

## Security notes

- `docs/threat-model.md` §9.3: environment values are compared in memory only and never appear in a refusal, the list or the hash.
- The plan is advice to the operator; authorisation stays with each operation the CLI calls (`docs/specs/compose.md`, "The list").
