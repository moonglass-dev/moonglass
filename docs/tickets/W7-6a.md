# Release signature verifier

The agent must verify a release artifact's `.sig` before it installs anything, in the same format the install script checks with `ssh-keygen -Y verify`, using the Go standard library only (ADR-0007 decision 1). After this ticket, `internal/update` has a verifier for OpenSSH `SSHSIG` signatures made by an `sk-ssh-ed25519@openssh.com` key: it checks the preamble, version 1, that the signing key is one of the pinned keys it is given, the namespace `moonglass-release`, the hash `sha512`, and the Ed25519 signature over the application hash, flags, counter and message hash, and it requires the flags to be exactly user-presence (0x01) and user-verification (0x04). Nothing calls it yet; W7-6e does.

## Scope

New package `internal/update`, standard library only (`crypto/ed25519`, `crypto/sha256`, `crypto/sha512`, `encoding/base64`, `encoding/binary`, `bytes`, `errors`, `fmt`, `io`, `strings`):

- `ParseSigner(line string) (Signer, error)`: parses one pinned key in exactly the `allowed_signers` form of `docs/specs/install.md`, "Pinned keys":
  `moonglass-release namespaces="moonglass-release" sk-ssh-ed25519@openssh.com <base64 key blob>`
  Four space-separated fields, nothing else: principal `moonglass-release`, option `namespaces="moonglass-release"`, key type `sk-ssh-ed25519@openssh.com`, and standard base64 of the key blob. No comment, no other option, no other key type. The key blob must decode as below, with its type string equal to the line's key type.
- `Verify(message io.Reader, armored []byte, pinned []Signer) error`: returns nil only when every check below holds. The message is hashed while streaming, so a large binary is never held in memory.
- `var ErrBadSignature`: every rejection from `Verify` and `ParseSigner` wraps it, and its message names the check that failed (for example `update: signature namespace is "x", want "moonglass-release": …`).

### Wire format (OpenSSH `PROTOCOL.sshsig` and `PROTOCOL.u2f`)

`string` is a big-endian `uint32` length followed by that many bytes; `uint32` is big-endian.

- **Armor.** The line `-----BEGIN SSH SIGNATURE-----`, then standard base64 (padded) in one or more lines, then `-----END SSH SIGNATURE-----`, with an optional single trailing newline. Lines end in `\n`. Anything before BEGIN, after END, or any non-base64 byte between them is rejected.
- **Signature blob**, in order, with no bytes left over:
  - `byte[6]` `SSHSIG`
  - `uint32` version, must be 1
  - `string` public key blob
  - `string` namespace, must be `moonglass-release`
  - `string` reserved, must be empty
  - `string` hash algorithm, must be `sha512`
  - `string` signature
- **Public key blob**, no bytes left over: `string` `sk-ssh-ed25519@openssh.com`, `string` Ed25519 public key (exactly 32 bytes), `string` application. The whole blob must equal, byte for byte, the blob of one of the `pinned` signers; the application is whatever that pinned key holds.
- **Inner signature**, no bytes left over: `string` `sk-ssh-ed25519@openssh.com`, `string` Ed25519 signature (exactly 64 bytes), `byte` flags, `uint32` counter.
- **Flags** must equal `0x05` (0x01 user presence and 0x04 user verification, and no other bit). The counter is any value; it is not checked against anything.
- **Signed data.** `data = "SSHSIG" || string(namespace) || string(reserved) || string("sha512") || string(SHA-512(message))`. The Ed25519 signature must verify, under the pinned key, over `SHA-256(application) || flags || uint32(counter) || SHA-256(data)`.

Every length is checked against the bytes remaining before anything is read or allocated, so a length larger than the input is a rejection, never a panic or a large allocation. The checks run in the order above and the first failure is returned.

Tests build `sk-ssh-ed25519` keys and signatures in Go from throwaway `ed25519.GenerateKey` keys with application `ssh:`, using a test helper that writes the blobs above field by field so each test can change one field. No private key, fixture key or real release key is committed.

## Acceptance criteria

- `TestVerifyAcceptsEitherPinnedKey`: with two pinned signers, a message signed by the first verifies and a message signed by the second verifies; the order of `pinned` does not matter; an armored signature with and without its trailing newline, and with base64 wrapped at 70 columns (as `ssh-keygen` writes it) or on one line, verifies.
- `TestVerifyRejectsUnpinnedKey`: rejected with `ErrBadSignature` when the signing key is not pinned, when `pinned` is empty or nil, and when the key's Ed25519 bytes match a pinned key but its application differs.
- `TestVerifyRejectsWrongEnvelope`: table-driven; each is rejected with `ErrBadSignature` and a message naming the field: preamble not `SSHSIG`; version 0 and 2; namespace `file`, empty and `moonglass-release2`; non-empty reserved; hash `sha256` and `SHA512`; outer key type `ssh-ed25519`; inner signature type differing from `sk-ssh-ed25519@openssh.com`. Each case is otherwise validly signed over its own fields, so only the named check can reject it.
- `TestVerifyRequiresExactFlags`: table-driven, each case validly signed with its flags: `0x05` verifies; `0x00`, `0x01`, `0x04`, `0x07`, `0x25`, `0x45`, `0x85` and `0xFF` are rejected with `ErrBadSignature`.
- `TestVerifyRejectsTamperedSignature`: a valid signature is rejected when the message has one byte changed, one byte appended or is empty; when the flags or counter are changed after signing; when one bit of the Ed25519 signature is flipped; and when the signature was made over `SHA-256` of a different application.
- `TestVerifyRejectsMalformedEncoding`: rejected with `ErrBadSignature`, never a panic: empty input; missing or misspelled BEGIN or END line; text before BEGIN or after END; invalid base64; a blob truncated at every byte offset; one byte appended to the blob; a length prefix larger than the bytes remaining (including `0xFFFFFFFF`); a 31- or 33-byte public key; a 63- or 65-byte signature; trailing bytes inside the key blob or the inner signature.
- `TestParseSignerAcceptsOnlyPinnedForm`: table-driven; the form above parses, and a signer parsed from it verifies a signature from that key. Rejected with `ErrBadSignature`: another principal; a missing or different `namespaces` option; an extra option or a trailing comment; key type `ssh-ed25519` or `sk-ecdsa-sha2-nistp256@openssh.com`; a key blob whose type string differs from the line's; invalid base64; a key blob with trailing bytes or a wrong key length; an `OWNER-PASTE` line; empty input.
- `FuzzParseSignature`: Go fuzzing of the armored-signature parser, seeded with a valid signature and the malformed cases above; arbitrary input never panics, and `Verify` of the input against a fixed pinned signer either returns nil or an error wrapping `ErrBadSignature`.
- The package imports only the standard library and `moonglass.dev/moonglass` packages; `go.mod` and `go.sum` are unchanged.
- No real or stand-in release key is embedded in the package; `Verify` trusts only the `pinned` it is given.
- `make ci` is green and `testdata/tests.txt` lists the new tests.

## Security notes

- `docs/threat-model.md` §2 (release signing keys), §3 (the ninth boundary: nothing is installed or run unless its `.sig` verifies against a pinned key with the 0x01 and 0x04 flags), §7 (release signing and self-update are trusted core), and §9 checklist item 6: the verifier uses only the standard library, requires a pinned key, the namespace, `sha512` and exactly the 0x01 and 0x04 flags, and rejects anything else.
- Checklist item 1 applies to the parser: lengths and types are checked before use, and there is a fuzz target.
- A signature accepted by `Verify` must be one that `ssh-keygen -Y verify -I moonglass-release -n moonglass-release` would also accept against the same `allowed_signers` lines; `Verify` may be stricter (exact flags, empty reserved, no comment), never looser.
- Errors name the failing check but never include the message contents; no key material other than public keys exists in the package or its tests' committed files.
