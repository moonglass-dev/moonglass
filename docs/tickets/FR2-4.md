# depguard boundaries for ADR-0011, ADR-0014 and ADR-0015

Rewrite `age-deps` and `docker-deps` as `$all`-with-exclusion rules (age outside internal/keys; moby outside internal/deploy, internal/build and internal/agent/disk), deny `moonglass.dev/moonglass/internal/proxy` and Caddy in internal/deploy, and delete the stale exclusion comment (R-2 finding 4).

After this ticket, the import boundaries in ADR-0015 decision 2, ADR-0014 decision 2 and `docs/specs/release.md` ("Proxy config") are checked for every Go file in the module, tests included. New packages are covered without editing the rule. `age-deps` and `docker-deps` today list fixed directories, so `internal/deploy`, `internal/update`, `tools/` and every package the plan adds later are not checked.

## Scope

All changes are in `.golangci.yml`, under `linters.settings.depguard.rules`:

- `age-deps`: `list-mode: lax`, `files: ["$all", "!**/internal/keys/**"]`, and the existing deny of `filippo.io/age` (desc: only internal/keys may import age (ADR-0015)). Replace the comment with one in the style of `policy-deps` and `pgx-deps`: age is imported only by internal/keys (ADR-0015 decision 2), and every file outside internal/keys is covered, so new packages are too. Delete the sentence "depguard file exclusions were not applied for policy-deps, so every package that exists today is listed."
- `docker-deps`: `list-mode: lax`, `files: ["$all", "!**/internal/deploy/**", "!**/internal/build/**", "!**/internal/agent/disk/**"]`, and a deny of `github.com/moby/moby` (this prefix covers both `github.com/moby/moby/client` and `github.com/moby/moby/api`). The desc names the three packages and ADR-0014, and drops "today". Add a comment in the same style naming ADR-0014 decision 2.
- A new rule, `deploy-deps`: `list-mode: lax`, `files: ["**/internal/deploy/**"]`, with two denies: `moonglass.dev/moonglass/internal/proxy` (desc: internal/deploy never imports internal/proxy, which links Caddy (docs/specs/release.md, ADR-0011)) and `github.com/caddyserver/caddy/v2` (desc: only internal/proxy may import Caddy (ADR-0011)). The comment cites `docs/specs/release.md` "Proxy config" and ADR-0011.
- Leave `main`, `proxy-deps`, `websocket-deps`, `huma-deps`, `sqlite-deps`, `policy-deps` and `pgx-deps` as they are.

## Acceptance criteria

- `make lint` and `make ci` are green on the merged tree. No Go file changes: the code already respects all three boundaries (only `internal/keys` imports age; only `internal/deploy` imports moby; `internal/deploy` imports neither `internal/proxy` nor Caddy).
- `age-deps` and `docker-deps` each have `"$all"` as their first `files` entry, followed only by the `!` exclusions named in Scope. No fixed directory list remains in either rule.
- `deploy-deps` exists with exactly the two denies named in Scope.
- The phrase "file exclusions were not applied" no longer appears in `.golangci.yml`.
- The reviewer checks that the rules apply, using a scratch file that is not committed: `golangci-lint run` reports depguard for an import of `filippo.io/age` in `internal/deploy`, `internal/update` and `tools/pipeline`; for an import of `github.com/moby/moby/client` in `internal/agent` (outside `disk`), `internal/keys` and a new directory such as `internal/scratch`; and for an import of `moonglass.dev/moonglass/internal/proxy` or Caddy in `internal/deploy`. The worker records the commands and their output in its result file.
- The diff touches only `.golangci.yml` and this ticket's own docs.

## Security notes

- `docs/threat-model.md` §3, boundary B5 (agent → Docker Engine): the Docker client stays confined to the packages ADR-0014 names, so the root-equivalent socket is reached only through code built on `policy.Checked`.
- §3, boundary B4 (agent → proxy) and ADR-0011: the agent's executor must not link Caddy or `internal/proxy`, which keeps the proxy a separate process and keeps the agent inside its memory budget.
- §7 (trusted core) and ADR-0015: age stays inside `internal/keys`, so wrap and unwrap have one implementation and every other package goes through it.
- No rule is loosened. Each rewritten rule must cover a superset of the files it covered before.
