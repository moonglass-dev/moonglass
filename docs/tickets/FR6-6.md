# One owner of the release status text

The release status text (`retired`, `previous` and the rest) is owned by internal/agent/state (`docs/specs/agent-state.md`, "Rules"), yet internal/deploy/stop.go redeclares `statusRetired = "retired"` and compares `state.DueStop.Status` against it (R-6 finding 6). After this ticket `DueStop` tells the executor whether a due stop is of a retired release through a `Retired bool` field that replaces the raw `Status` string, the executor decides removal from that field alone, and the deploy copy of the status is deleted. The command-type comment in internal/agent/state/state.go names the tickets that add the remaining command types of `docs/specs/agent-state.md` ("`commands`"): W3-4 adds `build`, W5-5b adds `stop_app` and `remove_app`. Behaviour is unchanged (`docs/specs/release.md`, "Switch" step 5), so no spec changes.

## Scope

- internal/agent/state: `DueStop` loses `Status string` and gains `Retired bool`, set by `DueStops` to true exactly when the row's status is `statusRetired` and false for a `previous` row. The status constants stay unexported. The comment above `CommandDeploy` reads that W3-4 adds `build` and W5-5b adds `stop_app` and `remove_app`; it no longer names W3-7. The existing `TestDueStopsListsPreviousAndRetiredPastStopAfter` expectations move from `Status: "retired"` / `Status: "previous"` to `Retired: true` / `Retired: false`, case for case, with nothing dropped.
- internal/deploy: `statusRetired` is deleted from stop.go; `stopOne` removes the container and clears the pre-deploy step name when `stop.Retired` is true, and otherwise only stops and keeps the container, exactly as today.

## Acceptance criteria

- `TestDueStopsMarksRetiredRows`: table-driven over a retired row and a previous row, each past its `stop_after`; `DueStops` returns `Retired` true for the retired row and false for the previous row, with the other fields as stored.
- `TestDueStopRetiredAfterSwitch`: after three `RecordSwitch` calls of one app and a `now` past both stops, `DueStops` lists the old previous with `Retired` true and the old current (now previous) with `Retired` false.
- `TestDueStopRetiredAfterRollback`: after two switches and a `RecordRollback`, and a `now` past the rolled-from row's `stop_after`, `DueStops` lists the rolled-from release with `Retired` true and does not list the restored release.
- `TestDeployDeclaresNoReleaseStatusText`: parses every non-test `.go` file in internal/deploy with `go/parser` and fails, naming file and line, on any string literal equal to `candidate`, `current`, `previous`, `retired`, `failed` or `aborted`.
- The existing deploy tests `TestStopPreviousStopsAndKeepsContainer`, `TestStopRetiredRemovesContainerAndPreDeployStep`, `TestStopNeverStopsRestoredRelease`, `TestStopRefusesUnmanagedContainer` and `TestReconcileCarriesOutDueStops` pass unchanged.
- `state.DueStop` has no `Status` field; `grep -rn statusRetired internal/deploy` finds nothing.
- The comment above `CommandDeploy` names W3-4 for `build` and W5-5b for `stop_app` and `remove_app`, and does not name W3-7.
- `make ci` is green.

## Out of scope

- FR6-8 (health-gate time limits in internal/deploy/switch_test.go).
- W3-4 and W5-5b adding the `build`, `stop_app` and `remove_app` command types.
- Any change to the stored status text, the storage schema or the specs.

## Security notes

- `docs/threat-model.md` §3 B5: every stop or removal still follows the managed-label check `ownedBy` made right before the call; this ticket changes only how the executor learns that a row is retired, never the ownership check or its order.
- No retired container may be left running or orphaned: a retired due row must still have its container stopped and removed and its pre-deploy step container cleared before `RecordStopped` clears `container_id`; a previous row must still be stopped and kept.
- No new dependency, no protocol, policy or agent.toml change.
