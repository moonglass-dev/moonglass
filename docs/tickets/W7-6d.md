# Protocol: update messages

The control plane gains a typed offer of a new agent release, `UpdateOffer` under the new type `UPDATE_OFFER` (server to agent), the agent gains a typed report of what it did with that offer, `UpdateReport` under `UPDATE_REPORT` (agent to server), and `Heartbeat` gains `update_channel`. `internal/protocol` validates every new field when a payload is opened, including the reason-to-outcome binding, rejects unknown fields, and has protocol-abuse tests and a fuzz target for each new parser. No field can carry a URL, a host path, a channel name in the offer, a shell string or free text. This implements the "Messages" subsection of `docs/specs/update.md` §6, the offer of §1, and the `update_channel` paragraph of `docs/specs/protocol.md` "Heartbeat" (owner decision 5 of `docs/specs/update.md` §10).

## Scope

- `proto/moonglass/agent/v1/agent.proto`:
  - `MessageType` gains `UPDATE_OFFER` and `UPDATE_REPORT`.
  - New `UpdateOffer` with one field, `version` (`string`), and a comment saying it is the only field, so an offer names no URL, path, channel, hash or older version.
  - New `UpdateReport`: `version` (`string`), `sha256` (`string`), `outcome` (`UpdateOutcome`), `reason` (`UpdateReason`), `proxy_restarted` (`bool`), with a comment saying the report has no free-text field.
  - New enum `UpdateOutcome`: an `UNSPECIFIED` zero value, then `REJECTED`, `VERIFY_FAILED`, `SWITCHING`, `PASSED`, `REVERTED`, `CHECK_FAILED`.
  - New enum `UpdateReason`: an `UNSPECIFIED` zero value, then `NOT_NEWER`, `NOT_ON_CHANNEL`, `REVERTED_BEFORE`, `TRIAL_IN_PROGRESS`, `POINTER`, `DISK`, `DOWNLOAD`, `TOO_LARGE`, `SIGNATURE`, `CHECKSUM`, `POINTER_MISMATCH`, `WRITE`, `RESTARTED`, `NOT_CONNECTED`, `EXE_MISMATCH`, `PROXY`, `DEADLINE`.
  - `Heartbeat` keeps fields 1 to 3 and gains `update_channel` (`string`, not an enum).
  - **Contract numbers and names are the owner's.** Neither spec fixes the two `MessageType` numbers, the field numbers of the two messages and of `update_channel`, the enum numbers, or the enum value names. `docs/specs/delete.md` and `docs/specs/protocol.md` require the type numbers to be greater than 16 (`STOP_APP` = 15, `REMOVE_APP` = 16 are reserved; `LOG_REQUEST` = 12, `LOG_CHUNK` = 13, `USAGE` = 14 too). Protobuf enum values share the package scope, and `REJECTED` (`CommandOutcome`) and `TOO_LARGE` (`ErrorCode`) already exist there, so the new enum values need names that do not collide. The plan step proposes every number and name; the owner approves them before tests lock, and they are recorded in `docs/specs/protocol.md`.
- `internal/protocol/agentv1/agent.pb.go`: regenerated with `make proto`, never edited by hand.
- `internal/protocol`:
  - `validateType` and `typeOf` know the two new types and `*agentv1.UpdateOffer` and `*agentv1.UpdateReport`; `validatePayload` validates both.
  - New file for the update validators: release version, sha256, outcome, reason, the outcome–reason binding, `proxy_restarted`. `validateHeartbeat` gains the `update_channel` check. Every failure wraps `ErrMalformed` and names the field, the expected form and the actual value or length. `hexChars` from `deploy.go` is reused.
- `docs/specs/protocol.md`: add `UPDATE_OFFER` and `UPDATE_REPORT` to the `MessageType` list; a new section "Update messages (W7-6d)" with the approved numbers and names and the rules below, pointing at `docs/specs/update.md` §1 and §6 for behaviour.

Validation rules, from `docs/specs/update.md` §1 and §6:

- **Release version** (`UpdateOffer.version`, `UpdateReport.version`): `v` followed by `MAJOR.MINOR.PATCH`, three semver numeric identifiers: each one or more ASCII digits, no leading zero unless the identifier is exactly `0`. No pre-release, no build metadata, no whitespace, no other character. Required in both messages.
- **`UpdateReport.sha256`**: empty when `outcome` is `REJECTED`; exactly 64 characters of `[0-9a-f]` for every other outcome.
- **`UpdateReport.outcome`**: one of the six values; `UNSPECIFIED` and unknown numbers are rejected.
- **`UpdateReport.reason`**: unknown numbers are rejected. Each reason belongs to one outcome:
  - `REJECTED`: `NOT_NEWER`, `NOT_ON_CHANNEL`, `REVERTED_BEFORE`, `TRIAL_IN_PROGRESS`, `POINTER`.
  - `VERIFY_FAILED`: `DISK`, `DOWNLOAD`, `TOO_LARGE`, `SIGNATURE`, `CHECKSUM`, `POINTER_MISMATCH`, `WRITE`.
  - `REVERTED` and `CHECK_FAILED`: `RESTARTED`, `NOT_CONNECTED`, `EXE_MISMATCH`, `PROXY`, `DEADLINE`.
  - `SWITCHING` and `PASSED`: `UNSPECIFIED` only.
  - `UNSPECIFIED` with any other outcome, and any reason outside its outcome's list, is rejected.
- **`UpdateReport.proxy_restarted`**: must be `false` when `outcome` is `REJECTED` or `VERIFY_FAILED`; either value otherwise.
- **`Heartbeat.update_channel`**: empty, `STABLE` or `CANARY`, byte for byte. Any other value, including `stable`, `canary`, `UNSPECIFIED` and values with surrounding whitespace, is rejected.
- **`Heartbeat.agent_version`**: unchanged (no rule).

## Acceptance criteria

- `TestUpdateOfferRoundTrip`: an `UpdateOffer` with each of `v0.0.0`, `v1.2.3`, `v10.20.30` and `v18446744073709551616.0.0` (a numeric identifier longer than uint64) round-trips through `Wrap`, `Marshal`, `Unmarshal` and `Open` under `UPDATE_OFFER` and is `proto.Equal` to the input; `UpdateOffer` has exactly one field, named `version` (checked through its descriptor), and no string field that looks like a host command (`assertNoShellStringFields`).
- `TestUpdateOfferRejectsInvalid`: `Open` rejects with `ErrMalformed`, and the error names `version`: empty; `1.2.3` (no `v`); `V1.2.3`; `v1.2`; `v1.2.3.4`; `v01.2.3`, `v1.02.3`, `v1.2.03`; `v1.2.3-rc.1`; `v1.2.3+build`; `v1..3`; `v.1.2`; `v1.2.`; `v-1.2.3`; ` v1.2.3` and `v1.2.3\n`; `v1.2.3/../x`; `https://moonglass.dev/releases/v1.2.3`; a NUL byte; a non-ASCII digit (`v１.2.3`).
- `TestUpdateReportRoundTrip`: for every valid outcome–reason pair in the binding above (5 + 7 + 5 + 5 + 1 + 1 = 24 pairs), a report with a valid version, the right `sha256` shape (empty for `REJECTED`, 64 lowercase hex otherwise) and `proxy_restarted` `false` round-trips under `UPDATE_REPORT` and is `proto.Equal` to the input; `proxy_restarted` `true` round-trips with `SWITCHING`, `PASSED`, `REVERTED` and `CHECK_FAILED`; `UpdateReport` has no string field that looks like a host command and its only string fields are `version` and `sha256` (checked through its descriptor).
- `TestUpdateReportRejectsInvalid`: `Open` rejects with `ErrMalformed`, naming the field: `outcome` `UNSPECIFIED` and unknown numbers (one above the last value, and 2^31-1); `reason` unknown numbers (one above the last value, and 2^31-1); `reason` `UNSPECIFIED` with `REJECTED`, `VERIFY_FAILED`, `REVERTED` and `CHECK_FAILED`; every reason paired with every outcome it does not belong to, including any non-`UNSPECIFIED` reason with `SWITCHING` and `PASSED`; `sha256` non-empty with `REJECTED`; `sha256` empty, 63 or 65 characters, uppercase hex, or containing a non-hex letter with each other outcome; `proxy_restarted` `true` with `REJECTED` and with `VERIFY_FAILED`; and an invalid `version` (empty, no `v`, leading zero, pre-release).
- `TestHeartbeatUpdateChannel`: a `Heartbeat` with `update_channel` empty, `STABLE` and `CANARY` round-trips under `HEARTBEAT`, alone and together with a valid `disk` and `deploy_key`; `Open` rejects with `ErrMalformed`, naming `update_channel`: `stable`, `canary`, `Stable`, `UNSPECIFIED`, `BETA`, ` STABLE`, `STABLE\n`, `STABLE\x00` and a 1 KiB string.
- `TestUpdateMessagesProtocolAbuse`: unknown fields appended to an `UpdateOffer` and to an `UpdateReport` payload are rejected with `ErrMalformed`; an `UPDATE_OFFER` envelope opened as `UpdateReport`, an `UPDATE_REPORT` envelope opened as `UpdateOffer`, and an `UPDATE_OFFER` envelope opened as `Deploy` fail with `ErrTypeMismatch`; `Wrap(UPDATE_OFFER, …, &UpdateReport{…})` and `Wrap(UPDATE_REPORT, …, &UpdateOffer{…})` fail with `ErrTypeMismatch`; an `UPDATE_OFFER` and an `UPDATE_REPORT` envelope carrying `error` are rejected by `Marshal` and `Unmarshal`; an `UpdateOffer` whose `version` makes the framed envelope larger than `MaxEnvelopeSize` is rejected by `Marshal`, and the same bytes are rejected by `Unmarshal`, before any proto parse.
- `FuzzOpenUpdateOffer` and `FuzzOpenUpdateReport`: seeded with a valid message, an empty payload, a payload with an appended unknown field and (for the report) one valid payload per outcome; for any input `Open` returns nil or an error wrapping `ErrMalformed` and never panics; an accepted message passes its validator directly, and re-wrapping and re-opening it gives a `proto.Equal` message.
- `TestEnvelopeRoundTripEveryType` passes unchanged with the two new types.
- No existing test line changes: the unknown-type numbers in existing tests (`15`, `99`) stay unknown because the new type numbers are greater than 16.
- The type, field and enum numbers and the enum value names in the `.proto` are the ones the owner approved, and `docs/specs/protocol.md` records them.
- `make proto` leaves no diff; `make ci` is green.

## Out of scope

- What the agent does with an offer, the pointer check, download, verification, switch, revert, self-check and report delivery: W7-6e.
- Sending offers, the per-server rate limit, ignoring duplicate reports, rollout state, and reading `update_channel` on the control plane: W7-6f.
- The `u` + 32 lowercase hex shape of an offer's request id, which the control plane mints, and message direction (offer server to agent only, report agent to server only): enforced by the connection layer in W7-6e and W7-6f, as for the `c` and `l` ids of `docs/specs/connection.md`; the codec keeps the envelope's 1-to-64-byte rule.
- The `none` command class for `UPDATE_OFFER` and `UPDATE_REPORT` on the non-command list in the agent's class table (`docs/specs/local-policy.md`): the agent ticket that dispatches it, W7-6e.
- Setting `update_channel` from `update.channel` in `agent.toml` (lowercase there, uppercase on the wire): W7-6e.
- The signature verifier: W7-6a. Release workflow: W7-6c, W7-6g.

## Security notes

- `docs/threat-model.md` §9 checklist 1: the `.proto` change is a contract change and needs the owner's approval of the numbers and names before code. No field of `UpdateOffer`, `UpdateReport` or `update_channel` can carry a URL, a host path, a command line, a shell string, free text, a secret or key material: the offer has only a strictly shaped version, the report has only a version, a fixed-shape hex hash, two closed enums and a bool, and the channel is one of two fixed words. Every new parser has a protocol-abuse test and a fuzz target.
- §3 B3 and the ninth boundary: the agent treats the control plane as hostile. The offer names only a version, so a hostile control plane cannot name a URL, a path, a channel or a hash through the protocol (`docs/specs/update.md` §1); malformed, oversized, unknown-field and wrong-type messages are rejected before any later code acts.
- §9 checklist 6 (release signatures) is not weakened: nothing in the protocol carries anything the agent would trust in place of the signed channel pointer.
- No error string includes more than the offending field's value or length, and none of these fields can hold a secret.
