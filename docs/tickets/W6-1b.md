# Policy: healthcheck, aliases and DNS search

`policy.Spec` gains three pass-through fields, `Healthcheck`, `NetworkAliases` and `DNSSearch`, which `Check` copies into `Checked` unchanged, so the Engine request built from `Checked` can carry a container's healthcheck, its internal service name and its search domain (`docs/specs/container-policy.md`, "Healthcheck, aliases and DNS search"; ADR-0004 decision 10). Owner decision of 2026-11-19.

## Scope

- `internal/policy/types.go`: the `Healthcheck` type (`Test []string`, `Interval`, `Timeout`, `StartPeriod`, `StartInterval time.Duration`, `Retries int`) and the three `Spec` fields. `Checked.Spec()` deep-copies them like the other slices and maps.
- `internal/policy/check.go`: the rules of that section, each a malformed spec (field `spec`). The deny list does not judge these fields, and no allow key is added.
- `CheckCompose` fills none of them; its output does not change.
- `docs/specs/container-policy.md`: already says this; change it only if the built behaviour needs a wording fix.

## Acceptance criteria

- `TestHealthcheckAliasesAndSearchPassThrough`: for each field, a spec that sets it passes `Check`, and `Checked.Spec()` returns it equal to the input; changing the returned copy does not change a second `Spec()` call (deep copy). A nil `Healthcheck` stays nil.
- `TestMalformedHealthcheckRejected`: a table with one row per rule (an unknown first word, `CMD` with no argv, `CMD-SHELL` with two entries, an empty or NUL entry, `NONE` with a non-zero duration or `Retries`, each duration and `Retries` just outside its bounds); each is a `*Rejection` whose violation has field `spec`, and the rendered text never contains a test entry's text.
- `TestMalformedAliasOrSearchRejected`: an alias or search entry that is upper case, ends in `.`, has an empty label, a label of 64 bytes or a leading `-`, or is 254 bytes; five entries; and aliases or search domains with no `Networks`; each is malformed (field `spec`).
- The escape suite and every existing `internal/policy` test pass unchanged.
- `make ci` is green and `scripts/verify check W6-1b` passes.

## Out of scope

- W6-1c: the executor filling these fields and the Engine request carrying them.
- W6-4a: `ResolveCompose` and its healthcheck mapping.

## Security notes

- `docs/threat-model.md` §6 and §9.2: the checked spec is still the whole request: the three fields are carried in `Checked`, never added after the check.
- A healthcheck runs inside the container through the Engine, never on the host (§8). `NetworkAliases` and `DNSSearch` are filled only by agent code from the binding, like `AgentLabels` (ADR-0004 decision 11); no protocol message or Compose file reaches them.
