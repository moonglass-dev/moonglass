# Protocol v0

## Outcome

The agent ↔ control-plane protocol v0 exists as a checked-in `.proto` file and a small `internal/protocol` codec. It covers the envelope, Enroll, Heartbeat and error codes — nothing else. `make proto` is deterministic, CI fails if generated code is stale, and a fuzz target exercises envelope decoding. ADR-0008 records the protobuf codegen tool. The full behaviour is `docs/specs/protocol.md`, written in this ticket from `docs/plan/stack.md` §3.1 and the threat model.

This ticket also writes `docs/adr/0008-protobuf-codegen.md` and adds a row to `docs/adr/README.md`. That ADR is expected; it is not an unplanned contract change. Prefer the official `protoc` + `protoc-gen-go` (`google.golang.org/protobuf`) toolchain, versions pinned, generated code checked in, no third-party codec. If a different official-protobuf tool is clearly better, say so in the ADR and still pin it.

## Out of scope

Transport (the WebSocket itself, TLS, reconnect). The enroll CLI, key generation, fingerprint printing and token store (W1-3). Heartbeat scheduling and liveness (W1-4). Deploy, SwitchRelease, Rollback, RunPreDeploy and every later message (W2-2). Compatibility with a previous protocol version (ADR-0007, after launch only). UI, Docker, product commands beyond the codec.

## Acceptance tests

- `TestEnvelopeRoundTrip`: a well-formed envelope encodes and decodes to the same version, type, request id and payload.
- `TestEnvelopeRejectsMalformed`: truncated, empty and trailing-garbage inputs return an error; they do not panic or yield a usable message.
- `TestEnvelopeRejectsOversized`: an input larger than the documented maximum is rejected before the payload is treated as a message.
- `TestEnrollRoundTrip`: Enroll request and response types round-trip through the envelope; the fields are typed (token id, public keys, result), not a host shell string.
- `TestHeartbeatRoundTrip`: Heartbeat and acknowledgement types round-trip through the envelope.
- `TestErrorCodes`: every documented error code encodes and decodes; an unknown code is rejected or reported as unknown, not panicked on; an error is a structured code plus an optional detail, not a shell command.
- `FuzzEnvelopeDecode`: Go fuzzing of envelope decode; malformed inputs must not panic.

## Security notes

Threat-model §9 checklist, especially "New protocol fields or messages": size, order and type are checked before any later code would act; there is a protocol-abuse test and a fuzz target for the envelope parser; no message field carries a shell string for the host (S§3.1). Enroll and Heartbeat carry keys, tokens or identifiers: tests must not log secret values. Do not add `RewrapEnvKey` or any secrets-wrapping message in this ticket.

## Done when

- `proto/moonglass/agent/v1/` holds the v0 `.proto` file; generated Go is checked in under `internal/protocol` and is not edited by hand.
- `make proto` is deterministic (running it twice produces no diff). `make ci` fails when generated code is stale.
- ADR-0008 is written and listed in `docs/adr/README.md`. `docs/specs/protocol.md` matches the implementation.
- Every test above exists, is not skipped, and passes. `make ci` is green.
- The codec is short enough to audit in one sitting. No `TODO`, `FIXME`, `XXX` or `HACK` in Go, proto, Makefile or CI files.
