# Compose hash on the control plane

A release records the Compose hash it was deployed with, `deploy` takes it as the optional input `compose_hash`, `services.list` shows each service's current release's hash, and `services.restore` keeps it, so Compose import compares a file against what actually runs (`docs/specs/compose.md`, "Change detection"; `docs/specs/storage.md`, "Service settings on releases"; `docs/specs/registry.md`). The owner approved the column and the input on 2026-11-19.

## Scope

- `internal/store`: a migration per backend adding `releases.compose_hash` (`TEXT NOT NULL DEFAULT ''`); `Release.ComposeHash` stored by `EnqueueRelease` and returned by every release read; `Service.ComposeHash` returned by `Services`, read from the release named by `current_release_id` in the same org, empty when there is none.
- `internal/registry`: `deploy` gains `compose_hash` (optional; empty or 64 lowercase hex, otherwise `Refuse(ErrInvalidInput, …)` before a release is minted). It is stored only and never sent in `DEPLOY`. `services.list` returns `compose_hash`.
- `internal/server`: the restore path copies `compose_hash` with the other settings.
- `internal/api/openapi.json`, `internal/cli/generated.go`: regenerated with `make generate`.
- The three specs: already say this; change them only if the built behaviour needs a wording fix.

## Acceptance criteria

- `TestComposeHashConformanceSQLite` and `TestComposeHashConformancePostgres`: a release enqueued with a hash reads it back; `Services` shows it only once that release is the service's current release, shows the previous current's hash after `SetServiceReleases` moves back, and shows empty for a service with no current release; a second org sees none of it.
- `TestDeployRecordsComposeHash`: a `deploy` with a hash stores it on the release, and the `DEPLOY` the agent stub receives is identical to one without it.
- `TestDeployRefusesMalformedComposeHash`: 63 hex, 65 hex and upper-case hex are each `ErrInvalidInput`, audited `invalid input`, with no release minted.
- `TestServicesListShowsCurrentComposeHash`: `services.list` returns `compose_hash` per service as above.
- `TestRestoreKeepsComposeHash`: a restore's new release carries the current release's hash.
- `TestGeneratedOpenAPIIsCurrent`, `TestGeneratedCLIIsCurrent` and every existing test pass unchanged.
- `make ci` is green and `scripts/verify check W6-4b` passes.

## Out of scope

- W6-4c: computing the hash. W6-4: the import command.

## Security notes

- `docs/threat-model.md` §3 B2 and §9.5: `releases` stays a row-level table under `org_isolation`, and the current-release read is bound to the caller's org.
- The hash covers no environment name or value (`docs/specs/compose.md`), so it reveals nothing about a secret.
- §9.5: no operation's role, scope or flags change.
