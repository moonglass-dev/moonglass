# Add enrolment: server endpoint and `moonglass agent enroll`

## Outcome

`moonglass agent enroll` generates the agent's Ed25519 and X25519 identity on the machine, registers with `moonglass server` using a one-time token, pins the control-plane public key, and prints the agent fingerprint. A replay of the same token fails. The behaviour is `docs/specs/enrolment.md`, which this ticket writes and may edit, and must stay faithful to ADR-0003 (agent identity only), ADR-0005 (token format, one-hour one-use, stored hashed), `docs/specs/protocol.md` Enroll types, and threat-model B3.

No new module. Standard library only (`crypto/ed25519`, `crypto/ecdh`, `net/http`, the existing `internal/store` and `internal/protocol`). SQLite via the existing store is enough for the server in this ticket; do not require Postgres for the named tests.

## Out of scope

- WSS, reconnect, heartbeat scheduling (W1-4).
- Environment keys, recovery key, `filippo.io/age` (W3-1).
- Bootstrap token, first-admin window, login links, GitHub OAuth (ADR-0005, W4-1, W7-1).
- Proxy (W1-5). Store schema changes. W1-1 questions 6 and 7, and ADR-0002 open question 1.

## Acceptance tests

- `TestGenerateAgentIdentity`: a new identity has 32-byte Ed25519 and X25519 public keys; the private halves are not equal to the publics; two calls produce different keys.
- `TestFingerprintIsSHA256OfSigningKey`: the printed fingerprint is the lowercase hex SHA-256 of the raw Ed25519 public key (64 hex characters).
- `TestEnrollAcceptsAndPins`: given a valid unused token, enroll returns `ACCEPTED`, stores the server, pins the control-plane public key in the agent data dir, and the fingerprint matches the signing key.
- `TestEnrollReplayFails`: a second enroll with the same token returns `TOKEN_USED` (or the agent-side error for that result), does not register a second server, and does not change the pin or keys.
- `TestEnrollDoesNotConsumeTokenOnMalformedKeys`: a request with the right bearer but public keys of the wrong length does not consume the token; a later well-formed enroll with that token is accepted.
- `TestEnrollRejectsInvalidToken` / `TestEnrollRejectsReplay`: server-side cases for unknown, expired, and already-used tokens.
- `TestAgentEnrollPrintsFingerprint`: `moonglass agent enroll` against a test server prints the fingerprint to stdout and does not print the token. Existing `cmd/moonglass` version tests still pass; update the usage test if the usage text grows, without weakening it.

## Security notes

Threat-model B3 and the token / key rules: the token secret is not in the protobuf and is not logged; only the hash is stored; a replay fails; agent private keys never leave the machine; the control-plane public key is pinned from the response.

- `docs/specs/enrolment.md` matches the implementation.
