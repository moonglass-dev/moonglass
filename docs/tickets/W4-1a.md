# Session tables

The store gains the `session_hashes` lookup table and the `session_id` and `step_up_id` columns of `audit_events`, on Postgres and SQLite, as `docs/specs/auth.md` ("Storage") specifies. After this ticket a session can be added by the SHA-256 of its `mg_` bearer, found by that hash only while it is live, and revoked by its owner; an audit event carries the session and step-up IDs through `AppendAudit` and `AuditEvents`. Nothing calls these methods yet: sign-in is W4-1b.

## Scope

- `internal/store/migrations/pg/` and `internal/store/migrations/sqlite/`: one new migration per backend, numbered after the highest file present on `main` when the ticket is built (never edit an applied migration, `internal/store/migrate.go`). It creates `session_hashes` with exactly the columns `hash` (`TEXT NOT NULL PRIMARY KEY`), `id` (`TEXT NOT NULL`, unique), `user_id` (`TEXT NOT NULL`), `expires_at` (`TEXT NOT NULL`) and `revoked_at` (`TEXT`, null while live), with no RLS on Postgres. It adds `session_id` and `step_up_id` to `audit_events` as `TEXT NOT NULL DEFAULT ''` on both backends. The two schemas stay identical in table, column and nullability.
- `internal/store/lookup.go`: `session_hashes` joins `LookupTables`.
- `internal/store/store.go`:
  - `type Session struct { ID, UserID, ExpiresAt string }`. It has no hash field.
  - `AuditEvent` gains `SessionID` and `StepUpID`.
  - `Store` gains:
    - `AddSession(ctx, userID, sessionHash string, expires time.Time) (Session, error)`: mints the ID with `NewID`, stores the row, returns the session; a repeated hash is `ErrDuplicate`.
    - `SessionByHash(ctx, sessionHash string, now time.Time) (Session, error)`: `ErrNotFound` for an unknown hash, a revoked session, or one whose `expires_at` is not after `now`.
    - `RevokeSession(ctx, userID, sessionID string, now time.Time) error`: stamps `revoked_at` with `now` on that user's session; `ErrNotFound` when no session with that ID belongs to that user. A session already revoked keeps its first `revoked_at` and the call returns nil.
- `internal/store/sessions.go` (new): the three methods on `SQLStore`, plain SQL in the common subset, through `s.q`. They read and write only `session_hashes`, without `app.org_id`, like the other lookups (`docs/specs/storage.md`, "Transactions and isolation").
- `internal/store/tokens.go`: `appendAuditOnce` inserts and `AuditEvents` selects `session_id` and `step_up_id`.
- `internal/store/schema_test.go`: `TestLookupTablesMatchSchema`'s expected list gains `session_hashes`. Nothing in it is removed or loosened.
- `docs/specs/storage.md`: the lookup-table list gains `session_hashes`, and the `audit_events` line names W4-1a's `session_id` and `step_up_id`.
- `docs/specs/auth.md`: changed only if the build finds a statement in "Storage" that the code contradicts.

## Acceptance criteria

- `TestSessionsConformanceSQLite` and `TestSessionsConformancePostgres` run one shared `runSessionsConformance` (Postgres as the application role) and prove: `AddSession` returns a 32-character ID, the user ID and the expiry as UTC RFC3339 text; `SessionByHash` returns that session before expiry; it is `ErrNotFound` for an unknown hash, at `now` equal to the expiry, and after it; `RevokeSession` by another user is `ErrNotFound` and the session stays live; `RevokeSession` of an unknown ID is `ErrNotFound`; after `RevokeSession` by its user, `SessionByHash` is `ErrNotFound`, and a second revoke returns nil; a second `AddSession` with the same hash is `ErrDuplicate`; two sessions of one user are independent, so revoking one leaves the other live.
- `TestAuditSessionColumnsConformanceSQLite` and `TestAuditSessionColumnsConformancePostgres` run one shared suite and prove: an event appended with `SessionID` and `StepUpID` set reads back from `AuditEvents` with both values unchanged; an event appended without them reads back with both empty; the chain still starts at seq 1 with an empty `PrevHash` and each later event's `PrevHash` equals the previous `Hash`.
- `TestSessionStoredHashedOnly`, with a `sqlite` and a `postgres` subtest in the style of `TestEnrolmentTokenStoredHashedOnly`: after `AddSession` with `store.HashToken` of a fixed `mg_` bearer, some stored cell equals the hex SHA-256, no cell in any table contains the plaintext or an `mg_` value, and `SessionByHash` with the hash of a different bearer is `ErrNotFound`.
- `TestLookupTablesMatchSchema` and `TestSchemasMatch` pass with `session_hashes` and the two new `audit_events` columns on both backends; `session_hashes` has no `org_id` and no RLS on Postgres.
- `TestMigrateIdempotent` and every existing store, registry, server and API test pass unchanged.
- `internal/registry` is not changed: the audit hash still covers the fields it covers today, and `registry.audit` leaves the two new fields empty. The hash with the new columns is W4-1b.
- `make ci` is green and `scripts/verify check W4-1a` passes.

## Security notes

- Threat model §2 (Tokens): a session is stored only as the SHA-256 hex of its bearer. No store method takes or returns the plaintext, and `Session` has no hash field. `TestSessionStoredHashedOnly` checks every table on both backends.
- ADR-0002 decision 12 and §9.5: `session_hashes` is on `LookupTables` and holds only its lookup key, the IDs it maps to, an expiry and a revoked marker; never a name, scope or secret. It is read without `app.org_id`, and returns nothing that is not on the row.
- §9.4: an expired or revoked session is never returned. The expiry is absolute: no method extends `expires_at`. Only the session's own user can revoke it.
- §2 (Audit trail): `AppendAudit` stays the only writer and keeps its one-transaction read of the chain head. No existing column, order or retry changes. Until W4-1b nothing writes the two new columns, so the unchanged hash leaves no unhashed value in the chain.
- §9.5: the application role still owns no table and lacks `BYPASSRLS`; the grants on the new table come from `pg.Migrate`, never from the migration file.
