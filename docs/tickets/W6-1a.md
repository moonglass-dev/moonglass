# Protocol: service settings on Deploy

`Deploy` gains `command` = 13, `volumes` = 14, `labels` = 15, `restart` = 16 and `healthcheck` = 17, with the new messages `VolumeMount` and `Healthcheck`, so a service's container settings can reach the agent for the databases of W6-1 and the Compose services of W6-4 (`docs/specs/protocol.md`, "Service settings"). The owner approved the fields, their rules and their numbers on 2026-11-19. Opening a `Deploy` validates every rule before any later code acts.

## Scope

- `proto/moonglass/agent/v1/agent.proto`: the five `Deploy` fields with exactly those numbers; `VolumeMount` (`name` = 1, `target` = 2, `read_only` = 3); `Healthcheck` (`test` = 1, `interval_ms` = 2, `timeout_ms` = 3, `start_period_ms` = 4, `start_interval_ms` = 5, `retries` = 6). `labels` is `map<string, string>`. Numbers 11 and 12 stay free for W4-8. Each new field has a comment saying it is not a host path or a host shell string.
- `internal/protocol/agentv1`: regenerated with `make proto`, never edited by hand.
- `internal/protocol`: the validation of every rule in the three tables of "Service settings", in the open path of `Deploy`, returning `ErrMalformed` with a message naming the field and never the value of a label or a command entry. Unknown fields inside `VolumeMount` and `Healthcheck` are rejected like every other nesting level. `Marshal` stays deterministic (map keys sorted).
- `docs/specs/protocol.md`: already says this; change it only if the built behaviour needs a wording fix.

## Acceptance criteria

- `TestDeployServiceSettingsRoundTrip`: a `Deploy` with every new field set at its bounds (32 command entries, 8 volumes, 32 labels, each restart value, each of the three healthcheck forms) opens to an equal message, and marshalling it twice gives identical bytes.
- `TestDeployServiceSettingsRejectMalformed`: a table with one row per rule: an empty or NUL command entry, 33 entries, a 1025-byte entry; a volume name that is empty, 64 bytes, upper case or starts with `.`; a target that is relative, `/`, has `..`, `.`, an empty element or a trailing `/`, or is 257 bytes; two volumes with one target; nine volumes; a label key in `dev.moonglass.`, empty, 129 bytes or with a space; a value of 1025 bytes or with NUL; 33 labels; a restart of `always` or `unless-stopped`; each malformed healthcheck form (`CMD` alone, `CMD-SHELL` with two entries, `NONE` with another entry or a non-zero timing, an unknown first word, 33 entries) and each timing out of bounds or missing. Each row is `ErrMalformed`, and the failure message shows the row's name and the error.
- `TestDeployServiceSettingsRejectUnknownNestedFields`: an unknown field inside a `VolumeMount` and inside a `Healthcheck` is rejected.
- `FuzzOpenDeployServiceSettings`: opening arbitrary `Deploy` payload bytes never panics, and an accepted payload re-marshals to bytes that open to an equal message.
- Every existing `internal/protocol` test passes unchanged; `make proto-check` is clean.
- `make ci` is green and `scripts/verify check W6-1a` passes.

## Out of scope

- W6-1b: the matching `policy.Spec` fields. W6-1c: the agent applying the settings. W6-1d: the control plane sending them.
- W4-8: `env_key` and `secrets`.

## Security notes

- `docs/threat-model.md` §9.1: no new field is a host path or a host command line. `command` and `healthcheck.test` run inside the container (a `CMD-SHELL` entry by the container's own shell), like `RunPreDeploy.args`; a volume `name` is a name the agent turns into its own volume name, never a path.
- ADR-0004 decision 11: a `dev.moonglass.` label key is refused here and again by the policy.
- §9.1: size and shape are checked before any later code acts; the fuzz target covers the new parser.
