# Tidy go.mod and gate it

R-1 finding 9: `go.mod` marks `github.com/danielgtaylor/huma/v2`, `github.com/jackc/pgx/v5` and `modernc.org/sqlite` as `// indirect` although `internal/api`, `internal/store/pg` and `internal/store/sqlite` import them, and it requires about 59 modules nothing imports. Among them are `github.com/BurntSushi/toml`, which ADR-0009 rejects, and the Gin, Fiber, Echo, Chi, gorilla/mux and bunrouter modules, which ADR-0013 rules out. After this ticket `go.mod` is exactly what `go mod tidy` produces, and `make ci` fails whenever it is not, so `go.mod` shows which modules the product depends on.

## Scope

- `go.mod`, `go.sum`: the result of `go mod tidy` with the pinned toolchain (`toolchain go1.27.4`). The direct block holds every module that product code imports, and unused requirements are gone. No version of a required module changes.
- `Makefile`: a new target `mod-check` that runs `go mod tidy -diff` and on failure prints `go.mod or go.sum is not tidy: run "go mod tidy" and commit the result` to stderr, then exits non-zero. Add `mod-check` to `.PHONY`, and run it in the first parallel phase of `ci`, next to `proto-check` and `fmt-check`, with its status line printed like theirs.
- `AGENTS.md`: the `make ci` row of the Commands table lists `mod-check` among the steps.

## Acceptance criteria

- `go mod tidy -diff` exits 0 on the branch and prints nothing.
- The direct `require` block in `go.mod` holds exactly `filippo.io/age`, `github.com/caddyserver/caddy/v2`, `github.com/coder/websocket`, `github.com/compose-spec/compose-go/v2`, `github.com/danielgtaylor/huma/v2`, `github.com/jackc/pgx/v5`, `github.com/pelletier/go-toml/v2`, `google.golang.org/protobuf` and `modernc.org/sqlite`, at the versions on `main` (huma `v2.40.0`, pgx `v5.13.0`, sqlite `v1.62.0`, and the rest unchanged).
- `go.mod` requires none of `github.com/BurntSushi/toml`, `github.com/gin-gonic/gin`, `github.com/gofiber/fiber/v2`, `github.com/gofiber/fiber/v3`, `github.com/labstack/echo/v4`, `github.com/labstack/echo/v5`, `github.com/go-chi/chi/v5`, `github.com/gorilla/mux` or `github.com/uptrace/bunrouter`.
- `make mod-check` exits 0 on the branch. A reviewer can check that it fails: add a `require github.com/gorilla/mux v1.8.1` line to `go.mod`, run `make mod-check`, see a non-zero exit with the message above, then revert.
- `make ci` runs `mod-check` and prints an `ok   mod-check` line, and `make ci` is green.
- `.github/workflows/ci.yml` is unchanged: it already runs `make ci`.
- No Go source changes, and `testdata/tests.txt` is unchanged.

## Out of scope

- FR1-10: depguard rules for the ADR-0009 and ADR-0010 import boundaries in `.golangci.yml`.
- Upgrading any module, and adding or removing a direct dependency. Each of those needs its own ticket and ADR.

## Security notes

- `docs/threat-model.md` §9 (reviewer checklist, "a dependency added without an ADR"): after this change every module in the direct block is named by an accepted ADR or was there from the start (age in ADR-0015, Caddy in ADR-0011, coder/websocket in ADR-0012, compose-go and go-toml in ADR-0009, huma in ADR-0013, pgx and modernc sqlite in ADR-0010, protobuf in ADR-0008), and the `mod-check` gate stops a stray requirement from being merged unnoticed.
- Removing unused requirements makes the supply-chain surface in `go.sum` smaller. The build output does not change, because the binary links only what it imports.
