# Add protocol deploy messages and the release state machine

## Outcome

Protocol v0 grows the four deploy commands `Deploy`, `SwitchRelease`, `Rollback` and `RunPreDeploy`, each a protobuf type in the existing envelope with a new `MessageType` value and no host shell field. A new pure `internal/release` package holds the state machine for the legal sequence of those commands against one app's releases. The behaviour is `docs/specs/release.md` and `docs/specs/protocol.md`.

## Out of scope

The deploy executor and Docker (W2-3), health-gated switch and draining (W2-4), CLI operations (W2-5), running the pre-deploy container (W2-6), auto-rollback (W4-3), response/result messages, new modules.

## Acceptance tests

- `TestDeployRoundTrip`, `TestSwitchReleaseRoundTrip`, `TestRollbackRoundTrip`, `TestRunPreDeployRoundTrip`: each message round-trips through the envelope and invalid identifiers, images and argv are rejected.
- `TestDeployMessagesRejectUnknownType`: unknown types and mismatched payload types are rejected without panic.
- `TestDeployThenSwitchMakesNewCurrent`, `TestPreDeployFailureLeavesOldServing`, `TestRollbackRestoresPrevious`, `TestIllegalTransitionDoesNotChangeState`: the state machine transitions.

## Security notes

Threat-model §9: size, order and type are checked before any later code acts; no field carries a shell string or host path. The state machine cannot reach Docker.

## Done when

- `make ci` is green and every test above passes.
- `docs/specs/protocol.md` and `docs/specs/release.md` match the implementation.
