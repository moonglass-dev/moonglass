# Deploy-correctness suite and Docker matrix

After this ticket a suite in `test/deploy` proves the G2 deploy claims against a real Docker Engine and the real `moonglass proxy`: zero failed requests across ten health-gated deploys under steady load, and `Executor.Rollback` returning `SUCCEEDED` in under 5 seconds. The proxy runs on the host on a loopback port, which `deploy.ProxyConfig.Listen` makes possible (`docs/specs/release.md`, "Listen"). `make test-deploy` runs the suite alone, and CI runs it on Docker Engine 25 to 29 on `ubuntu-22.04` (`docs/specs/deploy-suite.md`).

## Scope

- `internal/deploy/proxy.go`: add `Listen string` to `ProxyConfig`. Empty, the pushed document is byte-for-byte what it is today (`listen` `[":443"]`, no `automatic_https`). Set, the server `moonglass` has `listen` `[<Listen>]` and `automatic_https` `{"disable_redirects": true}`, everything else unchanged. A `Listen` that is not `host:port` with a numeric port makes every push (`Push`, `PushRouted`, and so `Run`) an error naming the value, checked before anything is read or posted, next to the issuer check. Nothing outside `internal/deploy` sets `Listen`; `moonglass agent connect` stays unchanged.
- `internal/deploy/proxy_test.go`: the two Listen tests, against the existing fake admin socket.
- `internal/deploy/reconcile.go` (and `deploy.go` only if the field's comment changes): an exported `func (x *Executor) ScopeReconcile(labels ...string)` that sets the existing unexported `scope`, so `Reconcile` (and so `Run`'s start-up reconcile) lists only managed containers that also carry every given `key=value` label (`docs/specs/release.md`, "Run"; owner decision, 2026-11-20). It is called before `Run`; nothing in `cmd/` or `internal/agent/` calls it. The existing tests that set `x.scope` directly are not edited.
- `internal/deploy/scope_test.go` (new): `TestScopeReconcileRemovesOnlyMatchingContainers`.
- `test/deploy/` (new package, test files plus `testdata/`):
  - `testdata/server`: the static standard-library test image of "The test image": port 8080, `GET /healthz` 200, every other path 200 with a body of exactly its release id, graceful exit on SIGTERM after in-flight requests. The release id is baked into each release's image (for example as an `ENTRYPOINT` argument), so images differ only in that id.
  - Helpers: the Engine connection with skip/fail-under-`CI`, the per-run project `t` + 12 lowercase hex, image build and import as `moonglass.local/<project>/web:<release_id>` through `github.com/moby/moby/client` (already a dependency, ADR-0014; no new module), and cleanup of every container, network and image of the run, pass or fail, tolerating images that retention already removed.
  - `TestMain`: builds `./cmd/moonglass` once with `CGO_ENABLED=0` into a temp directory.
  - The host proxy per run: `moonglass proxy --data-dir <dir> --admin-socket <dir>/admin.sock` with `<dir>` from `os.MkdirTemp("", "mgd")`, ready when `GET /config/` on the admin socket answers, stopped with SIGTERM in cleanup. A port reserved by listening on `127.0.0.1:0` and closing it; `deploy.NewProxy(engine, db, deploy.ProxyConfig{Socket, Issuer: "internal", Listen: "127.0.0.1:<port>"})`; the executor from `deploy.New` with an empty `agent.toml` and a fresh agent database, `Executor.ScopeReconcile("dev.moonglass.project=<project>")` called on it, and then `Executor.Run` running for the whole test.
  - The reachability check: when the first release's container IP on `mg-<project>` does not answer from the host, skip with that reason, or fail under `CI`.
  - The load generator: standard library, default 50 requests per second, keep-alives off, a 5-second limit per request, TLS trusting only the root from `GET /pki/ca/local`, every request to `127.0.0.1:<port>` with server name and `Host` `<project>.moonglass.test`. A request whose connection closed before any answer byte, without a timeout, is sent once more on a new connection and counted as retried (owner decision, 2026-11-20: a Caddy reload closes a connection the old server has not read a request from). It counts every non-2xx, timeout, connection error after the first answer byte and failed retry, keeps the first error and its time, and records each response's release id and arrival time for the ordering assertions.
- `Makefile`: target `test-deploy` running `CGO_ENABLED=1 go test -race -count=1 ./test/deploy`, added to `.PHONY`. `make test` keeps running `./...`, which includes the suite.
- `.github/workflows/ci.yml`: a matrix job, one entry per Engine major 25, 26, 27, 28, 29 on `ubuntu-22.04`, that installs `docker-ce`, `docker-ce-cli`, `containerd.io` and `docker-buildx-plugin` from Docker's apt repository at exact versions pinned in the file (the newest patch of each major at build time, looked up at download.docker.com), checks that the running Engine's server version has that major, sets up Go from `go.mod`, and runs `make test-deploy`. Actions pinned by commit SHA as the existing job does; `permissions: contents: read` stays. The `ci` job is unchanged.
- `docs/specs/deploy-suite.md` and `docs/specs/release.md`: touched only if the implementation shows a statement is wrong; behaviour is already specified there.

## Acceptance criteria

- `TestProxyPushListenSetsAddressAndDisablesRedirects`: with `Listen` `127.0.0.1:<port>` and one routed app, the posted document's server `moonglass` has `listen` `["127.0.0.1:<port>"]` and `automatic_https` `{"disable_redirects": true}`, and the rest of the document equals the one pushed with `Listen` empty except for those two fields; with `Listen` empty, `listen` is `[":443"]` and there is no `automatic_https` key.
- `TestProxyPushRefusesMalformedListen`: table of values such as `127.0.0.1`, `:https`, `127.0.0.1:port`, `127.0.0.1:` and `[::1` each make `Push` and `PushRouted` return an error containing the value; the fake admin socket receives no request, `commit` never runs, and the last pushed document is unchanged.
- `TestScopeReconcileRemovesOnlyMatchingContainers`: against a real Engine, two managed containers no release references, one labelled with the test's project and one with a second per-run project; after `ScopeReconcile("dev.moonglass.project=<first>")` and `Reconcile`, the first is gone and the second still exists (the test removes it in cleanup).
- `TestLoadGeneratorCountsEveryNon2xx`: against an `httptest` TLS server that answers a known number of requests with non-2xx statuses (and at least one with a connection cut after the first answer byte), the generator's failure count equals that number exactly, nothing was retried, every request used a new connection, and the reported first error and its time match the first failure.
- `TestLoadGeneratorRetriesOnceACutBeforeAnswer`: against an `httptest` TLS server that closes chosen connections without answering, a request cut once is retried on a new connection and answered, a request cut on its retry too is one failed request whose error marks the cut, and the retry count is 2.
- `TestTenDeploysUnderLoadDropNothing`: a first release deployed and switched before load starts; ten more releases each `Deploy` then `SwitchRelease` under load, each `SUCCEEDED`; after each switch a response with the new release id arrives within 2 s and no later response carries an older id; zero failed requests overall. A failure message shows the count, the first error and when it happened.
- `TestRollbackUnderLoadIsUnderFiveSeconds`: the same first release and ten deploys under load, then `Executor.Rollback` returns `SUCCEEDED` less than 5 s after the call, measured with the monotonic clock; within 1 s after it returns a response carries the release before the last one, and no later response carries the last one; zero failed requests across the deploys and the rollback.
- Both suite tests run with `Executor.Run` active, their own proxy process, port, data directories and labelled Docker resources, so the two tests and two worktrees can run at once; after each test no container, network or image with its project label remains, and the proxy process has exited.
- Without a Docker Engine the suite tests skip, and fail when `CI` is set; on a host where container IPs do not answer (Docker Desktop) they skip with that reason, and fail under `CI`.
- Nothing in the suite binds :80 or :443 or needs root; the only listener it reserves comes from `127.0.0.1:0`.
- `make test-deploy` runs only `./test/deploy` with `-race -count=1`; `make ci` is green; `testdata/tests.txt` lists the seven new tests.
- `ci.yml` has one job entry per Engine major 25–29 on `ubuntu-22.04`, every Docker package at an exact apt version, a step that fails when the running Engine's major differs from the entry's, and `make test-deploy` as the test step. No image is pulled from Docker Hub by the suite.
- `git grep -n 'Listen:' -- cmd/ internal/agent/` shows no `ProxyConfig` setting `Listen` outside `test/deploy` and `internal/deploy` tests, and `git grep -n ScopeReconcile -- cmd/ internal/agent/` shows nothing.

## Out of scope

- The control-plane deploy and rollback operations, `moonglass deploy`, `rollback`, `releases list`, and the audited rollback (W2-5).
- The G2 demo as one end-to-end CI test, including a failing pre-deploy step (W2-E).
- Changing branch protection: the owner makes the Engine 29 matrix job a required check after this merges.
- Stops, retention and draining themselves (W2-4); the proxy process and its guard (W1-5); `agent connect` flags (W2-4c).

## Security notes

- §3 trust boundaries, agent to proxy: `Listen` changes only the address the HTTP server binds and the redirect listener; the guarded admin document still repeats `admin` and `storage` exactly, and production (`agent connect`) never sets it. A malformed value is refused before anything is read or posted.
- §6 container-spec deny list: the suite deploys only through `Executor.Deploy` with an empty `agent.toml`, so every test container passes the sanitizer as production would; no privileged mode, host network, host bind or `docker.sock` mount.
- §8: no host shell in product code; the suite runs only `go build` and the built binary as the test user. The load generator trusts only the proxy's local CA, never the system pool or `InsecureSkipVerify`.
- §3, agent to Engine: `ScopeReconcile` only narrows which containers the reconcile may remove; production never calls it, so the agent still owns every managed container on its server.
- §9.8 and §9.9: no fallback path for an empty or set `Listen` beyond the one document builder; no existing test weakened, skipped or removed.
- CI: new job keeps `permissions: contents: read` and SHA-pinned actions; Docker packages come from Docker's apt repository at pinned versions only.
