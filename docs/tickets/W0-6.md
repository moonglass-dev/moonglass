# Fix harness ids, session allow-lists, dependencies and inspection

## Outcome

Four harness fixes found while running W0-0b to W0-4:

1. `scripts/ticket` accepts a ticket id with an optional lower-case letter suffix (`W0-0b`, `W0-0c`) as well as `W0-6` and `W12-3`.
2. A ticket's `allow` list lifts the matching protected-path `Edit` denies for that ticket's write sessions (tests, impl, fix), so `Makefile`, `*.proto`, `*.pb.go`, `docs/adr` and `.golangci.yml` are editable when named. `scripts/ticket` builds a per-session settings file from the committed `.claude/settings.json` and passes it with `--settings` and `--setting-sources ""`; the committed file keeps its deny rules. `.claude/` and `scripts/ticket` are never lifted, even when `allow` lists them.
3. The plan stage no longer returns `plan_blocked` for a `new_dependencies` entry that is already authorized: its module path is in the ticket's new `dependencies` frontmatter list, or appears in an ADR under `docs/adr/` marked `- Status: accepted`. Unnamed dependencies, `contract_change_required` and blocking ambiguities still block.
4. `.claude/settings.json` allows `ls`, `cat`, `rg`, `grep`, `find`, `head`, `wc`, `go list` and `git show`. The `find` write and exec flags and `rg --pre` are denied, and no existing deny is removed.

`docs/harness.md` and `docs/tickets/TEMPLATE.md` describe all four.

## Out of scope

Changing the verify gates or `is_protected`. Overriding any deny but the `Edit` rules for protected paths. A way for a ticket to edit `.claude/` or `scripts/ticket` through the harness. Product code. New ADRs.

This ticket edits the guard (`.claude/settings.json`, `scripts/ticket`), which the harness cannot do for itself, so it runs out of band with a direct `claude -p`.

## Acceptance tests

`make test-harness` covers:

- Ids `W0-0b`, `W0-0c`, `W0-6` and `W12-3` pass a dry run; `W0-0bb`, `W0-b`, `W0-0B`, `w0-6` and `W0` are rejected.
- With an `allow` list naming `Makefile`, `docs/adr`, a `.pb.go` file, a `.proto` file and `.golangci.yml`, the write session's settings drop those denies and keep the rest, including `Edit(../**)` and `Bash(git push *)`.
- With `.claude`, `.claude/settings.json` and `scripts/ticket` in `allow`, the session settings still deny both, and an `allow` naming only those two lifts nothing.
- With an empty `allow`, the session settings keep every Edit deny.
- A dependency named by an accepted ADR or the ticket's `dependencies` passes the plan stage. An unnamed one, one named only by a proposed ADR, and a mixed list with one unnamed entry all give `plan_blocked`. `contract_change_required` and a blocking ambiguity still give `plan_blocked`.
- `.claude/settings.json` allows the ten read-only commands, still denies `find -delete`, `find -exec`, `rg --pre`, `go get` and `git push`, and still denies the `Edit` rules for `.claude/`, `scripts/ticket`, `Makefile`, `docs/adr`, `*.proto`, `*.pb.go` and `.golangci.yml`.

`make ci` stays green.

## Security notes

Touches the agent permission boundary (build plan section on the harness). The override only removes `Edit` denies that `is_protected` already lists and the ticket already exempts at the `paths` gate, and never the two that guard the harness. A lifted rule covers its whole pattern for the session, so the `paths` gate stays the backstop for files the ticket did not name. The new `Bash` allows read files with the user's privileges: `Read` deny rules do not stop `cat` or `rg`, which is the same limit already documented for code the agent runs.
