# Policy: Compose resolution for import

`policy.ResolveCompose` turns a Compose project into the settings Moonglass import sends, in the CLI: it loads the files with every profile enabled and only the given variables, refuses every field outside the supported subset and every unsupported shape together, runs `CheckCompose` with the empty policy, and returns each service's image, port, command, environment, volumes, labels, restart policy, healthcheck and `depends_on` (`docs/specs/container-policy.md`, "Import resolution"; `docs/specs/compose.md`). It is the only new caller of compose-go's loader, which stays in `internal/policy` (ADR-0009 as amended, ADR-0004 decisions 15 and 16). Owner decision of 2026-11-19.

## Scope

- `internal/policy`: `ComposeService`, `ComposeVolume` and `ResolveCompose(ctx, ComposeInput) ([]ComposeService, error)`, implementing steps 1 to 5 of "Import resolution" exactly. Step 1 reuses the loader `CheckCompose` uses; step 4 calls `(*Policy)(nil).CheckCompose`. A step 2 or 3 refusal is one error listing every refusal of every service, in service then field order, and never includes a value.
- `CheckCompose`, its fixtures under `testdata/escape/` and its tests do not change.
- `testdata/compose/`: the fixtures the named tests load.
- The two specs: already say this; change them only if the built behaviour needs a wording fix.

## Acceptance criteria

- `TestResolveComposeMapsSupportedFields`: a table with one row per supported field shows the `ComposeService` value it gives: `ports: ["8080:3000"]` gives `Port` 3000; a string `command` gives the loader's argv; `restart` `unless-stopped` and absent give `""`; a `healthcheck` with only `test` gives Compose's defaults written out; `disable: true` gives `NONE`; `depends_on` is sorted; services are in name order.
- `TestResolveComposeRefusesUnsupportedFields`: a file with three services using `privileged`, `entrypoint`, `user`, `cap_add` and a top-level `secrets` key gives one error naming each service and field, and no services.
- `TestResolveComposeRefusesShapes`: a table with one row per refusal of step 3 (a bad name, no `image`, `build`, a bind mount, a tmpfs, an anonymous volume, a top-level volume with `driver_opts`, `external` or `name`, two ports, a `udp` port, `restart: always`, a `dev.moonglass.` label, an out-of-bounds healthcheck, an `environment` entry with no value or a lower-case name, a two-service `depends_on` cycle); each is refused and names the service.
- `TestResolveComposeRefusesNetworks`: a service with `networks: [other]`, and a top-level `networks` key, are refused; a service with no `networks` (the loader's implicit `default`) is not.
- `TestResolveComposeRunsDenyList`: with steps 2 and 3 satisfied, a project the deny list rejects returns `CheckCompose`'s `*Rejection` unchanged (a test seam may replace the step 2 and 3 checks, or a fixture that only step 4 catches is used).
- `TestResolveComposeEnablesEveryProfile`: a service behind `profiles: [debug]` is returned, and an unsupported field behind a profile is refused.
- `TestResolveComposeUsesOnlyGivenEnv`: `${TAG}` interpolates from `ComposeInput.Env` only; a variable set in the test process's environment and not in `Env` does not reach the result.
- The escape suite and every existing `internal/policy` test pass unchanged.
- `make ci` is green and `scripts/verify check W6-4a` passes.

## Out of scope

- W6-4c: the hash, the list and the apply order. W6-4: the CLI command.
- W6-1c: the agent checking each service's `Deploy` spec with `Check`.

## Security notes

- `docs/threat-model.md` §6: Compose is resolved before anything is judged (ADR-0004 decision 7), with every profile, and the deny list runs on the result; the agent checks each service again from its `Deploy` against its own `agent.toml`, and that check is the one that counts (ADR-0004 decision 16).
- ADR-0004 decision 15: `networks` is refused, so no service names another project's network.
- §9.3: environment values are returned to the CLI only, which encrypts them; no refusal, error or log line includes one (ADR-0004 decision 12).
- ADR-0009: compose-go is imported only here; the `policy-deps` depguard rule is unchanged.
