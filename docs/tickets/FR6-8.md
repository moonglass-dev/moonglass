# Health-gate pass cases with a load-safe limit

In internal/deploy/switch_test.go `TestHealthGateHTTPPath`, the cases that must pass run with the 20-second limit the package's other passing gates use. Only the cases that must fail keep the shortened limit and its elapsed-time bounds, and no assertion is dropped (R-6 finding 8). Right now every case runs under `x.healthLimit = 6 * time.Second`. A passing gate needs three probes in a row, 1 second apart and up to 2 seconds each (`internal/deploy/switch.go`, `docs/specs/release.md` "Health"). That leaves a new container about 3 seconds to answer while the whole package runs in parallel under `-race`, so `make ci` fails at random on `302 passes without following the redirect`. The health gate itself does not change.

## Scope

- `internal/deploy/switch_test.go`, `TestHealthGateHTTPPath` only: a case with `wantPass: true` runs `healthGate` with `x.healthLimit = 20 * time.Second`. A case with `wantPass: false` keeps `6 * time.Second`.
- Only add lines. Keep the existing `x.healthLimit = 6 * time.Second` line and, directly after it, set `x.healthLimit = 20 * time.Second` when `tc.wantPass` is true. `scripts/verify` fails any test file that loses a line it had on main (`removedTestLines` in `tools/pipeline/verify.go`), and FR6-8 has no entry in `ownerTestEdits`.
- No change outside that test function: not to `switch.go` (`healthPasses`, `healthInterval`, `probeTimeout`, the 60-second production limit), not to `deployGate` or the other helpers, and not to any other test.

## Acceptance criteria

- `TestHealthGateHTTPPath` keeps all four cases with the same `name`, `entrypoint`, `healthPath` and `wantPass` values. The test and each subtest still call `t.Parallel()`.
- The cases `200 passes` and `302 passes without following the redirect` call `healthGate` with `x.healthLimit` equal to `20 * time.Second` and still fail the test on any error from `healthGate`.
- The cases `500 fails at the limit` and `the stored path is probed, not another one` call `healthGate` with `x.healthLimit` equal to `6 * time.Second`. Each still asserts five things: a non-nil error; `elapsed >= x.healthLimit`; `elapsed <= x.healthLimit+3*time.Second`; that the error names `<container IP>:8080` followed by the stored health path; and that the error does not contain `health-body-must-not-leak`.
- `git diff --numstat origin/main -- internal/deploy/switch_test.go` shows 0 removed lines.
- No file other than `internal/deploy/switch_test.go` and the ticket's own docs changes. No test is added, skipped or deleted, and `testdata/tests.txt` is unchanged.
- `make test-one PKG=./internal/deploy NAME=TestHealthGateHTTPPath` passes against a real Docker Engine, `make ci` is green, and `scripts/verify check FR6-8` passes every gate.
