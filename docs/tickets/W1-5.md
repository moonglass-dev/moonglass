# Add the `moonglass proxy` process with embedded Caddy

## Outcome

`moonglass proxy` embeds Caddy 2.11.9, serves an admin API on a Unix socket only, includes one counter module, and can serve one HTTPS route with Caddy's internal issuer. The behaviour is `docs/specs/proxy.md`, which this ticket writes and may edit, and must stay faithful to ADR-0001. Pin `github.com/caddyserver/caddy/v2 v2.11.9` in `go.mod` and in a new accepted ADR-0011 (proxy dependencies), imported only from `internal/proxy`. Record it in the depguard allow list and deny it from `cmd/` (except the proxy command wiring if a command file must live there — prefer `cmd/moonglass` calling `proxy.Run` so `cmd` does not import Caddy directly) and from `internal/agent`, `internal/keys`, `internal/protocol`, and `internal/policy`.

SPIKE-1 is deferred. Do not amend ADR-0001's open questions. Use the defaults in the spec (drained restart until the spike; no memory campaign in this ticket).

## Out of scope

SPIKE-1 measurements and upgrade handshake (`SO_REUSEPORT` or socket activation). W1-6 units, W1-7 memory CI, deploy drain (W2-4), production ACME, Docker images, enrolment (W1-3). Do not pull container images in tests.

## Acceptance tests

- `TestAdminAPIOnUnixSocket`: the proxy starts with `--data-dir` and serves Caddy's admin API on a Unix socket in that directory, mode 0600 (or tighter).
- `TestNoTCPAdminPort`: with the proxy running, nothing is listening on a TCP admin port (Caddy's default `2019` is not bound).
- `TestOneHTTPSRouteInternalIssuer`: after a complete JSON config is pushed, a HTTPS GET to the one route succeeds using the internal issuer (no public ACME).
- `TestCounterRecordsRequest`: the same GET is visible in the counter module's counts for the route's release id.

`moonglass version` keeps working. If usage text grows, update the existing usage test without weakening it.

## Security notes

Threat-model B4: admin API on a Unix socket only, no TCP admin, no Docker access in the proxy, complete JSON config. Certificate private keys stay with Caddy under the data dir, not in the control plane.

## Done when

- `make ci` is green and every test above passes.
- ADR-0011 is accepted and listed in `docs/adr/README.md`.
- `docs/specs/proxy.md` matches the implementation.
- `cgo` stays disabled; `make build-all` remains a static ELF. The agent packages do not import Caddy.
