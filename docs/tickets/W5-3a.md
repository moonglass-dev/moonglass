# Source and command-class rules

Pure decisions in `internal/policy` for `[sources]` and `[commands]`, as `docs/specs/local-policy.md` ("Sources", "API (W5-3a)") and ADR-0004 decisions 8, 13 and 14 define them. After this ticket the package has one image-name normaliser, shared by the allow blocks and `[sources] registries`; rejects at load any source pattern not written in the normal form; treats a present, empty source list as allowing nothing; and answers `Forbids`, `CheckImageSource` and `CheckRepositorySource` from the parsed configuration alone. Nothing calls these yet: enforcement in the agent is W5-3.

## Scope

- `internal/policy/image.go`: `normalizeRepo` follows the spec's four steps: split off digest and tag; the first element is the host when it contains `.` or `:` or is `localhost`, otherwise `docker.io` is prefixed; `index.docker.io` becomes `docker.io` and the host is lower-cased; a one-element Docker Hub name gets `library/`. The allow blocks keep using it, so the change reaches them too (D46). No second normaliser exists.
- `internal/policy` (a new file beside `check.go`): `type Class uint8` with `ClassNone`, `ClassDelete`, `ClassExec`; `(*Policy).Forbids(Class) bool`; `(*Policy).CheckImageSource(ref string) error`; `(*Policy).CheckRepositorySource(repo string) error`; the exported `SourceRejection` error type, whose `Error()` is exactly the `detail` sentence the spec gives for its kind.
- `internal/policy/parse.go`: `[sources]` patterns are validated at load as the spec's "Patterns must be written in the normal form" and the `repositories` rule say. A present, empty `registries` or `repositories` list is accepted; an empty entry, a duplicate and bad `path.Match` syntax stay errors. `[commands] forbid = []` stays an error (the spec changes only `[sources]`).
- `internal/policy/types.go`: `Config` keeps a present, empty source list distinct from an absent one (non-nil, length 0 versus nil), including through `Config()`'s copy. The comment that enforcement is a later ticket is updated.
- `internal/policy/config_test.go`: the W1-1 cases `empty repositories` and `empty registries` are removed from the error table, owner-approved by D52; the new behaviour is `TestEmptySourceListAllowsNothing`. No other W1-1 case changes. Existing source fixtures in tests that are not in the normal form are rewritten to it only where load would otherwise fail for the new reason, and the test still asserts what it asserted.
- `docs/specs/container-policy.md`: the `sources.*` row, the `Parse`/`LoadFile` paragraph and "Tests" item 9 state the W5-3a rules as current behaviour rather than "From W5-3a".
- `docs/specs/local-policy.md`: only if the implementation reveals a wording error; the behaviour is already specified.

## Acceptance criteria

- `TestImageSourceNormalForm`: every row of the spec's normal-form table normalises to the shown form (`nginx:1.27`, `acme/web@sha256:…`, `GHCR.io/acme/web:v2`, `localhost:5000/web`, `ghcr.io/acme/team/web`), plus `index.docker.io/acme/web`, `docker.io/nginx` and `localhost/web`; failures show input, expected and actual.
- `TestImageSourceMatching`: with `registries` present, a reference whose normal form matches a pattern returns nil and one that matches none returns a `*SourceRejection` (via `errors.As`) whose `Error()` is exactly `agent.toml on this server allows images only from [sources] registries; <normal form> matches none of them. Add a pattern to [sources] registries in /etc/moonglass/agent.toml and restart the agent.`; `ghcr.io/acme/*` does not match `ghcr.io/acme/team/web` and `ghcr.io/acme/*/*` does; `docker.io/library/*` matches `nginx:1.27`; tag and digest never affect the result; the detail never contains a pattern; a `moonglass.local/...` reference (any host case) returns nil whatever `registries` holds; with `registries` absent every reference returns nil.
- `TestRepositorySourceMatching`: `Build.repository` `Acme/Web` is matched as `github.com/acme/web`; `github.com/acme/*` and `github.com/*/*` match it, `github.com/other/*` does not and returns a `*SourceRejection` whose `Error()` is the spec's `repositories` sentence naming `github.com/acme/web`; with `repositories` absent every repository returns nil.
- `TestSourcePatternsValidatedAtLoad`: `Parse` fails, naming the key, for a `registries` pattern that has upper case, a first element with `*`, `?` or `[`, a first element with no `.` or `:` that is not `localhost`, the host `index.docker.io` or the host `moonglass.local`, and the message shows a normal-form example such as `docker.io/library/nginx`; it fails for a `repositories` pattern with upper case, not starting with the literal `github.com/`, or without exactly three elements, and `github.com/acme` suggests `github.com/acme/*`; `docker.io/library/*`, `localhost:5000/*`, `ghcr.io/acme/*/*`, `github.com/acme/*` and `github.com/*/*` load.
- `TestEmptySourceListAllowsNothing`: `registries = []` and `repositories = []` load; with them, `CheckImageSource` rejects every non-`moonglass.local` reference and `CheckRepositorySource` rejects every repository; `Config()` reports each as present and empty, distinct from absent.
- `TestForbidsClasses`: for `forbid` absent, `["delete"]`, `["exec"]` and `["delete", "exec"]`, `Forbids` is true exactly for the listed classes and always false for `ClassNone`; `forbid = ["exec"]` loads and is reported forbidden although no command type has that class (D44).
- `TestAllowBlockImageUsesSourceNormalForm`: an allow block for `index.docker.io/prom/node-exporter@sha256:<d>` matches a spec image `prom/node-exporter@sha256:<d>`, and a block for `localhost/web@sha256:<d>` matches `localhost/web@sha256:<d>` but not `docker.io/localhost/web@sha256:<d>` (D46).
- The functions read only the parsed `Policy`: no Engine, file, network or clock access.
- Every existing `internal/policy` test and the escape suite stay green; only the two empty-list cases named in Scope are removed.
- `make ci` is green.

## Out of scope

- The agent's command-class table, `TestEveryCommandTypeHasAClass`, the `REJECTED` answers, the checks before pull and clone, the `moonglass.local` store and label rule, and the `dev.moonglass.repository` build label: W5-3.
- `STOP_APP` and `REMOVE_APP` and their `delete` class: W5-5a, W5-5b.
- Compose source checks: W6-4. Reporting local policy to the control plane: not planned.

## Security notes

- Threat model §8, "Local policy beats remote command": every decision here reads only `agent.toml` as parsed at start-up; no argument can widen it, and an absent key is the only way to leave a kind unrestricted.
- Threat model §6 and ADR-0004: the allow blocks now share the source normaliser, so a reviewer checks that the change cannot make a block match an image it did not match before except through the `localhost` host and `index.docker.io` folding of D46, and that a digest is still required for a block match.
- Threat model §5 item 5: `repositories` limits which code is built, not its base images; nothing here claims more.
- A pattern that could never match is a load error, not a silent deny-all (D47); a present empty list is the explicit deny-all (D52).
- Rejection text names the rejected source and never lists the patterns.
