# Proxy admin socket group

The agent (user `moonglass`) and the proxy (user `moonglass-proxy`) are different users, so the agent cannot reach today's admin socket, `<data-dir>/proxy-admin.sock`, mode 0600. After this ticket the agent-facing, guarded admin socket is `moonglass proxy --admin-socket PATH`, default `/run/moonglass-proxy/admin.sock`, mode 0660, group `moonglass-proxy-admin`, in the systemd runtime directory `/run/moonglass-proxy`, mode 0750. The install script creates the group, the proxy unit runs with it as its primary group and the agent unit adds it as a supplementary group. Caddy's own inner admin socket, the certificates and the autosave file stay in the proxy data dir, mode 0700. This implements ADR-0001 decision 3 as amended, and the W2-12 parts of `docs/specs/proxy.md` and `docs/specs/install.md`.

## Scope

- `internal/proxy`: `Run` takes the agent-facing admin socket path as a parameter beside the data dir. `AdminSocketPath(dataDir)` and the `proxy-admin.sock` name are deleted; there is no second location. An exported constant `DefaultAdminSocket = "/run/moonglass-proxy/admin.sock"`. `listenAdmin` listens on the given path (removing a stale socket there, as today), sets mode 0660 and sets the socket's group to the process's effective group (`os.Getegid()`), which under the unit is `moonglass-proxy-admin`. It does not create or chmod the parent directory (systemd's `RuntimeDirectory` does). Errors name the path. The guard, `checkConfig`, `AdminListenAddress` (the inner `<data-dir>/proxy-caddy.sock|0600`) and `StorageDir` are unchanged.
- `cmd/moonglass`: `moonglass proxy --data-dir DIR [--admin-socket PATH]`, `--admin-socket` defaulting to `proxy.DefaultAdminSocket`, passed to `proxy.Run`. The `--data-dir` usage rules stay as they are.
- `internal/registry/routes.go`: the `proxy` entry in `LocalCommands` gets the synopsis `proxy --data-dir DIR [--admin-socket PATH]` and a summary that no longer says the socket is in DIR. This is a local command, not a registry operation.
- `deploy/systemd/moonglass-proxy.service`: `Group=moonglass-proxy-admin`, `RuntimeDirectory=moonglass-proxy`, `RuntimeDirectoryMode=0750`. Nothing else is relaxed. `ExecStart` stays `moonglass proxy --data-dir /var/lib/moonglass/proxy`, so the default socket is used.
- `deploy/systemd/moonglass-agent.service`: `SupplementaryGroups=docker moonglass-proxy-admin`.
- `scripts/install`: in host setup, `getent group moonglass-proxy-admin >/dev/null 2>&1 || groupadd --system moonglass-proxy-admin || die "cannot create group moonglass-proxy-admin"`. No user is ever added to it.
- Existing tests follow the moved socket. `startProxy` in `internal/proxy/proxy_test.go` passes a temp admin socket path and dials it. `TestAdminAPIOnUnixSocket` asserts the socket at that path with mode exactly 0660, replacing its 0600 check (ADR-0001 decision 3 as amended; this follows the contract and does not weaken the test), and keeps its data-dir 0700 check. `TestProxyAndAgentIdleUnderBudget` starts the proxy with `--admin-socket <temp>` and waits for that socket.
- Specs: `docs/specs/proxy.md` describes the new layout as current (drop "Until W2-12", and the guard paragraph names `--admin-socket` instead of `<data-dir>/proxy-admin.sock`); `docs/specs/install.md` drops the "(from W2-12)" markers; `docs/specs/memory.md` step 3 names `--admin-socket <temp>`.

## Acceptance criteria

- `TestAdminSocketAtGivenPath`: with `proxy.Run(ctx, dataDir, sock)` and `sock` outside `dataDir`, `GET /config/` over `sock` returns 200, and `<dataDir>/proxy-admin.sock` does not exist.
- `TestAdminSocketModeAndGroup`: the socket at the given path is a Unix socket with permission bits exactly 0660 and group id equal to `os.Getegid()`.
- `TestCaddyAdminSocketStaysPrivate`: Caddy's inner socket `<dataDir>/proxy-caddy.sock` exists with no group or other bits (0600 or tighter), the data dir is 0700 or tighter, and a pushed `POST /load` whose `admin.listen` names the agent-facing socket path is refused with 400 (the inner address alone is accepted).
- `TestProxyAdminSocketDefault`: `moonglass proxy --help` exits 2 and its flag help shows `--admin-socket` with the default `/run/moonglass-proxy/admin.sock`, equal to `proxy.DefaultAdminSocket`.
- `TestProxyUnitOwnsAdminSocketDir`: the proxy unit has `User=moonglass-proxy`, `Group=moonglass-proxy-admin`, `RuntimeDirectory=moonglass-proxy`, `RuntimeDirectoryMode=0750`, no `SupplementaryGroups`, and its `ExecStart` either passes no `--admin-socket` or passes `/run/moonglass-proxy/admin.sock`, the path under that runtime directory.
- `TestOnlyAgentJoinsProxyAdminGroup`: the agent unit's `SupplementaryGroups` contains both `docker` and `moonglass-proxy-admin`; the proxy unit holds `moonglass-proxy-admin` only as `Group`; no non-comment line of `scripts/install` runs `usermod`, `gpasswd`, `adduser` or `useradd` with `moonglass-proxy-admin` (no user is a member in `/etc/group`).
- `TestInstallCreatesProxyAdminGroup`: inside the host-setup block (after the root check, before `systemctl daemon-reload`), `scripts/install` has a non-comment line that runs `groupadd --system moonglass-proxy-admin`, guarded by `getent group moonglass-proxy-admin`, and ending in `die` on failure; the custom-layout install used by the existing tests (`--prefix`, `--unit-dir`) still succeeds without root and calls no `groupadd`.
- The existing tests `TestAdminAPIOnUnixSocket`, `TestNoTCPAdminPort`, `TestPushedConfigCannotOpenTCPAdmin`, `TestAdminSocketRefusesOtherMutations`, `TestOneHTTPSRouteInternalIssuer`, `TestCounterRecordsRequest`, `TestUnitsAreHardened`, `TestOnlyAgentHasDockerGroup` and `TestProxyAndAgentIdleUnderBudget` pass, changed only as Scope says.
- No code refers to `proxy-admin.sock` or `AdminSocketPath` after the change.
- Admin socket paths in tests stay short (under `/tmp`, as `startProxy` does) because Unix socket paths are limited to about 100 bytes, and are unique per test run.
- `make ci` is green and `testdata/tests.txt` lists the new tests.

## Out of scope

- The proxy upgrade mechanism and SPIKE-1 questions: SPIKE-1.

## Security notes

- `docs/threat-model.md` §3 boundary B4: the guarded admin socket is reachable only by `moonglass-proxy` and members of `moonglass-proxy-admin`, which only the two units hold (the proxy as primary group, the agent as supplementary group). The socket is 0660 and its directory 0750; no other user can traverse to it. No TCP admin port is opened, and the guard still refuses any pushed config that moves the admin API or the storage.
- Caddy's inner admin socket stays 0600 in the 0700 data dir, so group members can only reach Caddy through the guard; certificates and private keys stay readable by the proxy only (§2, ADR-0001 decision 3).
- §9 checklist item 6: the only new root step is creating one system group, idempotently, inside the existing root-only host setup. The script never adds a user to `moonglass-proxy-admin` or `docker`.
- §9 checklist item 7: the proxy unit gains only `Group` and a runtime directory; no capability, no Docker access, no relaxed hardening. The agent gains only the `moonglass-proxy-admin` supplementary group. `ProtectSystem=strict` stays, with `/run/moonglass-proxy` writable only through `RuntimeDirectory`.
