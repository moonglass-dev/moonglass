## Findings

### 1. The memory-budget test now needs Docker and points the agent at the system proxy socket, which disagrees with docs/specs/memory.md

- Evidence: since W2-4c, `moonglass agent connect` opens the Docker Engine before it connects and exits 1 when it cannot (`cmd/moonglass/main.go:162-166`; `internal/deploy/engine.go:39-58` pings the Engine; `docs/specs/connection.md` "Commands"). `TestProxyAndAgentIdleUnderBudget` starts the agent with no `--proxy-socket` (`internal/proxy/memory_test.go:153`), so the agent pushes to the default `/run/moonglass-proxy/admin.sock` (`cmd/moonglass/main.go:115`) and not to the temp socket of the proxy it started (`internal/proxy/memory_test.go:151-152`). The test has no skip for a missing Engine (`internal/proxy/memory_test.go:86-180`). This disagrees with `docs/specs/memory.md` "What is measured", step 3, and with its line "It needs no Docker … every directory is temp". It also disagrees with `AGENTS.md` "Testing rules": with no Engine, a test skips, except under `CI`, and tests are safe to run in two worktrees at once. W2-4c's allowed paths did not include `internal/proxy/` or `docs/specs/memory.md`.
- Impact: on a machine without Docker, `make test` and `make memory-budget` fail with "agent did not connect" instead of skipping. The G1 gate measures an agent that never reaches the proxy it was started next to, so the pusher's steady state is not in the sample. On a host that runs a real Moonglass proxy, where the user is in `moonglass-proxy-admin`, the test agent posts its empty config to that proxy and drops every live route.
- Fix ticket: FR4-1

### 2. The TLS issuer list is checked in two packages

- Evidence: `cmd/moonglass/main.go:120-124` (`parseAgentConnect` switches on `acme`, `acme-staging` and `internal`) repeats the set that `internal/deploy/proxy.go:265-280` (`issuerApps`) accepts and refuses. `docs/specs/connection.md` ("Commands", `--tls-issuer`) and `docs/specs/release.md` ("Proxy config", "Certificates") describe one set of issuers. This disagrees with `AGENTS.md` ("One way to do each thing").
- Impact: if an issuer is added to one copy and not the other, the agent either refuses a valid flag at start-up or accepts a value that every push then rejects through `OnError`. In the second case the proxy serves no routes, and the only sign is a line on stderr every second.
- Fix ticket: FR4-2

### 3. `registry.LocalCommands` does not say that `agent connect` touches the Docker Engine and the proxy admin socket

- Evidence: `internal/registry/routes.go:32` gives `agent connect` the `Touches` value "the agent data dir and the control-plane agent listener". Since W2-4c the command also opens the Docker Engine socket and the agent state database, and posts to the proxy admin socket for its whole life (`cmd/moonglass/main.go:162-181`). `docs/specs/registry.md` ("Routes and commands that are not operations") says the list names each local command "with what it touches". `docs/threat-model.md` §3 B4 makes the admin socket a trust boundary. W2-4c updated only the synopsis.
- Impact: the fixed list is where a reviewer checks what each local command can reach outside the registry, and it understates the command that holds the Docker socket and drives the proxy.
- Fix ticket: FR4-3

### 4. The banned-words gate exempts `ui/svelte.config.js`, a file ADR-0016 says does not exist

- Evidence: `tools/pipeline/verify.go:762` (`bannedWordsSkip` matches `ui/svelte.config.js`), and `tools/pipeline/parse_test.go:153` expects that exemption. ADR-0016 decision 3, amended 2026-11-19, says "`ui/svelte.config.js` does not exist", and the adapter is set in `ui/vite.config.ts`, which is exempted at `tools/pipeline/verify.go:763`. The comment at `tools/pipeline/verify.go:754-758` names only `ui/vite.config.ts` and `ui/scaffold_test.go`. This is dead code left from #88 after #89 changed the design, against `AGENTS.md` ("When a design changes, delete the old path in the same change").
- Impact: a later ticket that adds `ui/svelte.config.js` against ADR-0016 passes the banned-words gate for that file without a reviewed reason.
- Fix ticket: FR4-4

### 5. docs/specs/connection.md still says the operation registry does not exist and `/v1/agent` will join the route list when W2-1 lands

- Evidence: `docs/specs/connection.md:90-92` ("Route registration": "The operation registry does not exist yet … It joins the fixed route list when W2-1 lands"). W2-1 is merged, and `/v1/agent` is on `registry.NonOperationRoutes` at `internal/registry/routes.go:12`. FR1-7 fixes the same stale text in `internal/server/agent.go` and `docs/specs/registry.md`, but its paths do not include `docs/specs/connection.md`.
- Impact: the spec that owns the agent route describes a state of the code that no longer holds. After FR1-7 merges, this page is the only place left with the old text.
- Fix ticket: FR4-5
