## Findings

### 1. The deploy executor has its own image-name normaliser, and it disagrees with the one in internal/policy

- Evidence: `internal/deploy/image.go:26-36` (`splitRef`) and `internal/deploy/image.go:38-47` (`normalizeRepo`) reimplement `internal/policy/image.go:37-56` (`splitImage`) and `internal/policy/image.go:80-94` (`normalizeRepo`). The deploy copy does not fold `index.docker.io` to `docker.io`, does not lower-case the host, and returns a `docker.io/<name>` reference unchanged without adding `library/` (`internal/deploy/image.go:40-41`). `internal/deploy/image.go:83-90` matches the reference against the Engine's `RepoDigests` with that copy. It disagrees with `docs/specs/local-policy.md` ("What registries is matched against": "The same normaliser serves the allow blocks (`internal/policy`), so there is one rule for image names", steps 2 to 4) and `AGENTS.md` ("One way to do each thing").
- Impact: a `Deploy` of `docker.io/nginx:1.27` or `index.docker.io/library/nginx:1.27`, which `internal/protocol/deploy.go:42` accepts and the Engine pulls, normalises to `docker.io/nginx` or `index.docker.io/library/nginx`, while the Engine reports `nginx@sha256:…` (`docker.io/library/nginx`). The deploy fails after a successful pull with "has no repository digest". When W5-3 checks `[sources] registries` with the policy normaliser, the agent will check one name and match the pulled image under another.
- Fix ticket: FR2-1

### 2. The project, environment and service name format is implemented twice

- Evidence: `internal/store/names.go:10` (`namePattern`, a regular expression) and `internal/protocol/deploy.go:55-67` (`validateName`) each implement "1 to 63 bytes of `[a-z0-9-]`, starting and ending with a letter or digit". `docs/specs/storage.md` ("Names": "the protocol's name format (`docs/specs/protocol.md`)") and `docs/specs/protocol.md` (Deploy fields: "The same format the control plane uses") say it is one format; `docs/specs/agent-identities.md` ("Name") reuses it for W5-1a. It disagrees with `AGENTS.md` ("One way to do each thing").
- Impact: the control plane can accept a name that every agent rejects as `ErrMalformed`, or the reverse, if one copy changes. The agent binds an app to these names for life (`docs/specs/storage.md`, owner decision D1), so a drift leaves services that can never be deployed.
- Fix ticket: FR2-2

### 3. The executor detects "not found" by matching error text as well as by the error type

- Evidence: `internal/deploy/engine.go:69-72` (`isNotFound`) returns true for an error implementing `NotFound()` or for any error whose text contains `not found` or `No such `. Its callers decide whether to pull (`internal/deploy/image.go:60` and `internal/deploy/image.go:74`), create a network (`internal/deploy/network.go:16`) or treat a container name as free (`internal/deploy/container.go:81`). It disagrees with `AGENTS.md` ("One way to do each thing", "No fallback, legacy or compatibility code").
- Impact: any Engine error whose message happens to contain "not found" (for example a wrapped registry or daemon error) is taken as "absent": the executor then pulls, creates a network or reuses a container name instead of failing loudly with the Engine's error.
- Fix ticket: FR2-3

### 4. The age, Docker and Caddy import rules still use fixed file lists, so packages outside the list are not checked

- Evidence: `.golangci.yml:73-80` (`age-deps`) lists twelve directories and leaves out `internal/deploy`, `internal/update` and `tools/`, although ADR-0015 decision 2 says "depguard denies the module everywhere else". `.golangci.yml:82-87` (`docker-deps`) lists fixed directories, while ADR-0014 decision 2 says depguard denies the Docker modules everywhere but `internal/deploy`, `internal/build` and `internal/agent/disk`; packages the plan adds (`internal/auth` W4-1b, `internal/github` W4-10, `internal/rollback` W5-5b, `internal/services` W6-1, `internal/compose` W6-4, `test/`) are not covered. `.golangci.yml:38-48` (`proxy-deps`) does not cover `internal/deploy`, and nothing denies `moonglass.dev/moonglass/internal/proxy` there, which `docs/specs/release.md` ("Proxy config": "`internal/deploy` never imports `internal/proxy`, which links Caddy (ADR-0011)") requires. The comment at `.golangci.yml:75-77` says file exclusions were not applied for policy-deps, but since FR1-10 `policy-deps` (`.golangci.yml:100-112`) uses them.
- Impact: `internal/deploy` or `internal/update` can import age, a new package can import the Docker client, and the agent's executor can link Caddy, with `make lint` still green. The agent memory budget and the ADR-0015 key boundary depend on these rules.
- Fix ticket: FR2-4

### 5. docs/specs/auth.md says `session_hashes.revoked_at` is empty when live, but it is NULL

- Evidence: `docs/specs/auth.md` ("Storage", "Lookup tables": "`revoked_at` (empty when live)") disagrees with `internal/store/migrations/sqlite/0005_sessions.sql:6` and `internal/store/migrations/pg/0005_sessions.sql:6` (`revoked_at TEXT`, nullable, no default) and `internal/store/sessions.go:32` (`revoked_at IS NULL`), which follow the `tokens.revoked_at` convention of `0002_tokens_audit.sql:24`.
- Impact: a later ticket that reads the spec (W4-1b, W4-1, W7-1) and writes or tests `revoked_at = ''` treats every session as revoked, or a revoked one as live. The storage schema is a contract, so the text has to say what the schema is.
- Fix ticket: FR2-5
